## 1.0.5.66 - Постоянный MAC из SID, RTC как UTC, осадка батч-прошивки (август 2026)

### Сеть

- **MAC больше не меняется при перезагрузке.** У платы нет аппаратного MAC:
  u-boot подставлял в `local-mac-address` случайный адрес при каждой загрузке.
  Последствия тяжёлые: MPLC Protect выводит Request key прямо из MAC
  (`000C0000` + байты адреса), поэтому выданная лицензия становилась
  недействительной после первого же перезапуска, а стенд не мог опознать плату.
  Теперь `sa02m-pre-start.sh` (до старта сети) вычисляет адрес из SID —
  eFUSE процессора, уникальный для каждого кристалла:
  `eth0 = 02:53:<SID[12]>:<SID[13]>:<SID[14]>:<SID[15] & 0xFE>`,
  `eth1 = eth0 + 1`. Пары адресов соседних плат не пересекаются (последний
  байт eth0 всегда чётный), для партии 200+ плат коллизий нет.
  Переопределение — `SA02M_MAC_ETH0` / `SA02M_MAC_ETH1` в `/etc/sa02m-mac.conf`.
  Проверено на изделии реальным снятием питания: MAC и Request key неизменны.
  Путь через DT-ячейки `nvmem` нерабочий по сути — в SID нет поля MAC
  (offset 0 → бит multicast, offset 4 → чужой OUI), и свойства DT приоритетнее
  nvmem; подробности — в комментарии к `&emac` в DTS платы.

### Устройства RS-485 (флешер)

- **Пауза-осадка между устройствами при пакетной прошивке.** Прошивка
  нескольких MR-модулей подряд по одному COM давала каскадный сбой: только что
  прошитый модуль перезагружается в новое приложение (~2 с) и кратко висит на
  фиксированном адресе загрузчика 247, коллизясь с кадрами `enter_bootloader`
  следующего устройства (на стенде: addr 13 падал на 620/701, addr 14 — каскадом;
  восстановление по серийнику по одному помогало). `run_flash_batch_job` теперь
  выжидает ограниченную отменяемую осадку (по умолчанию 2.5 с) перед каждым
  устройством, кроме первого, — модуль успевает освободить линию. Одиночная
  прошивка, port-lease и сессия прошивки не затронуты.

### Часы реального времени

- **DS3231 теперь виден ядру как `/dev/rtc1`.** Драйвер отсутствовал из-за
  опечатки в рецепте сборки: включался несуществующий символ Kconfig
  `RTC_DRV_DS3231` (DS3231 обслуживается драйвером `ds1307`), поэтому опция
  молча терялась при каждом `olddefconfig`. Теперь `CONFIG_RTC_DRV_DS1307=m`
  и `CONFIG_RTC_DRV_DS3232=m`; штатный `hwclock` и systemd работают с
  батарейными часами напрямую, а raw-I2C остаётся запасным путём.
- **Единый формат времени — UTC.** Чип хранил местное время при
  `/etc/adjtime`=UTC: путь `hwclock` и запасной `i2cget` расходились на
  величину часового пояса (3 ч). Чип приведён к UTC, запасной путь в
  `sa02m-pre-start.sh` исправлен на `date -u -s`.
- Проверено на изделии реальным снятием питания: `/dev/rtc1` поднимается
  автоматически, время из батарейного чипа совпадает с системным (1 с), OSF=0.

### Важно при правках на изделии

- **Корень смонтирован с `commit=600`** — журнал ext4 сбрасывается раз в
  10 минут. Любая запись (модуль, конфиг, ключ лицензии) перед снятием
  питания должна завершаться `sync`, иначе теряется. Проверено: установленные
  файлы исчезли после обесточивания через ~3 минуты.

## 1.0.5.65 - BACnet MS/TP: выбор шины, проверка и возврат в Modbus (Фаза 1) (август 2026)

### Устройства RS-485 (флешер)

- **Выбор полевой шины модуля (регистр 122).** В конфигурации модуля появился
  3-позиционный переключатель: классический Modbus / Fast Modbus / BACnet MS/TP.
  Показывается только для семейств MR-02m и DTV (у которых прошивка умеет BACnet);
  скрыт для CE-02m-3, WB и загрузчика. Перед переключением в BACnet — диалог
  подтверждения, называющий путь возврата ДО записи (дисциплина контракта
  флешера). Запись идёт через существующую арендованную сессию конфигурации
  (порт-lease, остановка MPLC/моста, `flasher_busy`).
- **Проверка BACnet.** Новое задание демона: пассивное прослушивание MS/TP на
  арендованном порту (MR — фиксированные 38400 8N1, DTV — на своей скорости),
  только чтение, N секунд. Отчёт «шина жива / тишина» с числом кадров; тишина и
  ошибки порта сообщаются, а не скрываются.
- **Честность к прошивке без BACnet.** После записи `122=2` UI держит окно ~6 с
  как «применение», затем перепроверяет: тишина ⇒ применилось; модуль всё ещё
  отвечает по Modbus и регистр == 2 ⇒ «прошивка без поддержки BACnet или
  переключение не применилось» вместо ложного успеха.
- **Возврат в Modbus.** Новое задание: если модуль ещё в окне применения —
  прямая запись FC06; если уже «защёлкнулся» в BACnet — присоединение к кольцу
  MS/TP и WriteProperty (MR: MSV:1; DTV: AV:122), затем подтверждение, что модуль
  снова отвечает по Modbus. Требует второго явного подтверждения; идёт под
  арендой порта.
- **Диагностика «пропавшего» модуля.** Когда скан порта ничего не нашёл —
  предложение одной кнопкой «Проверить BACnet-активность» (пассивный сниф), чтобы
  защёлкнутый в BACnet модуль был диагностирован, а не потерян.

### Прошивка модулей (флешер)

- **Исправлены сбои прошивки на последних блоках.** Флешер писал каждый блок в
  фиксированный регистр `0x2000`; при потере ответа и повторе блока загрузчик
  писал и продвигал `flash_offset` заново → накопление сдвига → отказ на
  последних ~4 блоках (на стенде — падение на 596–598/600 каждый раз). Переход
  на **индексированное окно** загрузчика: блоки приложения → `0x2100+индекс`
  (BL ≥ 0.0.0.11), блоки обновления загрузчика → `0x2600+индекс` (BL ≥ 0.0.0.21);
  легаси `0x2000` остаётся запасным путём для старых/неизвестных версий
  загрузчика. Повтор блока теперь идемпотентен (загрузчик подтверждает без
  сдвига). Регистры и версии сверены с контрактом загрузчика MR-02m; 19 новых
  юнит-тестов. **Проверено на железе:** застрявший в загрузчике модуль
  восстановлен прошивкой 600/600 (та же прошивка падала 3 раза до фикса).

### Контракты / документация

- Новый `docs/contracts/web-bus-mode-bacnet.md` — веб-контракт селектора/проверки/
  возврата; ссылается (не копирует) на прошивочные контракты MR-02m/DTV и контракт
  standalone-флешера. Кодек MS/TP и семантика регистра 122 портированы из
  проверенного `MR-02m-flasher` (чистый Python, транспорт инъектируется,
  host-тестируется — 50 новых юнит-тестов).

**Ограничение Фазы 1 (проверяется на стенде):** on-wire тайминг MS/TP-мастера на
A40i и точное декодирование DTV AV:122 (REAL) прошивкой — не подтверждены на
железе; закрываются HIL-сценарием на стенде с прошивкой `WITH_BACNET`.

**файлы:** `opt/sa02m-flasher/sa02m_flasher/{bus_mode,bacnet_mstp,device_config,jobs,runner,service,flash_protocol}.py`,
`opt/sa02m-flasher/tests/{test_bus_mode,test_bacnet_mstp,test_indexed_block_window}.py`,

## 1.0.5.64 - First-boot образ, KLogic-совместимость, командная строка, KPI-дашборд (август 2026)

### Web UI

- **Командная строка в «Управление».** Перед «Журнал событий» добавлен
  терминальный блок для выполнения команд на устройстве через авторизованный
  `cmd_exec.cgi`: POST-only, session auth, timeout 20 секунд, лимит команды
  1000 символов и вывода 32 KiB. По умолчанию команды запускаются от
  пользователя web-интерфейса (`www-data`); режим `root` включается командой
  `su root` в самой командной строке и выключается через `exit` / `su web`.
  Команды с префиксом `sudo ...` также маршрутизируются через root-режим, чтобы
  не вызывать интерактивный `sudo` из `www-data`. Root-команды требуют пароль
  root и выполняются через sudo-helper
  `sa02m-web-root-cmd.sh`, который проверяет пароль root по `/etc/shadow`.

### Imaging / first-boot

- **Expand rootfs больше не держит Ethernet на минуты.** Unit
  `sa02m-rootfs-expand` не ставит `Before=networking` / `ifupdown-pre` /
  `basic.target` — только userspace-watchdogs; `WantedBy=multi-user.target`.
  Раньше `resize2fs` блокировал линк/SSH на 2–6 мин (выглядело как «плата не
  загрузилась»).
- **Убран deadlock expand ↔ net-watchdog.** В `finish_firstboot` больше нет
  `systemctl start/restart` единиц, от которых expand стоит `Before=`.
- **Нельзя `systemctl stop` watchdogs из expand.** При `Before=net-watchdog…`
  stop отменяет уже поставленный в очередь start на всю загрузку — после
  first-boot `net-watchdog` оставался мёртвым (нет recovery линка). Hot path
  только resize + файловый mask armbian / DONE; watchdogs стартуют сами по
  ordering.
- **`boot.scr` снова фиксируется в образе.** Offline patch пересобирает FAT
  `boot.scr` из `etc/boot.cmd.sa02m` и кладёт canonical copy в
  `/usr/local/share/sa02m/boot.scr`; USB autorun дополнительно копирует
  `boot.scr` с флешки после `dd`. Это сохраняет `threadirqs`, без которого на
  рабочей плате с PCA9536 возможен I2C IRQ storm до `sa02m-pre-start`: нет
  пищалки, службы не доходят до запуска.
- **Нет dual-resize.** При снятии/патче образа включается только
  `sa02m-rootfs-expand`, `armbian-resize-filesystem` маскируется (иначе шторм
  udev и срыв `ifupdown-pre`).
- **Watchdogs не маскируются и не останавливаются** в expand / installer;
  `systemctl mask` больше не уничтожает unit-файлы под `/etc`.
- **Cold-boot PHY:** `sa02m-eth-coldboot` для eth0/eth1; `fix-eth.sh` делает
  link-cycle при `operstate=down|dormant|unknown` (не только `down`).
- **Инструменты:** `tools/imaging/patch-firstboot-image.sh`, `autorun-fel.sh` /
  `autorun.sh`, `firstboot-overlay/`, `capture-image.*`, обновлены
  `stream-after-cleanup.sh`, `make-image.sh`, `wait-donor.sh`, README.

### Cloud agent

- **Клон образа не уносит enrollment донора.** Wipe
  `/etc/sa02m-cloud` (`device_secret`, `frpc.toml`, `enrolled=false`) в
  `stream-after-cleanup`, offline-патче и autorun; скрипт
  `tools/imaging/reset-cloud-enrollment.sh`.

### Hardware

- **Диагностический режим без I2C/PCA9536:** только при явно заданном
  `SA02M_HW_BACKEND=disabled` `sa02m-pre-start` не пытается recovery/boot
  indication через `i2c-2`. Для серийной платы и платы перед установкой в
  рабочее устройство остаётся продуктовый backend `i2c_expander`.
- **Web override пищалки без остановки KLogic.** При web-записи `beeper`
  создаётся `/run/sa02m-hw-override/beeper.env` с TTL
  `SA02M_BEEPER_WEB_OVERRIDE_SEC=7`. KLogic-side драйвер PCA9536 читает этот
  override и применяет bit2 с приоритетом, не меняя остальные биты. Для текущего
  live-бинаря без пересборки установлен worker
  `/usr/local/sbin/sa02m-beeper-override.sh`: он не останавливает KLogic и
  удерживает bit2 до истечения TTL.
- **Stop/start KLogic для web-пищалки убран.** Алгоритмы KLogic продолжают
  выполняться: на `.136` при `beeper=1` KLogic остаётся `active`, output
  `0xf3/0xfb`; при `beeper=0` output `0xf7/0xff`; failed units = 0.
- **MPLC4 корректно считается владельцем PCA9536.** Owner detection теперь
  учитывает active units из `SA02M_I2C_OWNER_UNITS`, а не только имена процессов:
  на `.136` после `klogic=inactive` / `mplc4=active` web beeper идёт через
  override и не пишет PCA9536 напрямую.
- **Синий LED KLogic сохранён как reserved output.** Bit3 PCA9536 не управляется
  web UI, но остаётся output через `SA02M_I2C_EXTRA_OUTPUT_MASK=0x08`; helper
  больше не пишет config `0x08` и не обнуляет верхний nibble output/config.
  На `.136` восстановлен config `0xF0`, мигание bit3 снова видно по samples
  `0xff/0xf7`.

### Интерфейс

- **Виджет служб:** установленный KLogic показывается отдельной строкой

## 1.0.5.63 - Сброс «залипшей» retained-ошибки устройства при старте моста (июл 2026)

### MQTT

- **Здоровое устройство больше не остаётся «offline» после перезапуска моста.**
  При старте `sa02m-modbus-mqtt` теперь чистит device-level
  `/devices/{id}/meta/error=""` для каждого устройства из конфига, снимая
  retained `"r"`, оставшийся от прошлого процесса (штатная остановка/LWT).
  Раньше устройства по умолчанию считаются online, поэтому оставшееся здоровым
  через перезапуск устройство не меняло состояние и никогда не сбрасывало
  старый `"r"`: мост рапортовал `devices_online == всего`, а retained-дерево
  продолжало «лгать» об offline — облачный watchdog флудил ложными инцидентами

  back-off снова выставит его после `offline_after_fails` неуспешных чтений.
  Единственный прежний сброс (только для CE-02m-3, в `setup()`) убран —
  теперь один дом у логики (регистрация устройства). Автомат доступности
  (`mark_ok`/`mark_fail`) не тронут.

  старте и правило стабильности `bridge_device_id` (канон `sa02m-bridge`;

## 1.0.5.59 - Активация свежего ядра того же профиля на загрузочный раздел одной кнопкой (июл 2026)

### Ядро / загрузка

- **Новое действие `refresh` в `sa02m-kernel-select.sh` — активирует
  свежесобранный zImage запущенного профиля на загрузочный FAT-раздел.** Раньше
  свежий same-profile kernel не доходил до загрузчика: `set <profile>` при
  совпадении с запущенным профилем делал ранний no-op и никогда не копировал
  канонический `zImage.<профиль>` на активный `/mnt/fat/zImage`. Обходной манёвр
  rt→smp→rt больше не нужен. `refresh` работает только с запущенным профилем
  (`running_profile()`), под тем же `flock`, что и `set` (взаимоисключение),
  через `cmp` пропускает запись при идентичном образе (`refreshed:0`,
  перезагрузка не требуется) и предлагает перезагрузку только при реальном
  изменении байт (`refreshed:1`). Отсутствующий/битый активный zImage считается
  «нужен refresh» — восстанавливает повреждённый загрузочный файл.
- **Атомарная запись загрузочного zImage (`write_fat_zimage`).** Запись идёт во
  временный файл на том же FAT-каталоге, `sync`, проверка размера **до** подмены,
  затем `mv -f` (атомарная замена dir-entry на vfat) и `sync` — активный
  загрузочный zImage никогда не остаётся усечённым при сбое/полном носителе.
  Обе `cp`-строки существующего `set` переведены на этот же хелпер
  (behaviour-preserving hardening); новый код ошибки `fat_write_failed`.

### Веб-интерфейс

- **Кнопка «Обновить загрузочное ядро»** в карточке «Ядро и частота CPU»
  (вкладка «Управление»), рядом с «Применить и перезагрузить». Доступна, когда
  артефакт запущенного профиля валиден; после успеха предлагает перезагрузку
  (`refreshed:1`) или сообщает «уже актуально» (`refreshed:0`).
- **CGI `kernel_ctrl.cgi`: аддитивная форма запроса `POST {"action":"refresh"}`.**
  Старая форма `POST {"profile":"smp"|"rt"}` (переключение профиля) не изменена.
  `action` — allow-list только на `refresh` (fail-closed: любое другое непустое
  значение → `bad_action`); `refresh` не принимает пользовательский профиль/путь.
  Проверка авторизации по-прежнему выполняется до любой мутации. Форма
  ответа: `{"ok":true,"refreshed":0|1,"target":"<профиль>","reboot_required":0|1,"warnings":""}`.

### Установщик

- **`scripts/03-webserver.sh`:** точная sudoers-строка
  `/usr/local/sbin/sa02m-kernel-select.sh refresh` в NOPASSWD-блоке (без
  аргумента — точный матч, как `status --json`).

**файлы:** `etc/sa02m-kernel-select.sh`, `www/network_config/cgi-bin/kernel_ctrl.cgi`,

- **Скрипт канонизации теперь ждёт не «имя существует», а «устройство
  обработано udev»** (пер-устройственный признак `/run/udev/data/n<ifindex>`):
  переименование выполняется строго после прохода политики именования udev по
  этому устройству, и ворота не зависят от занятости всей очереди. Если
  udev-db так и не появилась за бюджет ожидания, скрипт честно (WARN в
  журнале) действует по текущему имени — поведение деградирует ровно до
  прежнего, не хуже. Дисциплина кодов выхода и список допустимых имён не
  изменились.
- **Юнит `sa02m-iface-canonical.service` упорядочен после
  `systemd-udevd.service` и `systemd-udev-trigger.service`** (`After=` +
  `Wants=`) — при `DefaultDependencies=no` ничто иное не гарантирует запуск
  udevd до юнита, и ограниченное ожидание одно (без ворот) не спасало: юнит
  успевал отработать до переименования. (Отказ от `Wants=systemd-udev-settle`
  состоялся в 1.0.5.54; этот выпуск заменяет ожидание всей очереди
  пер-устройственными воротами по существу.)
- **Бэкапы сетевых конфигов больше не поднимаются как живая конфигурация.**
  Установщик писал в `/etc/network/interfaces` строку
  `source /etc/network/interfaces.d/*` без фильтра — резервные файлы
  `*.sa02m-bak` (их создают панель и миграция) сорсились как настоящий
  конфиг: дублирующая станса `auto eth0` заставляла `ifup -a` настраивать
  интерфейс дважды, второй `ip addr add` падал с `RTNETLINK answers: File
  exists`, и `networking.service` оказывался failed (подтверждено стендовой
  перезагрузкой № 1: сами ворота отработали, переименования на 10,3 с).
  Теперь сорсятся только `*.conf`; перезапись `/etc/network/interfaces`
  установщиком безусловна, так что это же и полевая миграция.
  **файлы:** `scripts/02-network.sh`.
- **Честное ограничение:** на загрузках с занятой очередью udev плата может
  грузиться медленно по-прежнему (Debian `ifupdown-pre` ждёт очередь до
  120 с) — теперь это только задержка, а не отказ; причина занятости очереди
  не установлена и записана отдельным пунктом backlog.
- Новый регрессионный тест `scripts/dev/test-iface-canonical-gate.sh` (шесть
  сценариев ворот, включая точную boot-последовательность отказа) и
  расширенный статический гейт контракта
  (`.ai-dev/quality/checks/iface-naming-contract.sh`) закрепляют исправление.
  **файлы:** `etc/sa02m-iface-canonical.sh`,
  `etc/systemd/sa02m-iface-canonical.service`, `etc/fix-eth@.service`,

## 1.0.5.52 - Канонические имена Ethernet-интерфейсов; настройки сети не стирают сторонние строки (июл 2026)

### Сеть / система

- **Канонические имена Ethernet-интерфейсов `eth0`/`eth1` на всех платах.**
  Новый юнит `sa02m-iface-canonical.service` переименовывает `end0`/`end1` →
  `eth0`/`eth1` **до** `networking.service`, при **каждой** загрузке; на плате,
  где имена уже канонические (все текущие образы SA-02m), — чистый no-op.
  Драйвер изменения: SCADA-рантайм KLogic обращается к интерфейсу по
  вкомпилированному имени `eth0` (изменить нельзя — двоичный файл без исходников,
  вендорский `pre-start` восстанавливает его при каждом обновлении), плюс девять
  собственных потребителей репозитория, молча неработающих на `end0`-плате.
  Поддержка самого KLogic этим не обещается. **Почему это не возврат к
  1.0.3.38/39:** `.link`-файлы по-прежнему не используются — юнит зовёт
  `ip link set … name` через стабильный netlink ABI, от политики именования
  udev/systemd не зависит и сам чинит имя следующей загрузкой после
  `apt upgrade`; переименование только legacy → канон, обратного пути нет.
  Отказ юнита не блокирует сеть (`Before=` — только порядок): плата остаётся на
  старом имени, а отказ виден в `systemctl --failed`.
- **Миграция состояния на диске** (установщик, идемпотентно): `interfaces.d/end*.conf`
  → `eth*.conf` (адрес **не меняется**), `.link`-файлы удаляются безусловно,
  к `WATCHDOG_PING_END*` в `/etc/sa02m_network.conf` дописывается `ETH*`-аналог
  (строка оператора сохраняется), dhclient-hook переводится на новые имена.
  Перенос конфига связан с **подтверждённым** переименованием; в отложенном
  случае пишутся оба файла (legacy — как `allow-hotplug`), так что плата
  остаётся доступной даже при отказе переименования. **Живая плата применяет
  переименование при следующей перезагрузке** (по умолчанию; немедленно — только
  `install.sh --canonical-iface-now`, роняет SSH).
- **Проверено на живой legacy-плате** (стенд `192.168.1.136` оказался на
  `end0`/`end1`): переименование `end0`→`eth0` + `end1`→`eth1` на загрузке,
  миграция конфигов, вывод legacy-конфига в комментарии при сохранении из
  панели, выживание сторонних `post-up`-строк, ключ `klogic`, порядок запуска
  юнита. **Не воспроизводились**: срабатывание altname-защиты (нет платы с
  altname), загрузка по ветке отказа DUAL-CONF, реальный KLogic (проверка
  постановочная). Детали: `docs/contracts/ethernet-iface-naming.md`.

### Интерфейс / Сеть

- **Настройки сети больше не стирают сторонние строки конфигурации.** Ранее
  сохранение вкладки «Сеть» полностью перегенерировало
  `/etc/network/interfaces.d/<iface>.conf` и молча удаляло строки, добавленные
  оператором или вендорским рантаймом (`post-up`/`pre-up`/`hwaddress`/комментарии) —
  в частности, hook `post-up /home/klogic/adjust-eth0`, единственный механизм
  применения IP у KLogic. Теперь панель заменяет только свои строки
  (`address`/`netmask`/`gateway`/`dns-nameservers`/`metric` и заголовок стансы),
  остальное переносится дословно; повторное сохранение даёт побайтово тот же
  файл. Перед каждой перезаписью — резервная копия `<conf>.sa02m-bak`
  (одно поколение); битый конфиг не сливается, а сохраняется в бэкап и
  перегенерируется начисто. Отключение Ethernet № 2 выводит конфиг из работы
  (файл остаётся в виде комментариев + бэкап; прежний `sudo rm` из CGI был
  молчаливой пустышкой — у `www-data` нет права `rm`, конфиг фактически
  не удалялся).
- **Подпись на карточке Ethernet, когда интерфейсом также управляет KLogic**
  («IP-адрес этого интерфейса также задаёт KLogic» / предупреждение «KLogic
  установлен, но не управляет этим интерфейсом»). Определение — новый аддитивный
  ключ `klogic` в `config.cgi` (один запрос на загрузку страницы; в опрашиваемый
  `status.cgi` ничего не добавлено; старый закешированный бандл ключ просто
  игнорирует).

### Сеть / система (исправления)

- **Периодическая 30-секундная страховка восстановления IP не работала на
  текущих платах**: циклы `net-watchdog.sh` и `fix-eth.sh` перебирали только
  `end*.conf`, которых на `eth0`-платах (все с 1.0.3.39) нет. Событийное
  восстановление через udev (`fix-eth@ethN`) работало — страховка была
  ослаблена, не мертва. Теперь перебираются оба именования.
- Устаревшие имена `WATCHDOG_PING_END0/END1` в шаблоне
  `/etc/sa02m_network.conf` заменены на `ETH0/ETH1` (имя переменной выводится из
  живого имени интерфейса).

## 1.0.5.50 - MQTT: WB-формат событий Fast Modbus; чанк чтения AI — ключ устройства (июл 2026)

### MQTT / мост (Fast Modbus события)

- **Две формы кадра `configure_events` (0x18) вместо одной.** Новые прошивки
  MR-02m принимают только WB-форму (запись
  `[тип wire][рег][кол-во][настройка на каждый регистр]`, эталон
  `wb-mqtt-serial`); релизы ≤ 1.0.10.4x — только прежнюю, одноранговую.
  Мост пробует WB-кадр и при отсутствии подтверждения откатывается на прежний,
  поэтому модули обоих поколений остаются на событиях без ручной настройки.
  Подтверждённая рукопожатием форма запоминается по адресу и в дальнейшем
  пробуется первой — лишний обмен платится не чаще одного раза на модуль.
- **WB-проба уходит только модулям `mr02m`** (или по явному
  `fmb_event_wire: wb`). СЭ-02м-3 и ДТВ получают прежний кадр: новую прошивку
  MR-02m они не получают никогда, а неожиданный `0x18` уже заклинивал СЭ на
  COM2 с восстановлением только по питанию (1.0.5.46).
- **Разбор записей событий понимает обе грамматики** и опирается на форму,
  подтверждённую рукопожатием, а не на догадку по содержимому кадра.
  Отдельно закрыт случай перезагрузки: запись «перезагрузка» в WB-форме
  читается решающе, где бы в кадре она ни стояла — иначе перезагрузка
  перепрошитого модуля могла быть молча съедена устаревшим кешем поколения,
  и события по этому модулю умирали до перезапуска службы.
- **Неразбираемый кадр больше не заливает журнал** — одна строка на модуль
  раз в 10 с с числом подавленных (цикл событий работает на 20 Гц).
- Шов с прошивкой MR-02m описан отдельным контрактом
  `docs/contracts/fmb-event-wire.md` (обе грамматики, порядок попыток,
  источник истины, инвариант и что сломается при его нарушении). Сторона
  прошивки помечена как непроверяемая из этого репозитория.
  **файлы:** `opt/sa02m-modbus-mqtt/modbus_mqtt_bridge.py`,
  `docs/contracts/fmb-event-wire.md`, `docs/MQTT_TOPICS.md`,
  `opt/sa02m-modbus-mqtt/tests/test_fmb_event_parsers.py`,
  `opt/sa02m-modbus-mqtt/tests/test_fmb_wire_wb.py`

### MQTT / МР-02м

- **Размер чанка чтения AI стал настройкой устройства** — ключ
  `ai_read_chunk_regs` (либо переменная окружения
  `SA02M_MR02M_AI_CHUNK_REGS`), умолчание прежнее — 42 регистра (6 каналов).

## 1.0.5.43 - Устройство открывается через облако · версия прошивки в heartbeat (июл 2026)

### Интерфейс / Службы

- **CODESYS и MPLC4 больше не показывают ложный Active и «&lt;1м».** Юниты
  `codesyscontrol` / `mplc4` с `RemainAfterExit=yes` остаются `active (exited)`
  в systemd после выхода start-скрипта, хотя процесса уже нет. CTL `list` и
  дашборд брали этот ActiveState → аптайм 0 → UI рисовал «&lt;1м». Теперь
  активность = наличие процесса; без процесса — inactive / «—».
  **файлы:** `etc/sa02m-web-service-ctl.sh`, `www/network_config/cgi-bin/status.cgi`

### Облако / Интерфейс

- **Относительные пути ресурсов и API — устройство нормально открывается через
  облако.** Раньше пути в UI были корне-абсолютными (`/static/…`, `/cgi-bin/…`,
  `/api/flasher`), поэтому под облачным префиксом `/devcfg/<id>/` браузер
  запрашивал `cloud.cyntron.ru/static/…` → 404 (страница ломалась), а «спасал»
  лишь хрупкий 307-редирект по `Referer` со стороны облака (лишний round-trip на
  каждый ресурс, а любой запрос без `Referer` — 404). Убран ведущий `/` у
  `src`/`href`/`action`/`meta refresh` в `index.html`/`login.html`/`cloud.html` и
  у клиентских запросов в JS (`fetch`/`apiGet`/`apiPost`/`statusFetchJson`/
  `location`, база `api/flasher`) — путь резолвится относительно страницы. Все
  страницы отдаются с корневой глубины (`/index.html`, `/login.html`,
  `/cloud.html`, без под-маршрутов), поэтому относительный путь одинаково верен
  и в LAN (`/`), и через облако (`/devcfg/<id>/`). Корневой переход
  `location.replace('/')` → `('./')` (текущая директория). `Location:`-заголовки
  CGI НЕ трогаем — их переписывает сам облачный прокси. Устаревшие прошивки в
  поле по-прежнему опираются на облачный 307-fallback — он остаётся.

### Облако

- **Версия прошивки в heartbeat — облако видит актуальную версию.** Раньше облако
  показывало `fw_version`, снятую в момент привязки, навсегда: агент слал в
  heartbeat только `device_id`/`uptime_s`/`telemetry`, без версии. Теперь в
  payload heartbeat добавлены `fw_version` (из `get_fw_version()`) и `hw_variant`
  — те же значения, что уже уходили в enroll/claim. Облако обновляет их, если поля
  присутствуют; половины независимы (облако принимает payload и без этих полей).

## 1.0.5.42 - Шапка — версия подтягивается автоматически с сервера (июл 2026)

### Интерфейс

- **Версия в шапке — автоматически с сервера, не из «запечённой» константы.**
  Раньше номер версии рядом с «СА-02м» брался из JS-константы `APP_VERSION`,
  вкомпилированной в бандл; через облако со старым закэшированным бандлом версия
  могла не показываться вовсе (её добавили в шапку лишь в 1.0.5.34) или быть
  устаревшей. Теперь `app/init.js` при загрузке читает `/VERSION` (`fetch`,
  `cache: no-store`) и подставляет РЕАЛЬНО развёрнутую версию — единый источник
  правды (файл `VERSION`), шапка самокорректируется даже поверх устаревшей
  константы. Мгновенный fallback на `APP_VERSION` до ответа и при любой ошибке
  fetch, так что пустой шапки не бывает. Проверено на мобильной вёрстке (393px,
  обе темы): «СА-02м v1.0.5.42» видна, не обрезается.

### Облако

- **JS-логаут чистит cookie на РЕАЛЬНОМ пути** — авто-логаут по 401 больше не
  зацикливается через облако. Через облачный прокси cookie сессии живёт по
  `Path=/devcfg/<id>` (прокси пере-скоупит `Set-Cookie` в маршрут устройства),
  а не по `Path=/`, поэтому прежняя одиночная очистка `Path=/` не удаляла cookie
  → login.html отбрасывал обратно на дашборд → redirect-loop. Новый помощник
  `clearSessionCookie()` (`app.js`) удаляет `session_token` на КАЖДОМ префиксе
  текущего пути (`/`, затем каждый накопительный сегмент) — один из них реальный,
  очистка пустого пути — no-op. В LAN путь не менялся (cookie там на `Path=/`).
  Маршрут `/devcfg/<id>` НЕ захардкожен: устройство не знает своего облачного id.
- **Агент рендерит `transport.poolCount` из профиля** — ускорение проксируемых
  запросов через облако. Профиль enroll/claim теперь может нести `pool_count`;
  агент эмитит `transport.poolCount = <n>` в `frpc.toml` ТОЛЬКО когда ключ
  присутствует И валиден (целое 0..16, проверка как враждебного входа — по
  образцу allow-list портов), иначе — предупреждение и никакой строки (откат на
  дефолт frpc). Замер стенда: медиана отклика ~1.38 с → 0.431 с при `poolCount=4`
  (пул work-соединений устраняет свежий handshake через ~555 мс облачный линк).
  Легаси-рендер (без ключа) байт-в-байт прежний.

## 1.0.5.18 - Флешер: сигнатура из рег. 290 для .fw info-блока (все пути) (июл 2026)

### Флешер (RS-485)
- **Прошивка `.fw`-образов теперь переопределяет `NONE`/пустую сигнатуру во
  встроенном info-блоке реальной сигнатурой платы из рег. 290** — на всех
  четырёх путях отправки: приложение по адресу и по серийному, загрузчик по
  адресу и по серийному. Раньше `.fw` уходил с сырым info-блоком, а файлы
  CYNTRON часто несут `NONE`/пустую сигнатуру (BUGLOG 2005); загрузчик модуля
  сверяет её с рег. 290, из-за чего прошивка `.fw` была ненадёжной. Дополняет
  1.0.5.17, который закрыл только `.bin`-загрузчик по адресу.
  - **правится только 12-байтовое поле сигнатуры**, размер и CRC (CRC2 +
    crc32 полезной нагрузки) не трогаются — CRC считается по payload, а не по
    info-блоку, поэтому патч сигнатуры остаётся валидным.
  - **fail-safe:** реальная сигнатура из файла остаётся как есть (совместимость
    с WB-прошивками); замена происходит только при валидном и поддерживаемом
    чтении рег. 290 (та же проверка, что у `.bin`-путей). Ошибка чтения,
    `NONE`/пустое или неподдерживаемое значение — исходный блок уходит без
    изменений: регресса к `NONE` нет, прошивка не прерывается.
  - Путь `.wbfw` (`run_flash_sequence_wb`) не затронут — это отдельный формат
    WB, несущий собственную сигнатуру.
  - **файлы:** `opt/sa02m-flasher/sa02m_flasher/flash_protocol.py`
- **Тест** `test_fw_info_reg290_signature.py` (ряд `py-unit-flasher`) — патч из
  рег. 290, сохранение реальной сигнатуры и fail-safe-откат при ошибке чтения,
  для пути приложения и загрузчика.
  - Для веб-пользователей поведение UI не менялось.

  половины: демон читает то же серверное хранилище через
  `auth.py::check_session_store` (`sha256(token)` → файл → срок из содержимого,
  read-only), с новым ключом `SESSION_DIR` в `/etc/sa02m_flasher.conf` и
  tmpfiles-каталогом сессий. Токен не виден как имя файла (security).
- **Истёкшая сессия → страница входа.** Вместо тостов «HTTP 401: unauthorized»
  от отдельных виджетов (напр. «Порты») при 401 пользователя перекидывает на
  форму авторизации (централизованно, обёртка `fetch`). Одиночные транзиентные
  401 (краткая гонка в хранилище сессий) не разлогинивают: 401 перепроверяется
  лёгким запросом к `auth_check.cgi` (не к кэшированному `status.cgi`) — редирект
  только при подтверждённой пропаже сессии, иначе исходный GET тихо повторяется.
- **Обновление сессии — троттлинг и атомарность.** Продление срока веб-сессии
  выполняется атомарно и с троттлингом — устранены редкие ложные 401 от
  смешанного/гоночного доступа к хранилищу сессий при обновлении страницы.

### Производительность
- **HW-блок «Дискретный выход, USB-питание и индикация» грузится рано.**
  `status.cgi?part=hardware` перенесён из тяжёлой очереди опроса в лёгкую
  (ранняя фаза 500 мс): дешёвое чтение (~0.4 с, TTL-кэш, без живого I2C)
  больше не ждёт 2.2-с интервал тяжёлой очереди. Блок заполняется за ~3 с
  вместо ~18 с; период опроса 6 с (был 12 с) — нагрузка на I2C не растёт.
  Проверено на устройстве.

### Инструменты и качество (dev-only)
- **version-consistency gate выбирает рабочий python.** Строка реестра качества
  (`.ai-dev/quality/tools.json`) пробует `python3` → `python` → `py` и запускает
  первый рабочий интерпретатор. На Linux/CI поведение не меняется (`python3`);
  на Windows-машине разработчика, где `python3` — нерабочая заглушка Microsoft
  Store, гейт больше не падает ложно. Fail-closed: без рабочего интерпретатора
  гейт ПАДАЕТ. На веб-интерфейс и развёрнутые устройства не влияет.

### Установщик
- **Поддержка имён интерфейсов `end0`/`end1`.** `scripts/02-network.sh` больше
  не завязан жёстко на `eth0`/`eth1`: он определяет фактическое имя интерфейса
  (`first_existing_iface`, как в веб-UI), пишет конфиг под него
  (`interfaces.d/<iface>.conf`) и на плате с предсказуемыми именами не удаляет
  её `.link`-файлы. Повторный прогон установщика без `--ip` НЕ трогает живой
  интерфейс (не делает flush) — установка/обновление на плате с `end0` больше
  не рвёт связь. На платах с `eth0` поведение не изменилось.
- **Права каталога сессий — прошивальщик не отдаёт 401 после установки.**
  Установщик создавал `/run/sa02m-web-sessions` с правами `0700`, из-за чего
  демон `sa02m-flasher` (в группе www-data) не мог войти в каталог и прочитать
  сессию → `/api/flasher/*` отвечал 401. Установщик теперь создаёт каталог с
  `2750` (setgid, группа www-data — демону доступно), а `lib_web_auth.sh`
  доводит права на каждом входе (самолечение существующего каталога).

## 1.0.3.17 — MQTT: доступность и надёжность в стиле wb-mqtt-serial

Применимо к Modbus→MQTT мосту (`opt/sa02m-modbus-mqtt/modbus_mqtt_bridge.py`) и
системной телеметрии (`sa02m_telemetry.py`) — для всех модулей: **MR-02м**, **ДТВ**,
**СЭ-02м-3**.

- **Last Will (LWT):** при падении/обрыве моста брокер сам публикует
  `/devices/sa02m-bridge/meta/error="r"` (единый канал ошибок). Телеметрия — то же
  для `/devices/sa02m-<host>/meta/error`. Клиенты не доверяют устаревшим retained.
- **Доступность устройства (device-level):** после `offline_after_fails` подряд
  неответов мост публикует `/devices/<id>/meta/error="r"`, при восстановлении — `""`.
  Значения `controls/*` сохраняют последнее достоверное значение.
- **Экспоненциальный back-off опроса** «мёртвого» устройства (`backoff_base_s` …
  `backoff_max_s`) — не блокирует half-duplex RS-485 для живых устройств на шине.
- **Устройство-статус моста** `/devices/sa02m-bridge`: `connection` (switch),
  `devices_total`, `devices_online`, `poll_errors`.
- **Корректный graceful offline** при `systemctl stop` (мост и устройства помечаются
  offline до отключения от брокера).
- **Совместимость paho-mqtt 2.x:** телеметрия переведена на callback API v1
  (как мост) — фикс несовпадения сигнатур колбэков.
- Новые ключи конфигурации (`/etc/sa02m-modbus-mqtt.yaml`): `mqtt.availability`,
  `mqtt.bridge_device_id`, `mqtt.username`/`password`, и на устройство —
  `offline_after_fails`, `backoff_base_s`, `backoff_max_s`. Топики описаны в
  [docs/MQTT_TOPICS.md](docs/MQTT_TOPICS.md#доступность-как-в-wb-mqtt-serial).

- Отдельный системный пользователь `sa02m-flasher` (не `www-data`):

  дополнительный общий секрет `INTERNAL_TOKEN` (заголовок `X-SA02M-Auth`).

### Схема `index.json` на cyntron.ru

```json
{
  "schema": 1,
  "updated": "2026-04-20",
  "channels": {
    "stable": [
      {
        "file": "MR-02m_1.2.3.0.fw",
        "version": "1.2.3.0",
        "signatures": ["mp02m"],
        "device": "MR-02m",
        "size": 34816,
        "sha256": "…",
        "released": "2026-03-15",
        "notes": "исправление опроса ADS1220"
      }
    ],
    "beta": []
  }
}
```

Поля: `schema` (версия формата, сейчас `1`), `updated` (дата обновления
манифеста), `channels.<name>[]` (каналы `stable`/`beta`). Для каждой прошивки:
`file` (имя в каталоге `firmware/`), `version` (обязательно X.Y.Z.W — видно в
UI), `signatures[]` (допустимые сигнатуры устройств — демон подбирает
совместимые прошивки по сигнатуре из Modbus-регистра `290`), `size`, `sha256`
(для контроля целостности при скачивании), `released`, `notes`.

## 1. Реструктуризация проекта

### Проблема (было)
Весь HTML/CSS/JS был встроен в один bash-скрипт `web/web` в виде heredoc-ов. Это делало невозможным:
- редактирование файлов в IDE без сложных правок установщика;
- версионирование отдельных компонентов;
- деплой без повторного запуска всего монолитного скрипта.

### Решение (стало)
Проект разделён на независимые файлы. Установщик **копирует** готовые файлы, а не генерирует их.

```
install.sh                        ← точка входа: sudo ./install.sh [--ip X] [--port Y]
scripts/
  lib.sh                          ← общие функции: log(), pkg_install(), svc_enable()
  01-system.sh                    ← ОС: пакеты, пользователи, udev-симлинки RS-485/COM
  02-network.sh                   ← сеть: eth0 static IP, watchdog, udev правила
  03-webserver.sh                 ← nginx + fcgiwrap + sudoers + деплой www/
etc/
  nginx/network_config.conf       ← шаблон nginx (токены __PORT__, __WEB_ROOT__)
  sa02m_hw.conf                   ← шаблон GPIO (DO, beeper, alarm LED)
  sa02m_network.conf              ← шаблон настроек watchdog (WATCHDOG_PING_*)
  fix-eth.sh                      ← скрипт восстановления сети
  fix-eth.service                 ← systemd unit (oneshot, triggered by udev)
  net-watchdog.sh                 ← постоянный демон мониторинга
  net-watchdog.service            ← systemd unit (simple, Restart=always)
  99-lan-recovery.rules           ← udev правила
www/network_config/               ← готовые файлы для деплоя в /var/www/network_config/
  index.html
  login.html
  static/css/main.css
  static/js/app.js
  static/logo.svg
  cgi-bin/                        ← API-скрипты (без HTML внутри)
    config.cgi  status.cgi  hw_set.cgi
    apply.cgi   login.cgi   logout.cgi
    restart.cgi reboot.cgi  log.cgi
```

## 4. Страница входа — анимация огня

### Файл: `www/network_config/login.html`

Добавлена полноэкранная анимация огня на `<canvas>` за карточкой входа.

#### Алгоритм (Doom-style fire, 1993)
```
1. Canvas W×H пикселей (SCALE=3 → рендер в 3× меньшем буфере для ARM)
2. Нижняя строка постоянно = 255 (источник тепла)
3. Каждый кадр: pixel[y][x] = avg(4 соседей снизу) − random_decay
4. Палитра 256 цветов: чёрный → тёмно-красный → оранжевый → жёлтый → белый
5. requestAnimationFrame() — синхронизация с vsync браузера
```

#### Параметры
| Параметр | Значение | Описание |
|----------|----------|----------|
| `SCALE` | 3 | Масштаб пикселя (производительность на ARM) |
| `DECAY` | 1 | Скорость охлаждения |
| Палитра | 256 цветов | black→red→orange→yellow→white |

#### Тумблер управления
- Расположен: фиксированный, правый верхний угол (`position: fixed; top:18px; right:22px`)
- Иконка пламени мерцает (`@keyframes flicker`)
- Состояние сохраняется в `localStorage` (ключ `sa02m_fire`)
- По умолчанию: **включено**
- При выключении: плавное затухание (`transition: opacity .6s`)

#### Эффект карточки поверх огня

## 9. Сетевой watchdog — полная переработка

### Критические ошибки в старом коде

| # | Файл | Проблема |
|---|------|----------|
| 1 | `99-lan-recovery.rules` | **Перенос строки внутри `RUN+=`** — правило никогда не срабатывало |
| 2 | `99-lan-recovery.rules` | `systemctl restart` без `--no-block` → **дедлок udev** |
| 3 | `fix-eth.sh` | Вся DHCP-логика (`dhclient`, `dhcpcd`) — **бесполезна** на устройстве со статическим IP |
| 4 | `fix-eth.sh` | `ethtool` для определения линка — пакет может не быть установлен |
| 5 | `fix-eth.service` | `TimeoutSec=10` — скрипт убивался до завершения (реальное время > 30с) |
| 6 | Весь стек | Нет постоянного watchdog — реакция только на физическое подключение кабеля |

### `fix-eth.sh` — новая логика

#### Трёхуровневая проверка здоровья
```
carrier_up()         → /sys/class/net/ethX/carrier (всегда есть, без ethtool)
has_ip()             → ip -4 addr show
check_connectivity() → пинг (см. приоритет ниже)
```

#### Приоритет выбора цели пинга
```
1. WATCHDOG_PING_ETH0=<IP>  в /etc/sa02m_network.conf  (явная настройка)
2. gateway в /etc/network/interfaces.d/eth0.conf        (стандартный шлюз)
3. Ни то, ни другое → пинг пропускается                 (LAN без маршрутизации)
4. WATCHDOG_PING_ETH1=skip  → пинг принудительно отключён
```

> **Важно:** отсутствие шлюза — нормальная ситуация для eth1 как локального интерфейса.
> В этом случае считаем интерфейс здоровым если есть carrier + IP.

#### Восстановление
```bash
ifdown "$iface"      # читает /etc/network/interfaces.d/*.conf
sleep 1
ifup "$iface"        # применяет статический IP правильно
```
Fallback если `ifdown/ifup` нет: `ip link set down/up` + ручная установка IP из конфига.

#### Защиты
- **Lock-файл** `/run/fix-eth/<iface>.lock` — предотвращает параллельный запуск
- **Cooldown 60с** — между попытками восстановления одного интерфейса
- **Ротация лога** — автоматически при > 512 КБ (сохраняет последние 200 строк)
- **Поддержка eth1** — автоматически обходит все `eth*.conf`

### `net-watchdog.sh` + `net-watchdog.service` *(новые)*

Постоянный фоновый демон.

```bash
# Каждые CHECK_INTERVAL=30 секунд:
for conf in /etc/network/interfaces.d/eth*.conf; do
    fix-eth.sh "<iface>"
done
```

```ini
[Service]
Type=simple
Restart=always        # перезапускается при падении
RestartSec=10
```

Покрывает сценарии, которые udev **не покрывает**:
- потеря IP без физического события
- зависание сетевого стека
- программный сбой после загрузки

### `fix-eth.service` — исправления

| Параметр | Было | Стало |
|----------|------|-------|
| `TimeoutSec` | `10` | `45` |
| `StartLimitBurst` | `2` | `3` |
| `StartLimitIntervalSec` | `5` | `60` |
| `RemainAfterExit` | `yes` | `no` |
| `StandardOutput` | *(нет)* | `journal` |

### `99-lan-recovery.rules` — исправления

```ini
# БЫЛО (СЛОМАНО — перенос строки в RUN+="..."):
ACTION=="add", SUBSYSTEM=="net", KERNEL=="eth0", RUN+="/usr/bin/systemctl restart 
fix-eth.service"

# СТАЛО (исправлено):
ACTION=="add", SUBSYSTEM=="net", KERNEL=="eth0", RUN+="/usr/bin/systemctl --no-block start fix-eth.service"
ACTION=="add", SUBSYSTEM=="net", KERNEL=="eth1", RUN+="/usr/bin/systemctl --no-block start fix-eth.service"
ACTION=="bind", SUBSYSTEM=="net", KERNEL=="eth0", RUN+="/usr/bin/systemctl --no-block start fix-eth.service"
ACTION=="bind", SUBSYSTEM=="net", KERNEL=="eth1", RUN+="/usr/bin/systemctl --no-block start fix-eth.service"
```

Добавлен `ACTION=="bind"` — срабатывает при привязке драйвера (например после `modprobe`), а не только при физическом подключении кабеля.

### `/etc/sa02m_network.conf` *(новый)*

Конфиг watchdog — без правки скриптов.
```bash
WATCHDOG_PING_ETH0=192.168.1.1  # переопределяет шлюз
WATCHDOG_PING_ETH1=10.0.0.2     # для eth1 без шлюза
WATCHDOG_PING_ETH1=skip         # отключить пинг для интерфейса
RECOVER_COOLDOWN=90             # изменить cooldown
```
