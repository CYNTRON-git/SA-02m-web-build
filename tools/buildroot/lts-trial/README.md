# Испытательное ядро Linux 6.1.193 для СА-02м NANO-2E

Для стенда подготовлены два ARMv7-профиля, SMP и PREEMPT_RT. Оба зарегистрировали H3 Audio Codec в QEMU, загрузили модули TUN, IPv6 и WireGuard и передали по восемь пакетов по зашифрованному туннелю. Испытание физической платы A40i и решение о серийном допуске остаются открытыми. Штатные сборка, выбор ядра и обновление СА-02м используют прежние профили rc6.

## Сборка

Нужны Python 3, Docker с linux/amd64, закреплённый образ сборщика и том `cyntron-sa-bsp-work` с двумя профилями Buildroot. Устройство тома и исходное окружение описаны в [документации BSP](../rc6-tun.md). Поместите официальный архив `linux-6.1.193.tar.xz` в локальный каталог и из корня проекта запустите одну команду. Выходной каталог должен быть новым. [Архив ядра](https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.1.193.tar.xz) · [Подпись несжатого tar](https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.1.193.tar.sign)

```sh
python3 tools/buildroot/lts-trial/build.py linux-6.1.193.tar.xz out-kernel-trial
```

Каждый профиль собирается в новом контейнере без сети, том BSP открывается для чтения. До компиляции команда сверяет Linux, патчи, компилятор, линкер, исходные и полученные конфигурации. В каталогах `smp` и `rt` появятся zImage, архив модулей, конфигурация, System.map, Module.symvers, GNU Build ID и отдельный пассивный initramfs. Оба каталога публикуются вместе после сверки контрольных сумм. [Входы](source.sha256) · [Инструменты](toolchain.sha256) · [Выход SMP](smp.output.sha256) · [Выход RT](rt.output.sha256)

## Происхождение и инженерные решения

Основой служит Linux 6.1.193, commit `1ca1436ccc68275d0b43b6a730b3940fcc46b7c2`. Подпись проверена ключом Greg Kroah-Hartman `647F28654894E3BD457199BE38DBBDC86092693E`. Для проверки содержимого каждого из трёх патчей используйте `gzip -dc <имя.patch.gz>`. [Тег stable](https://kernel.googlesource.com/pub/scm/linux/kernel/git/stable/linux/+/refs/tags/v6.1.193) · [Ключи kernel.org](https://www.kernel.org/signature.html)

1. `01-starterkit` переносит дельту между полным архивом Starterkit `998d6a5a583ad42fdf5ef3c2b3bdeb4f5a2f93789d4c5b65b032a9c2075e9804` и upstream v6.1-rc6. Из 117 путей 74 добавлены, 40 слились чисто, три потребовали разбора. В USB PHY сохранены обходы stable для D1/H616 и порядок доступа к регистру R40 из BSP. В Cedrus сохранены два устройства кодера и декодера и учёт полезного размера H.265 из stable. В EMAC сохранены reset и совместимость R40, в DTS платы — явный PHY ID из обоих сохранённых сборочных профилей. PWM переведён на возвращающий статус интерфейс stable.
2. `02-sunxi-audio` переносит изменение upstream для четырёх драйверов Allwinner. В исходном stable 6.1.193 sun4i-codec передавал старое поле `.probe`. При регистрации ASoC помещал временно выделенную через devm копию операций в общий статический дескриптор DAI. После отложенного повторного probe происходил сбой в `snd_soc_dai_set_fmt` до запуска init. Использование статической таблицы операций сохраняет пробу DMA и регистрацию звуковой карты. Проверено обычной загрузкой с включённым кодеком до и после изменения. [Изменение ASoC](https://github.com/torvalds/linux/commit/fc95a8a3eaebff8130bd34a43e6a0fc14aa766d9)
3. `03-rt72` применяется только к RT. Официальный патч 6.1.192-rt72, SHA-256 xz `c4df2cca8ff986a0fcda9d2c00551d293f8fdda932470c087e3ef72a81eafd79`, подписан Clark Williams ключом `D5653EA39C8675DA4BD5971C13B55DD07C53B851`. Для 6.1.193 подготовлена локальная адаптация всех 176 путей. С UART-дельтой BSP пересеклись `8250_port.c` и `serial_8250.h`. Итог проверен повторным применением поверх 6.1.193 с перенесённым BSP. Сопровождение этой комбинации относится к проекту. [Публикации PREEMPT_RT](https://cdn.kernel.org/pub/linux/kernel/projects/rt/6.1/) · [Ключ сопровождающего](https://kernel.googlesource.com/pub/scm/docs/kernel/pgpkeys/+/d5ecb771e8492579957144184fa0dd391067c85e/keys/13B55DD07C53B851.asc)

## Стендовая проверка

В каждом профиле проверены 27 значений конфигурации платы и наличие всех 45 прежних путей модулей. В каждом из 62 новых ELF совпали ARM ABI и строка версии. Два независимых сетевых пространства имён QEMU проверены с ARMhf-программами ip, wg, ping и ping6 серийной комплектации. Проверены создание TUN, время рукопожатия обоих WireGuard-узлов, счётчики передачи и приёма, обмен IPv4 и IPv6 в обе стороны. На RT дополнительно прочитано `/sys/kernel/realtime=1`. Сетевой адаптер хоста, внешние узлы и диски в испытании отсутствовали. [Квитанция SMP](checks/smp-qemu.txt) · [Квитанция RT](checks/rt-qemu.txt) · [Сценарий обмена](checks/vpn-init.sh)

Лабораторный набор от 27 ноября находится в `final-preparation.uAqD5OCq/lts-candidate` на носителе `sa02m-golden-20261127`. В нём сохранены полные serial-логи, проверка подписей, `qemu/orangepi-pc.dtb` и `qemu/vpn-{smp,rt}.cpio.gz`. Для повтора укажите один из двух полученных zImage, DTB модели H3 и диагностический initramfs этого же профиля. Команда сверяет три SHA перед загрузкой. Через `dtc` и `fdtoverlay` она добавляет во временную копию H3 DTB свойство загрузчика `/chosen/rng-seed` из 32 свежих случайных байт хоста. Это позволяет гостю создать ключи WireGuard при отключённой внешней сети. После запуска команда проверяет результат обмена. Источник энтропии физического A40i при загрузке подлежит отдельной проверке на стенде. [Повторная проверка QEMU](checks/replay-qemu.py)

```sh
python3 tools/buildroot/lts-trial/checks/replay-qemu.py smp out-kernel-trial/smp/zImage \
  /lab/qemu/orangepi-pc.dtb /lab/qemu/vpn-smp.cpio.gz smp-boot.log
```

## Первое испытание A40i

1. Требуются UART-консоль с проверенным доступом к U-Boot и отдельный носитель для загрузки либо отдельная восстанавливаемая плата. Сверьте хеши файлов профиля и рабочий продуктовый DTB `sun8i-a40i-sk.dtb` с FAT, SHA-256 `b16fe929c81c47ae82d9b5c9558476562c010ea4887cc7487d035178bc402745`. Проверьте на стенде возврат к прежнему ядру с внешней копией FAT. Штатный boot.scr запускает единственный активный zImage с eMMC.
2. Через U-Boot однократно загрузите в RAM с отдельного носителя zImage, этот DTB и `passive.cpio.gz` одного профиля. Адреса буферов и источник консоли берутся из окружения конкретного загрузчика, размер initramfs фиксируется сразу после его загрузки. Для `bootz` вторым аргументом передают адрес и размер initramfs, третьим адрес DTB. Замените bootargs в оперативном окружении на активную серийную консоль и `root=/dev/ram0 ro rdinit=/init panic=0`. Проверьте `printenv bootargs` до запуска. Такой резервный корень сохраняет eMMC вне пути загрузки и при ошибке распаковки initramfs. После сброса U-Boot использует исходное окружение.
3. Снимите UART-журнал. Пассивный init сверяет строку модели из переданного DTB и uname, печатает связи DT с Ethernet/MDIO, eMMC, UART, USB, аудио и WDT, затем ждёт отключения питания в RAM. Он монтирует procfs, sysfs и devtmpfs. На H3 оба профиля штатно напечатали `HIL_REJECT_IDENTITY`. Маркер `HIL_PASSIVE_INVENTORY_COMPLETE` означает окончание сбора, исполнитель сверяет маркировку физического экземпляра и действующую UART-консоль отдельно. Сопоставьте строки MAC и MDIO с адресами 1c0b000 и 1c50000 для распаянных портов, eMMC с контроллером 1c11000 и отдельными p1/p2. Зафиксируйте отсутствующие узлы. Привязка PHY может появиться при поднятии интерфейса, что проверяют на следующем этапе. [Исходник пассивного init](passive.c)
4. На отдельной копии системы требуются холодная и тёплая загрузки обоих профилей, UART/RS-485 с реальным обменом, USB и модемы, watchdog с восстановлением, звук и численное измерение RT под рабочей нагрузкой. Для каждого доступного физического Ethernet сопоставьте адрес DT, драйвер MAC, PHY и режим линии, измерьте двусторонний трафик и изменения счётчиков. У донора 1ETH исходный eth0 показывал link up, неопределённые speed/duplex, CRC 2, length 1 и dropped 6662 при 769933 принятых пакетах. Второй порт требует физически доступного соответствующего варианта платы. Причина прежних зависаний остаётся открытой.

## Граница допуска безопасности

Для двух ранее выделенных исправлений исходники обоих кандидатов содержат проверку отображения UID/GID в OverlayFS и проверку полного значения verdict в Netfilter. Включены `CONFIG_OVERLAY_FS` и `CONFIG_NF_TABLES`. Этим подтверждены соответствующие изменения кода. [CVE-2023-0386](https://github.com/torvalds/linux/commit/4f11ada10d0ad3fd53e2bd67806351de63a4f9c3) · [CVE-2024-1086](https://github.com/torvalds/linux/commit/f342de4e2f33e0e39165d8639387aa6c19dff660)

Для общего допуска требуется датированная и воспроизводимая сверка актуальных записей с точной базой stable, составом обоих профилей, 117 путями Starterkit и локальной адаптацией RT. Отдельного рассмотрения требуют собственные драйверы и изменения привязок оборудования. Подойдут проверяемые бюллетени поставщика либо собственное независимое заключение по сопоставимому набору записей с версиями, исходными путями, исправлениями и обоснованиями применимости. Исправления двух CVE, подписанный исходный архив и успешный запуск в QEMU закрывают только соответствующие проверки. Физический HIL и оценка безопасности серийного состава оформляются отдельно.
