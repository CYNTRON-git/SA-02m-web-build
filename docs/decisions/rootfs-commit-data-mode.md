# Политика rootfs: commit=60 и ordered

Принятое решение для ext4-корня СА-02м — интервал журнала `commit=60` и режим
данных `ordered`. Единственная реализация изменения —
`usr/local/sbin/sa02m-rootfs-policy.sh`; её вызывают системный установщик,
упаковщик Debian rootfs и финализатор снятого образа. Эксплуатационная
приёмка и развёртывание описаны в [deployment.md](../deployment.md).

`live` определяет текущий корень через `findmnt`, проверяет ext4, блочное
устройство и совпадение с единственной записью `/` в fstab. `offline ROOT
DEVICE` требует явно смонтированный корень образа и его фактическое
устройство. `check ROOT DEVICE` проверяет конечную политику. Ни один
offline-вызов не перемонтирует файловую систему хоста.

Помощник сохраняет исходный fstab, владельца, права, параметры текущего
монтирования и defaults суперблока в закрытом каталоге
`etc/.sa02m-rootfs-policy-*` внутри обрабатываемого корня. Он меняет только
опцию commit корневой записи, проверяет её через `findmnt --verify`, затем
публикует файл заменой после fsync. Остальные записи и опции сохраняются.
Небезопасные типы файла, ссылки, чужой владелец, доступ на запись группе или
остальным, неоднозначный корень и конфликтующая явная `data=` приводят к
отказу. Повторный запуск не переписывает уже правильный fstab.

`tune2fs` убирает defaults `journal_data_writeback` и `journal_data`, сохраняя
остальные defaults, включая `user_xattr` и `acl`. Это меняет режим данных
при следующем монтировании. Живой вызов применяет только
`mount -o remount,commit=60 /` и проверяет результат. Новая `data=` в fstab
не добавляется. При ошибке после начала изменений помощник сообщает
отдельно состояние fstab, суперблока и живого монтирования, а также путь к
резервной копии. Эти три изменения не являются общей атомарной транзакцией.

Ordered обеспечивает порядок записи данных относительно связанной записи
метаданных в журнал. Интервал 60 секунд не обещает сохранность всех данных
за последние 60 секунд: приложениям по-прежнему необходим fsync. Локальные
тесты на ext4 loop проверяют фактический переход режима только после нового
mount; они не заменяют аппаратное испытание отключением питания и не
подтверждают бюджет износа или производительности.
