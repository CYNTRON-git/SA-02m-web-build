# Решение: GitHub-канал OTA устанавливает неподписанный код от root

**Дата:** 2026-08-28 (1.0.6.24). **Статус: действует (поведение не меняется).**

Дом решения о том, ПОЧЕМУ обновление «Обновление веб» из GitHub не требует
Ed25519-подписи артефакта, тогда как офлайн-путь (загрузка `.sa02m`-файла) —
требует. Поднято аудитом 2026-08-28 (`.ai-dev/audit/security-verdict.md`, M8):
не как дефект кода, а как невидимый компромисс — модель угроз его не взвешивала.
Машинная грамматика (имена, флаги) — латиницей (`PROTOCOL.md` invariant 5);
пояснения — по `docLanguage: ru`.

## Что именно происходит

`etc/sa02m-update-runner.sh` при `source=github` выставляет `allow_unsigned=1`,
что пропускает проверку Ed25519, обязательную для file-upload пути
(`sa02m-update-runner.sh` — валидатор подписи для `source=file`). Обновление
скачивается по HTTPS с проверкой сертификата по умолчанию, репозиторий ограничен
allow-list (`etc/sa02m-web-update-apply.sh`). Применяет обновление root.

## Якорь доверия GitHub-канала

Целиком — транспортный:

1. **HTTPS с проверкой сертификата** (urllib TLS-verify, никаких `-k`/`verify=False`
   в дереве — подтверждено аудитом, раздел «Clean»).
2. **Allow-list репозиториев** (`sa02m-web-update-apply.sh`): скачать можно только
   из перечисленных CYNTRON-репозиториев, не из произвольного URL.

Подписи артефакта НЕТ. Значит, кто контролирует GitHub-репозиторий/аккаунт
CYNTRON (или встал в разрыв TLS, обойдя проверку сертификата), тот доставляет
**root-код на устройство** — против актора A4 (целевая атака) это реальный
supply-chain-вектор.

## Почему оставлено как есть (осознанно)

- **Офлайн-путь уже защищён подписью** — самый опасный вектор (произвольный файл
  от неизвестного) закрыт; GitHub-канал ограничен доверенным источником.
- **Подпись GitHub-канала — бо́льшая работа**, чем эта security-ветка (1.0.6.24)
  несёт: нужен ключевой материал на стороне сборки, встраивание подписи в релизный
  артефакт GitHub, публикация публичного ключа на устройство и путь его ротации.
  Это отдельная веха, а не строка в аудит-ветке.
- Оператор в 1.0.6.24 **не просил** менять поведение — задача аудита была сделать
  компромисс видимым, а не устранить его.

## Что изменит это решение (условие пересмотра)

Подписать GitHub-канал (перевести его на тот же Ed25519-путь, что и file-upload)
следует, когда появится любое из:

- релиз/выкладка на устройства, где GitHub-аккаунт CYNTRON не под полным контролем
  команды, или расширение allow-list на внешние репозитории;
- требование заказчика/регламент, запрещающий неподписанный код на устройстве;
- любой инцидент компрометации GitHub-аккаунта/репозитория.

До тех пор остаточный риск взвешен здесь и в модели угроз (`docs/threat-model.md`
§4, строка `A4→S2`), а не молчит.

## Не сделано (осознанно)

- **Не** меняли `allow_unsigned` для `source=github` — поведение то же.
- **Не** трогали file-upload путь — он и так требует подпись.
