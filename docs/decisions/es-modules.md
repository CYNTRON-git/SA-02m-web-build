# Решение: синтаксический пол фронтенда — ES2020 + нативные ES-модули

**Дата:** 2026-08-18. **Статус: действует.**

Дом обоснования синтаксического пола для JS, который отдаёт устройство
(`www/network_config/static/js/**`). На него ссылается правило
`docs/agent-rules/web-code-rigor.md ## Frontend floors` («ES2020 + ES modules»);
правило формулирует пол, этот документ — почему он именно такой. Машинная
грамматика (имена файлов, версии браузеров, флаги команд) — латиницей
(`PROTOCOL.md` invariant 5); пояснения — по `docLanguage: ru`.

## Контекст

Правило `web-code-rigor.md` (пункт «ES5-leaning syntax», строки 84–88 до этого
решения) требовало «избегать optional chaining / nullish coalescing в новом коде»
и «никогда не добавлять синтаксис модулей (`import`) — бандлы остаются обычными
скриптами», мотивируя это тем, что «UI открывают из встраиваемых браузеров и
старого WebKit».

Правило вошло в репозиторий коммитом `ad6c93d` (2026-07-12) — переносом набора
agent-rules из проекта MR-02m «с адаптацией под веб». Ни в этом коммите, ни где-либо
ещё в дереве нет: решения, которое его породило; названного клиента (модели
киоска / HMI-панели / встроенного браузера); версии WebKit, под которую писался
пол. То есть пол был **унаследованной шаблонной прозой**, а не зафиксированным
требованием заказчика.

Запрет мешает следующему шагу — разложению JS-«god-файлов» (`flasher.js` ~5100
строк, `mqtt.js` ~2800 строк) на модули с явными импортами: без `import`/`export`
единственный способ дробить файл — глобалы на `window.*` + порядок `<script>`-тегов
в `index.html`, что уже сделано для `app/*.js` (F10) и не масштабируется дальше
(нет явных зависимостей, нет изоляции области видимости, нет проверки «кто что
использует»).

## Доказательства

### 1. Клиента, ради которого держали ES5-пол, в проекте нет

Просмотрены `README.md`, `docs/product.md`, `docs/deployment.md`,
`docs/threat-model.md`, `CHANGELOG.md`. Пользователь UI везде — «браузер на ПК»
(`README.md`: «Откройте браузер на ПК», «Веб-интерфейс (браузер)»), телефон /
планшет (мобильные вьюпорты в `ui-layout`), облачный доступ (`cloud.js`, тоннель).
Ни одного упоминания киоска, HMI-панели, встроенного WebKit-браузера или
конкретной старой версии браузера как поддерживаемого клиента.

Оператор подтвердил (2026-08-18): клиентов старше Chromium 80 / Firefox 74 /
Safari 13.1 (2020) в контуре нет.

`?.` и `??` — **синтаксис уровня парсера**: браузер без их поддержки не выполняет

уже недоступны любому клиенту старше 2020 года. Пол «ES5-leaning» никого не
защищал: то, что он якобы оберегал, давно не открывается.

### 3. Нативные ES-модули старше уже отгружаемого пола на ~3 года

| Возможность | Chromium | Firefox | Safari | Год | Источник |
|---|---|---|---|---|---|
| `<script type="module">` + `import`/`export` | 61 | 60 | 11 (10.1 с флагом) | 2017 | caniuse `es6-module`; MDN «JavaScript modules» |
| dynamic `import()` | 63 | 67 | 11.1 | 2017–2018 | caniuse `es6-module-dynamic-import` |
| optional chaining `?.` | 80 | 74 | 13.1 | 2020 | caniuse `mdn-javascript_operators_optional_chaining` |
| nullish coalescing `??` | 80 | 72 | 13.1 | 2020 | caniuse `mdn-javascript_operators_nullish_coalescing` |
| import maps (`<script type="importmap">`) | 89 | 108 | **16.4** | 2021–2023 | caniuse `import-maps`; MDN |
| logical assignment `??=` `\|\|=` | 85 | 79 | 14 | 2020 | MDN |
| `Array.prototype.at`, `String.replaceAll` | 92 / 85 | 90 / 77 | 15.4 / 13.1 | 2021 | MDN |

Вывод: любой браузер, который сегодня открывает вкладку MQTT (нужен `?.`), умеет
нативные модули с запасом. Разрешение модулей **не сужает** круг клиентов ни на
одного.

## Решение

1. **Явный синтаксический пол: ES2020 + нативные ES-модули** (`import` /
   `export`, `<script type="module">`, dynamic `import()`). Это фиксирует то, что
   уже отгружается, и разрешает модули.
2. **Всё новее пола — отдельное решение**, а не «раз работает у меня»: import maps
   (Safari 16.4 — режет iPad/iPhone 2021–2022 годов без обновления), `??=`/`||=`,
   `.at()`, `replaceAll`, top-level `await`, `Array.prototype.findLast` и т. п.
   Появление такой конструкции в диффе — находка ревью, если решения нет.
3. Правило `web-code-rigor.md ## Frontend floors` заменяет пункт «ES5-leaning
   syntax» на этот пол и **ссылается сюда**, не пересказывая обоснование.

## Последствия — три предпосылки, обязательные ДО первого модуля

Исследование показало, что первый `import` в дереве без этих трёх изменений
ломает либо гейт качества, либо обновление устройств. Все три реализованы
в том же PR, что и это решение; ни одного модуля в нём нет.

### П1. `js-syntax` должен понимать модули (иначе гейт слепнет)

`node --check file.js` в Node 20/24 **молча возвращает 0** для файла с
`import`/`export`, даже если в нём синтаксическая ошибка (путь module-detection:
CJS-разбор падает на `import`, повторный ESM-разбор в режиме `--check` ошибку
наружу не выносит). Воспроизведено на Node v24.14.1: `import {a} from './x.js'; export function f( {`
→ `node --check` exit 0; тот же текст через
`node --input-type=module --check < file` → `SyntaxError`, exit 1.

Гейт (`.ai-dev/quality/checks/js-syntax.sh`, строка реестра `js-syntax`)
определяет модуль по строке, начинающейся с `import`/`export`, и проверяет его
через `--input-type=module --check < "$f"`; классические скрипты — через
`node --input-type=commonjs --check < "$f"` (закреплённый разбор, а не
детекция: файл с `export` посреди строки или `import.meta`, который эвристика
сочла классическим, падает громко, а не проскакивает). Обход дерева рекурсивный (`static/js/**/*.js`), поэтому будущие
`static/js/mqtt/`, `static/js/flasher/` покрыты с первого файла. Ненулевое
покрытие проверяется (0 файлов = FAIL); non-vacuity закреплена тестом
`scripts/dev/test-js-syntax-gate.sh`.

### П2. `?v=` внутри спецификаторов импорта (иначе стейл после «Обновления веб»)

nginx отдаёт `/static/` с `expires 1h` (`etc/nginx/network_config.conf`).
Сегодня стейл гасится тем, что `index.html` (без кэша) несёт `?v=<версия>` на
каждом `<script src>`, и `scripts/sync-app-version.py` переписывает эти строки
при смене версии. Импортированный модуль (`import x from './mqtt/scan.js'`)
браузер запрашивает **сам**, по спецификатору внутри JS — если там нет `?v=`
или он не обновлён, сразу после «Обновления веб» точка входа (новая) подтянет
модуль из кэша (старый, до часа) — класс дефекта «UI сломан после деплоя,
работает локально» из `web-diagnostic-tools.md`.

Правило: **каждый спецификатор импорта в отдаваемом JS несёт `?v=<версия>`**;
`scripts/sync-app-version.py` патчит их вместе с HTML, а `--check` (строка
`version-consistency`) падает на устаревшем; закреплено тестом
`scripts/dev/test_sync_app_version.py`.

### П3. Расширение остаётся `.js`, не `.mjs`

`mime.types` nginx 1.18 (Debian bullseye) и 1.22 (bookworm) содержат только
`application/javascript js;` — записи `mjs` нет. Файл `.mjs` уйдёт как
`application/octet-stream`, и браузер **откажется выполнить его как модуль**
(строгая проверка MIME для `type="module"`). Добавлять `types {}` в наш vhost —
лишняя точка отказа при обновлении пакета nginx. Итог: модули — `.js`; тип
задаётся `<script type="module">` на точке входа, не расширением.

### Что остаётся как есть

- **`window.*`-шимы на точках входа.** HTML-обработчики (`onclick="doRestart()"`)
  и кросс-бандловые вызовы (`app.js` → `flasher.js` и т. п.) читают глобалы.
  Модуль не создаёт глобалов сам — точка входа модульного кластера явно
  публикует то, что нужно снаружи (`window.doRestart = doRestart`), как это уже
  делает `app/init.js`. Снятие шимов — отдельная работа после того, как все
  потребители сами станут модулями.
- **Порядок загрузки.** `type="module"` = `defer` по умолчанию: модуль исполняется
  после разбора документа и **после** обычных синхронных `<script>`. Классический
  скрипт, который на верхнем уровне обращается к глобалу из модуля, увидит
  `undefined` — при переводе файла в модуль его потребители проверяются на
  верхнеуровневые обращения (или переводятся вместе).

## Форма миграции (для следующих PR, не для этого)

1. **Шаг 0 — «флип» файла**: IIFE-обёртка → модуль (`export` того, что
   импортируют другие; `window.*` для HTML/кросс-бандла), точка входа получает
   `type="module"`; поведение байт-в-байт то же. Оракул — характеризационный
   базовый снимок `scripts/dev/characterize-ui.mjs --compare baseline` — теперь
   on-demand инструмент (строка `headless-smoke` снята в 1.0.6.24, требовала
   живую плату и не могла работать в CI; см. `scripts/dev/README.md`).
2. Далее — **по одному кластеру ответственности за коммит** (`mqtt/scan.js`,
   `mqtt/bridge.js`, …), каждый со своим `?v=` в спецификаторе; после каждого —
   тот же оракул + `js-syntax` + `version-consistency`.
3. Кластеры режутся по ответственности, не по числу строк
   (`.ai-dev/procedures/decompose.md`).
