# Продукт: веб-интерфейс SA-02m

Что это за продукт и для кого — до того, как строить фичи (AI-Dev `## Product discovery`).
Заведён 2026-07-14 в режиме draft-first для legacy-проекта: разделы, помеченные
_(из дерева)_, реконструированы из кода/README/CHANGELOG; ответы наладчика/оператора
получены в диалоге; `[?]` — то, что ещё не подтверждено.

---

## §0 Идея (одна строка)

Веб-конфигуратор и монитор для сервера автоматизации **SA-02m / SA-02m-2** (ЦИНТРОН,
SoM A40i-2eth, Armbian): настройка сети/MQTT/RS-485-шлюза, прошивка RS-485-модулей и
живой мониторинг состояния — из браузера, без входа в консоль устройства. _(из дерева)_

## §1 Для кого

- **Основной пользователь — наладчики / интеграторы** (пусконаладка): при вводе объекта
  настраивают сеть, RS-485, MQTT, прошивают модули MR-02m. _(ответ Оператора)_
- **Вторичный — эксплуатация на объекте:** мониторинг состояния, перезапуск служб на уже
  настроенном устройстве. _(ответ Оператора)_
- **Вторичный — инженеры ЦИНТРОН:** производство, тестирование, поддержка/диагностика.
- Профиль: технически грамотный промышленный пользователь, НЕ обязательно Linux-администратор
  (замена SSH/CLI — прямая ценность, см. §6). Многопользовательских ролей нет — одна учётная
  запись на устройство _(из дерева: `/etc/sa02m_web.env`, единый `session_token`)_.

## §2 Проблема (словами пользователя)

Без веб-интерфейса настройка сети/служб/RS-485 и прошивка модулей — вручную по SSH/CLI:
требует Linux-квалификации, медленно, ошибкоопасно, нет единой точки и живой картины
состояния. _(ответ Оператора: «Замена SSH/CLI», «Единая точка управления»)_

## §3 Путь от нуля к работе _(из дерева)_

Устройство поставляется с предустановленным веб-интерфейсом (`install.sh` — он же путь
обновления). Наладчик подключается по Ethernet к IP по умолчанию (SA-02m `192.168.1.136` /
SA-02m-2 `192.168.0.136`), открывает `http://<ip>:9999` , входит по учётной записи, далее вкладки:
Сведения · Сеть/Время · MQTT · Устройства RS-485 (флашер) · Шлюз RS-485 · Управление.
Вариант железа (1eth/2eth) определяется автоматически. `[?]` как именно наладчик узнаёт
дефолтный IP/пароль (сопроводительная документация? наклейка? — не в дереве).

## §4 Доступ между сессиями и потеря доступа _(из дерева)_

- Сессия — cookie `session_token` (per-session sha256-токен, серверное хранилище
  `/run/sa02m-web-sessions`); истёкшая сессия → страница входа.
- Учётные данные веб-UI: `/etc/sa02m_web.env`; смена — через «Управление» (`web_creds.cgi`).
- **Потеря пароля:** восстановление — через SSH к устройству (правка `sa02m_web.env`) или
  переустановка/переобраз. `[?]` есть ли штатный сброс без SSH (для наладчика без Linux-доступа).

## §5 Кто эксплуатирует и финансирует

- Продукт **ЦИНТРОН**, продаётся как сервер автоматизации (каталог cyntron.ru). _(из дерева/README)_
- Веб-интерфейс — часть поставки устройства (не отдельный SaaS); «финансирование» = ЦИНТРОН как
  производитель, пользователь = покупатель устройства и его наладчик. `[?]` доля self-service
  наладки заказчиком vs пусконаладка силами ЦИНТРОН/партнёров.

## §6 Ценность (что было бы больно без него)

Все подтверждены Оператором:
1. **Замена ручной SSH/CLI-настройки** — снимает требование Linux-квалификации.
2. **Единая точка управления** — сеть + MQTT + RS-485-шлюз + службы в одном месте.
3. **Прошивка модулей MR-02m** — флашер RS-485-модулей без отдельного программатора/СКАДА.
4. **Живой мониторинг** — CPU/темп/сеть/службы/RS-485 без входа в консоль.

## §7 Заключение (adversarial — почему может НЕ взлететь)

> Раунд заключения проведён 2026-07-14 (pre-mortem · persona panel · red-vs-blue).

- **Сильнейшая причина провала / несоответствия.** Продукт спроектирован в модели
  **«доверенная LAN»** (код прямо трактует вход из QUERY_STRING/cookie как «attacker-controlled
  on the LAN», авторизация — одна общая учётка, HTTP без TLS на :9999). Но Оператор подтвердил
  реальный контур **«удалённо через VPN/интернет» и «заводская LAN общего доступа»**. То есть
  устройство с root-способными CGI и флашером живёт в среде, для которой его модель доверия
  может быть недостаточна (нет TLS «из коробки», нет多-факторности, единый пароль, нет журнала
  доступа). Это прямой вход в threat-discovery — и повод спросить, не нужен ли класс защит
  (обязательный TLS/só-VPN-политика, per-user учётки, аудит-лог) как продуктовое требование.
- **Кому продукт НЕ подходит.** Заказчику, которому нужны: многопользовательские роли с
  разграничением прав; аудит «кто что менял»; доступ из недоверенной сети без VPN;
  соответствие требованиям ИБ, требующим TLS и индивидуальных учёток. Сейчас это `[?]` —
  насколько такие требования встречаются у реальных заказчиков.
- **Сигналы «остановиться / пересмотреть».** (1) Инцидент ИБ из-за LAN/интернет-экспозиции;
  (2) наладчики в обход UI всё равно уходят в SSH (значит UI не покрывает их задачи);
  (3) запрос заказчика на多-пользовательский доступ/аудит, который архитектура «одна учётка»
  не закрывает.
