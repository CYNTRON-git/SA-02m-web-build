# USB-микрофон на SA-02m (вход звука для светомузыки LED)

**Что это:** USB-микрофон по классу USB Audio (UAC1/UAC2) — аудиовход для
сценариев подсветки и светомузыки на LED-лентах. Драйвер — штатный
`snd-usb-audio` ядра; без него микрофон виден в `lsusb`, но звуковой карты нет.

**Где собирается драйвер:** `tools/buildroot/prepare-rt-docker-kernel.sh`,
функции `apply_usb_audio_kconfig` / `verify_usb_audio_kconfig` /
`verify_usb_audio_modules` — для обоих ядер линии
(`docs/contracts/kernel-conditional-services.md` §6: SMP и RT). Набор опций и
почему он такой — в комментарии над этими функциями; здесь не повторяется.
Команды `build-kernel` и `build-kernel-smp` падают, если хоть одна опция не
попала в `.config` или если `snd-usb-audio.ko` / `snd-usbmidi-lib.ko` не
пересобраны этим `make linux`. Полная сборка образа (`build`) этих проверок не
выполняет.

**Как модуль загружается на плате:** автоматически через udev по
`modules.alias` при подключении микрофона. Записи в `/etc/modules-load.d/`
нет намеренно: модуль нужен только когда микрофон воткнут, а автозагрузка не
зависит от порта и от порядка загрузки. Индекс `modules.alias` для версии ядра
перестраивает `tools/buildroot/sa02m-kernel-deploy.sh` (`depmod -a <версия>`
сразу после распаковки модулей).

## Стендовый факт (192.168.1.135, 2026-10-15)

- Микрофон Fifine `3142:5060`: UAC1, моно, 16/24 бит, 44,1–192 кГц,
  full-speed USB.
- В работающем RT-ядре `6.1.0-rc6-rt4` ALSA-ядро встроено, а
  `snd-usb-audio` отсутствует.
- С разрешения Оператора проверочно загружен старый стек `snd-usb-audio`
  (сборка 2025-05-28, из `/lib/modules/6.1.0-rc6-rt4.pre-docker-20260623`)
  через `insmod`: карта `1 'Fifine Microphone'`, чистый захват 48 кГц, уровни
  живые. Это **разовая проверка, не решение**: модуль из другой сборки без
  modversions и после перезагрузки не загрузится. Штатный путь — пересборка
  ядра ниже.

## Шаги Оператора (не автоматизированы)

1. На Starterkit VM собрать и упаковать ядра **строго в порядке**
   `tools/buildroot/README.md` «После сборки на VM»: сначала RT
   (`build-kernel`), сразу сохранить его `output/images/zImage` и упаковать
   модули `6.1.0-rc6-rt4` — и только потом SMP (`build-kernel-smp`) и его
   модули `6.1.0-rc6`. SMP-сборка перезаписывает `output/images/zImage`: если
   собрать оба ядра до упаковки, в RT-слот уйдёт SMP-ядро с RT-модулями. В логе
   каждой сборки должна быть строка `USB-audio modules present in …`; без неё
   сборка завершилась ошибкой и деплоить нечего.
2. Задеплоить на 1.135 по тому же разделу README:
   `sa02m-kernel-deploy.sh install-rt …` и `install-smp …` — каждый zImage с
   архивом модулей из **той же** сборки, затем `sa02m-kernel-select.sh init`.
   В логе деплоя — `depmod -a <версия> done`.
3. Перезагрузить плату (снимает и проверочно загруженный старый модуль).
4. Проверить на плате с подключённым микрофоном:
   `cat /proc/asound/cards` — есть карта Fifine; `lsmod | grep snd_usb_audio`
   — модуль загрузился сам; `arecord -l` — устройство захвата видно.
5. Повторить шаг 4 после переключения на второе ядро (SMP↔RT).
