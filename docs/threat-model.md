# SA-02m — Threat Model (веб-интерфейс и службы)

Модель угроз для веб-слоя конфигуратора СА-02м: nginx + fcgiwrap CGI (bash),
демон `sa02m-flasher` (Python, unix-сокет), MQTT-мост, cloud-агент. Обновлять
при добавлении внешних маршрутов (см. §3).

## 1. Модель нарушителя

- **Сетевой нарушитель** в одном сегменте с устройством (промышленная сеть,
  часто без сегментации). Может слать HTTP-запросы на веб-порт (по умолчанию 9999)
  и, при наличии, на 443/TLS.
- **Пассивный перехват** трафика в сегменте (незашифрованный HTTP).
- **Скомпрометированный `www-data`** (например через уязвимость в CGI): цель —
  оценить, что даёт эскалация через sudo.

Вне модели: физический доступ к устройству, компрометация root, атаки на прошивку
модулей по RS-485 (отдельный контур).

## 2. Аутентификация и сессии

- Логин: `POST /cgi-bin/login.cgi`, форма `username`/`password`. Пароль хранится
  **хэшированным** (`SA02M_WEB_PASS_HASH`, sha512crypt) в `/etc/sa02m_web.env`
  (0640 root:www-data). Legacy открытый `SA02M_WEB_PASS` принимается только при
  чтении старых файлов; смена пароля через веб всегда пишет хэш.
- Сессия: при успешном входе выдаётся **случайный per-session токен** (32 байта
  из `/dev/urandom`, hex). Серверное хранилище — `/run/sa02m-web-sessions/`
  (tmpfs); имя файла = `sha256(token)`, содержимое = `<expiry> <user>`. Токен в
  файле не хранится → листинг каталога бесполезен для подделки. TTL скользящий
  (10 дней). Проверка — `lib_web_session.sh` (CGI) и `auth.py::check_session_store`
  (демон, read-only, паритетный sha256).
- Cookie `session_token`: `SameSite=Lax`, без `HttpOnly` (guard в `app.js` читает
  `document.cookie`), флаг `Secure` — только при HTTPS.
- Rate-limit входа: до 8 неудач за 300 с на IP (`/run/sa02m-web-login/`), затем
  отказ; на каждую неудачу — задержка. Недоступность каталога снимает лимит, но
  не отключает проверку пароля (fail-closed на аутентификации).

Ранее (до 1.0.3.38): сессия — общая константа `session_token=cyntron_session`,
одинаковая на всех устройствах и лежавшая в репозитории. Устранено.

## 3. Внешние маршруты (границы доверия)

| Маршрут | Гейт | Примечание |
| --- | --- | --- |
| `/login.html`, `/static/*` | нет (публично) | статика и форма входа |
| `/cgi-bin/status.cgi?part=cpu\|temp\|ram\|disk` | нет (публичные метрики) | только эти part |
| `/cgi-bin/*.cgi` (все прочие) | `web_session_check_cookie` | сессия обязательна |
| `/_auth_check` (internal) | — | `auth_check.cgi` для nginx `auth_request` |
| `/api/flasher/*` | nginx `auth_request` → `auth_check.cgi` + демон `check_session_store` | двойная проверка |

Каждый новый внешний маршрут должен появляться здесь.

## 4. Обработка недоверенного ввода

- **Сетевые параметры** (`apply.cgi`): IP/маска/шлюз/DNS проходят строгую
  валидацию IPv4 на границе перед записью в root-owned
  `/etc/network/interfaces.d/*` (`printf`, не `echo -e`) — исключает инъекцию
  строк конфигурации, в т.ч. через `%0A`. При невалидном вводе — `error_net`
  (fail-closed, без частичной записи).
- **ID служб / профили / каналы** (`services_ctrl`, `kernel_ctrl`, `hw_set`):
  allowlist по `case`.
- **JSON тела** парсятся `python3`, не `eval`.

## 5. sudo (least privilege)

- `sudoers.d/sa02m-flasher`: только `systemctl` и `fuser` (координация RS-485).
- `sudoers.d/sa02m-mqtt`: конкретные `systemctl … mosquitto|sa02m-modbus-mqtt|…`
  и **фиксированные** пути helper-скриптов **без wildcard-аргументов**. Ранее
  `sa02m-mqtt-config-apply.sh *` позволял `www-data` скопировать произвольный
  root-файл в 0660-yaml (эскалация чтения) — устранено: скрипт читает
  фиксированный staging `/tmp/sa02m-mqtt.yaml.new` (symlink отвергается),
  scanner — `/tmp/sa02m-mqtt-scan.json`.

## 6. Транспорт

- HTTP на порту 9999 сохранён (совместимость, изолированные сети).
- HTTPS (`listen 443 ssl`) добавляется установщиком при наличии самоподписанного
  сертификата (`/etc/ssl/sa02m/`), с HSTS. Аддитивно: проблема с сертификатом не
  мешает старту nginx (HTTP остаётся). Рекомендация: доступ по HTTPS, HTTP
  ограничить сегментированием сети.

## 7. Cloud-агент

- Команды из облака (`reboot`, `restart_*`, `get_log`, `ping`) аутентифицируются
  bearer-токеном устройства. `get_log` ограничен `realpath` под `/var/log/`
  (защита от `../`).

## 8. Развёртывание (важно)

Схема авторизации в 1.0.3.38 изменена согласованно в CGI **и** демоне. Полная
установка — `install.sh` (создаёт `/run`-каталоги через tmpfiles, кладёт
сертификат, синхронизирует демон). Веб-обновление
(`sa02m-web-update-apply.sh`) также создаёт runtime-каталоги и **пересобирает и
перезапускает демон**, чтобы CGI и демон не разошлись по схеме сессий.
