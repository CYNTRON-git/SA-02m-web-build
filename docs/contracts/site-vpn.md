# Объектовый VPN для отдельного приложения

СА-02м может запускать выбранное приложение с собственной таблицей маршрутизации и DNS объекта. Оператор выбирает объект, его туннель, удалённую сторону, адреса, защищаемые сети и приложение. Обычные клиенты OpenVPN, WireGuard, wg-quick и плагин NetworkManager сохраняют свои точки входа и настройки. Изоляция распространяется на процессы приложения, которые systemd запустил через `sa02m-site-vpn-workload@ОБЪЕКТ.service`. Она требует поддержки TUN или WireGuard в работающем ядре. На доноре с 6.1.0-rc6 наличие этих драйверов необходимо подтвердить отдельно.

## Подключение объекта

Имя объекта содержит от 1 до 31 строчной латинской буквы, цифры, дефиса или подчёркивания и начинается с буквы либо цифры. Каталог `/etc/sa02m/site-vpn/<объект>/` и файлы конфигурации принадлежат root. Для каталога используйте 0700, для файлов 0600. Установка программ и шаблонов служб выполняется на сетевом шаге. Запуск и автозагрузка каждого объекта включаются отдельно.

Для WireGuard поместите в каталог `wireguard.conf` в формате штатного `wg setconf`, включая ключи, Endpoint и AllowedIPs для каждого пира. Локальные адреса и маршруты приложения указывайте в `profile.json`. Пример для одного объекта с двумя сетями:

```json
{
  "backend": "wireguard",
  "addresses": ["10.40.1.2/32", "fd40:1::2/128"],
  "routes": ["10.40.0.0/16", "fd40::/48"]
}
```

Для OpenVPN используйте клиент TLS с выделенным TUN и топологией subnet. Положите в каталог `ca.pem`, `client.pem`, `client.key`. При необходимости добавьте `tls-crypt.key` и включите `tls_crypt`, либо `auth.txt` и включите `auth_file`. Проверка сертификата сверяет роль сервера и точное имя своего пира. Поддерживаются `udp4`, `udp6`, `tcp4-client` и `tcp6-client`. Укажите числовой IP пира и соответствующее семейство транспорта. Локальные адреса выдаёт сервер. Объект определяет маршруты для этих семейств в своём файле. Пример:

```json
{
  "backend": "openvpn",
  "remote": "192.0.2.10",
  "port": 1194,
  "proto": "udp4",
  "server_name": "vpn.example",
  "routes": ["10.40.0.0/16"],
  "tls_crypt": true
}
```

Разместите исполняемый файл `run`, `resolv.conf` с адресами DNS объекта и `nsswitch.conf` с `hosts: files dns` в `/etc/sa02m/site-vpn-apps/<объект>/`. Каталог, код и файлы принадлежат root и доступны приложению для чтения. Для каталога и `run` подходят права 0755, для конфигурации 0644. DNS должен входить в маршруты объекта и в AllowedIPs для WireGuard. Для приложений с дополнительными системными справочниками сохраните их секции в `nsswitch.conf`.

Запустите приложение через `systemctl start sa02m-site@<объект>.target`. После успешной проверки связь можно включить при загрузке через `systemctl enable sa02m-site@<объект>.target`. Журнал TLS и запуска приложения доступен через `journalctl -u sa02m-site-vpn@<объект>.service -u sa02m-site-vpn-workload@<объект>.service`. Команда `systemctl stop sa02m-site@<объект>.target` останавливает приложение и VPN. Пока target активен, systemd восстанавливает обе его службы после падения. Для управления объектом используйте target; внутренние службы служат для диагностики.

## Данные и маршруты

Процесс запускается с отдельным динамическим UID, без сетевых capabilities, с доступом к IPv4 и IPv6. Приложению доступна петля и туннель. Внешний UDP WireGuard остаётся в пространстве, где создан интерфейс. Внешний TCP/UDP OpenVPN держит клиент в сети хоста. После аутентификации его TUN передаётся в пространство приложения. На стороне приложения доступ к IP-сетям прекращается при исчезновении туннеля. Серверные настройки маршрутов и DNS OpenVPN не меняют исходящее соединение объекта. Остальная система продолжает применять маршруты DHCP 121, статические маршруты, DNS и обычную политику переключения каналов.

Эта конфигурация рассчитана на непривилегированное IP-приложение с отдельным процессом. Служба ограничивает создание сетевых сокетов семействами AF_INET и AF_INET6, запускает процесс с native ABI и блокирует системные вызовы io_uring. Приложение подключается напрямую к DNS объекта. Сокеты, переданные при запуске, и локальные пары socketpair имеют отдельную семантику. Шаблон не использует socket activation; объектовые расширения с передаваемыми файловыми дескрипторами требуют самостоятельной проверки. Для служб, которым нужен системный D-Bus, доступ к Unix-сокетам хоста, сеть основного процесса, другой набор capabilities или внешний прокси, требуется отдельная проверка интеграции. Развёртывание произвольных объектовых конфигураций штатными VPN-клиентами сохраняет самостоятельную область проверки.

## Приёмка

В одноразовой Linux-системе с настоящим PID1 systemd, TUN, WireGuard, OpenVPN 2.6, wg, iproute2 и OpenSSL установите шаблоны и помощник. В пространстве контейнера в начале должен присутствовать только lo. Из копии проекта выполните `SA02M_DISPOSABLE_SITE_VPN=1 python3 scripts/dev/test-site-vpn-systemd.py` от root. Тест использует два локальных пира и временный центр сертификации. Проверяются DNS A/AAAA, двусторонние IPv4 и IPv6, остановка приложения при потере VPN и повторный запуск обоих backend. Этот тест предназначен для одноразовой системы. Аппаратная приёмка требует проверки возможностей конкретного ядра, работы целевого приложения и штатных маршрутов объекта.
