# Соответствие ответа Modbus запросу моста

Мост принимает обычный Modbus-ответ только после проверки его соответствия
отправленному запросу. Это подтверждение протокольного обмена; оно само по себе
не доказывает положение контактов или напряжение на выходе.

Общая проверка находится в `bridge_serial.validate_modbus_reply` и вызывается
из настоящих `_transact` всех трёх транспортов: UART RTU, RTU-over-TCP и Modbus
TCP. Вход проверки — исходный RTU-запрос и ответ `unit + PDU` без CRC.
RTU-транспорты предварительно проверяют настоящий CRC принятого кадра;
TCP проверяет MBAP и не добавляет синтетический CRC.

| Ответ | Условие принятия |
|---|---|
| Любой | Адрес и код функции соответствуют запросу |
| FC01/02 | Число байтов равно `ceil(requested_bits / 8)`, длина соответствует этому числу |
| FC03/04 | Число байтов равно `2 * requested_registers`, длина соответствует этому числу |
| FC05/06 | Ровно шесть байтов `unit + function + address + value`, полностью совпадающих с запросом |
| FC16 | Ровно шесть байтов `unit + function + start + count`, полностью совпадающих с началом запроса |
| FC17 (`0x11`) | Объявленное число байтов совпадает с длиной; переменная длина Carel сохраняется |
| Исключение | Только `request_function | 0x80` и ровно один байт кода; наружу передаётся ошибка с принятым кодом |

Полное соответствующее исключение распознаётся до проверки минимальной длины
обычного успешного ответа. Оно остаётся ответом устройства: TCP-соединение
сохраняется, но значение или успешная запись вызывающему коду не возвращаются.
Ошибочный или чужой ответ не сбрасывает счётчики восстановления соединения и
молчания unit; сетевой поток закрывается по существующему пути рассинхронизации.
Новая повторная отправка запроса не добавляется. Жизненный цикл TCP и существующие
повторы описаны в [контракте транспорта](bridge-modbus-tcp.md).

Чтение и разбиение кадров, очистка входного буфера, последовательный доступ к
линии, приоритет записи, таймауты и отдельный Fast Modbus путь сохраняются.
Опциональный FC17 по-прежнему возвращает пустую идентификацию при ошибке.

Есть ограничения самого протокола. Ответ RTU на чтение не содержит адрес
запрошенного регистра или номера транзакции: задержанный ответ того же адреса,
функции и размера может быть неотличим от нового. Локальное эхо FC05/06 также
может быть побайтно неотличимо от подтверждения ведомого. Эта проверка не
обещает различать такие кадры и не заменяет проверку фактического состояния.

Регрессия: `opt/sa02m-modbus-mqtt/tests/test_modbus_reply_correlation.py` проходит
через реальные транзакции и приёмник UART с подставной границей порта, а также
через локальные TCP-серверы. Она проверяет матрицу функций, неверные адреса,
функции, параметры записи, размеры данных, CRC и исключения, фрагментацию,
отсутствие повторной отправки и преждевременного признака восстановления.
Тесты транспорта/Carel сохраняют проверки обычного обмена. Это программные
проверки без оборудования и без подтверждения электрического состояния.
