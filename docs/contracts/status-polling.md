# Опрос и достоверность статусов

## Транспорт и очередь

Dashboard выполняет один запрос одновременно и хранит не более одной ожидающей заявки на часть. Готовый priority проходит перед фоновыми заявками; после него обслуживается старейшая готовая фоновая заявка. Выполняющийся запрос не вытесняется. Тайм-аут считается с начала запроса до окончания чтения и разбора тела, время ожидания очереди его не увеличивает.

Смена поколения отменяет запросы. Ответы и завершения старого поколения не изменяют отображение, busy-флаги и слот нового поколения. Успех одной части не скрывает ошибку другой. После пяти отказов приостанавливается только соответствующая часть на 25 секунд.

Общий fetch guard проверяет `error: unauthorized` при чтении JSON, включая HTTP 200. HTTP 401 проверяется через auth_check с тем же AbortSignal. Подтверждённая потеря сессии вызывает единственное перенаправление на вход; сетевой отказ сам по себе этого не делает. Авторизационный отказ не повторяет POST. Существующее однократное повторение явно отклонённого E_CSRF сохраняет контракт selective-csrf-policy.

Cloud, HomeKit, HomeConnect и Audio допускают один GET одновременно. Выход со вкладки отменяет запрос и таймеры; завершение отменённого запроса не освобождает слот нового. Ограничение времени действует на всё тело ответа.

## Метаданные источника

`status.cgi` добавляет к JSON `_status_meta: {measured_at, age_s, ttl_s}`. Время в секундах Unix; `age_s` — неотрицательное число либо null, если возраст неизвестен. Для кэша время привязано к сохранённому inode; повторная выдача и откат к старому файлу после неудачной сборки не обновляют время. Отключённый аппаратный опрос имеет неизвестный возраст внутренних показаний.

Клиент прибавляет время после получения ответа к `age_s`. Старый backend без метаданных и отрицательный возраст означают неизвестный возраст. При восстановлении sessionStorage учитывается время хранения. Порог устаревания задаётся на часть и выводится из таблиц планировщика в `app/status.js` (одно место), а не из константы: `ttl_s` из того же ответа + собственный период опроса части + верхняя граница ожидания в очереди одного запроса + её тайм-аут запроса. Граница ожидания — гарантия самой очереди: по одному слоту на каждую поставленную часть, слот не длиннее её тайм-аута с зазором; фоновые части ждут в порядке очереди с priority между любыми двумя слотами, сам priority — не более запроса в полёте и одного фонового слота. Порог короче этой границы помечал бы исправные части как устаревшие на каждом цикле: с одним запросом в полёте фактический цикл фоновых частей на A40i составляет 23–30 с при таймерах 6/12 с (стенд 136, 21.10.2026). Часть, ни разу не полученная за загрузку страницы, не входит в сообщение. Устаревание наступает только по истечении порога и снимается только успешным ответом; сообщение перерисовывается только при изменении текста. Пороги описывают предупреждение о молчании, а не SLA скорости: отказ и тайм-аут запроса сообщаются сразу как «Ошибка обновления».

Тайм-аут запроса задан на часть в той же таблице и включает чтение тела: `services` и `main` — 20 с (холодная сборка `services` на A40i ≈ 9 с, `main` ≈ 14 с), быстрые части — 3–10 с, разовый `services&fast=1` при загрузке — 8 с. Постоянное сообщение dashboard перечисляет проблемные части по названиям виджетов с одной из трёх категорий — «Ошибка обновления», «Данные устарели», «Возраст данных неизвестен»; текст ошибки и число секунд в нём не показываются.

## Службы и порты

Состояние процесса и политика автозапуска независимы: active при disabled остаётся работающей службой с кнопкой остановки. Activating, deactivating, failed, inactive, unknown и paused имеют отдельные подписи; запуск не обозначается зелёным активным состоянием. Цвета прежние: active — зелёный, activating/deactivating/paused — нейтральный, остальные (inactive, failed, disabled, masked) — красный. Подпись «Автозапуск включён/выключен» строится из `enabled` (JSON boolean в ответе `sa02m-web-service-ctl.sh list`) и `user_disabled`.

Ответ services добавляет `port_coordinator` из `/run/sa02m-port-coordinator/status.json`: timestamp, configured_scopes, leases, services и available. Снимок перечитывается при выдаче даже кэшированных служб — без интерпретатора: CGI проверяет фиксированную раскладку снимка (`snapshot_document` в `sa02m_ports/broker.py`), и снимок с иной раскладкой или лишним ключом не проецируется (`available:false`, `error:snapshot_unavailable`). available проверяет читаемый снимок, совпадение broker_pid/broker_start_ticks с /proc и наличие Unix-сокета. Это проверка существования процесса, а не готовности RPC; timestamp изменяется при переходах и не служит TTL. При недоступности сохраняются сведения о незавершённых операциях с явным предупреждением.

Отказ JSON `error: unauthorized` в теле HTTP 200 ведёт к выходу только после подтверждения `auth_check.cgi` (401); при HTTP 401 действует проверка статуса fetch guard. Временная ошибка backend с таким телом сессию не завершает.

Dashboard отображает порт, назначение операции, фазу, целиком затронутые службы и ошибки восстановления. Запись restore_failed не обозначается успешным восстановлением; старый активный badge затронутой службы заменяется состоянием координатора. Остальные поля services, включая svc_vplc_ui, сохраняются.

## Проверки

`test-status-reliability.mjs` проверяет реальные незавершённые HTTP-тела, поколения, очередность, возраст и состояния служб. `status-reliability-browser.mjs` проверяет тот же путь в Chromium, карточки, локали и перенаправление. `test-status-cache-metadata.sh` проверяет возраст повторно выдаваемого и резервного кэша. Аппаратные измерения выполняются отдельно координатором; модельные ответы не доказывают исправность физического обмена.
