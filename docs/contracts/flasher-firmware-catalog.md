# Метаданные локальной прошивки

Локальный каталог восстанавливает семейство, тип и версию из полного имени известного релиза, когда заголовок `.fw` не определяет семейство. Правило действует при загрузке файла и обнаружении файлов в кеше.

| Полное имя без учёта регистра | Семейство | Тип |
|---|---|---|
| `MR-02m_X.Y.Z.W.fw` | `MR-02m` | `app` |
| `RTU-Sensor_X.Y.Z.W.fw` | `RTU-Sensor` | `app` |
| `CE-02m-3_X.Y.Z.W.fw` | `CE-02m-3` | `app` |
| Те же имена с `_bootloader_` вместо первого `_` | То же семейство | `bootloader` |

Допускается также расширение `.bin`. Каждый из четырёх компонентов версии состоит из цифр ASCII. Пути, дополнительные префиксы и суффиксы не соответствуют этому правилу. Для остальных имён сохраняются прежние правила, включая короткие версии MR/CE, псевдонимы MR и общие имена `bootloader.fw` / `*_bootloader.fw`.

Приоритет источников:

1. Явные метаданные манифеста сохраняются; локальный файл не создаёт конкурирующую запись. Если поле `kind` отсутствует либо не поддерживается, применяется существующий разбор имени.
2. Для локальной записи распознанная сигнатура заголовка `.fw` определяет семейство даже при противоречии с именем.
3. Если сигнатура не определяет семейство, используется известное полное имя. Для заголовка `EN_METER` / `ENMETER` без такого имени и для неопознанного BIN семейство остаётся неопределённым. У старого локального `.fw` резервная метка `MR-02m` служит только для отображения в каталоге.

Для приложений используются маркеры `MR02M_VER:`, `DTV_VER:`, `LED_VER:` и `CE02M3_VER:` с четырьмя компонентами версии. Поиск охватывает весь декодированный образ. У `.fw` заголовок и заполнение последнего блока находятся за границами полезной нагрузки. Если маркера нет, имя релиза может дать отображаемую версию, в том числе `RGBW_WS2812_X.Y.Z.W.bin` для ленты.

Для записи любого BIN без маркера нужен манифест с явно заданным нативным семейством и SHA-256 выбранного файла. Одного точного имени для такой операции недостаточно. Старый контейнер `.fw` с нейтральной сигнатурой допускается по известному имени релиза. Образ без подтверждения семейства остаётся в хранилище. Веб-интерфейс исключает его при выборе нативной цели. Поле `flash_error` содержит причину отказа. Демон сверяет сведения по фактическим байтам перед получением порта в одиночной и пакетной задаче. Сигнатуры LED и WB исключают запись в МР, СЭ и ДТВ. Противоречие известных семейства, версии или типа в заголовке, маркере, имени и выбранной записи прекращает операцию.

Перед командой модулю проверяется таблица векторов ARM. У приложения обработчик сброса должен указывать за первые два векторных слова на целую 16- или 32-битную инструкцию Thumb в переданных байтах. Начальное полуслово `0xFFFF` означает стёртую память. У загрузчика обработчик находится в передаваемом коде от `0x08038000`. Для контейнера проверяются заявленный размер, порядок байтов и CRC32 при наличии `CRC2`. Для загрузчика поддерживаются упакованный `.fw`, прежний сырой `.fw` размером 34 КиБ и извлечение областей векторов и кода из поддерживаемого полного BIN. Адресная и серийная запись передают одни и те же байты во Flash.

При замене загруженного файла демон проверяет временную копию под именем релиза. Конфликт нового образа с семейством релиза, непригодный обработчик сброса или ошибка записи сохраняют ранее пригодный файл и его метаданные, в том числе после перезапуска. Читатель кеша видит целую старую или новую версию. Для имени из манифеста сохраняются канал и ограничения записи манифеста.

После пригодной загрузки под полным именем релиза из таблицы демон может удалить старую локальную копию с добавочным номером от `.2` перед расширением. Для этого требуется побайтовое совпадение с загруженным файлом. Имена из любого канала манифеста защищены. Загрузка под коротким или свободным именем сохраняет соседние файлы, включая другие версии релиза.

Обычный перезапуск процесса заново классифицирует уже существующие локальные файлы. Для этого не нужны сеть, перезапись `.index.json`, переименование или изменение байтов образа. Записи уже работающего процесса автоматически не переклассифицируются.

Имя даёт метаданные, но не доказывает подлинность или пригодность образа к записи. Проверки содержимого, хеша, допустимого формата и маршрута устройства сохраняются. Регрессии: `test_firmware_catalog_metadata.py` проверяет приоритеты и цикл загрузки/перезапуска; `test_firmware_catalog_dispatch.py` соединяет настоящий Linux runner с каталогом и записывающими заглушками оборудования. Эти проверки не подтверждают физическую запись прошивки на модуль.

Для выбора цели прошивки нужен опознанный прибор. Сигнатура HR290 `CE02M3` подтверждает автономный СЭ-02м-3 как при старом IR0=14, так и при IR0=100. Одно имя драйвера `EN_METER` / `ENMETER`, тип 14 или предположение по диапазону серийных номеров не определяют семейство образа. В этих случаях веб-интерфейс не предлагает образ, а одиночная и пакетная запись требуют повторного опознания.

Для МР, ДТВ и СЭ полное поле `device` должно однозначно определять семейство. Допускаются известные обозначения вариантов, например `MR-02m DI16`. Смешанное обозначение `MR-02m SENSOR` и противоречащая семейству сигнатура в списке манифеста исключают файл из выбора нативной цели. В одиночной и пакетной задаче демон сверяет это семейство с образом и выбранным прибором, затем проверяет фактическую сигнатуру загрузчика и выбранный SN по используемому транспорту. Если загрузчик вернул пустое или неоднозначное имя, семейство может подтвердить только прочитанная в той же операции сигнатура приложения с тем же действительным SN. Маршрут сторонних устройств WB использует формат `.wbfw`.
