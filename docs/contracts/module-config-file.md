# Файлы конфигурации MR-02м

Файл содержит прочитанные настройки одного совместимого модуля. Живые
состояния DO/AO, счётчики, команды сброса, адрес и параметры RS-485 в него не
входят. Чтение после записи подтверждает текущее значение; сохранение после
отключения питания этим не проверяется.

## Формат и совместимость

Формат `sa02m-mr-config`, целочисленный `schema_version: 1`. Объект `module`
содержит `type_code`, `io_counts` (`do`, `di`, `ao`, `ai`) и описательную
`app_version`. `settings` содержит именованные настройки, а не адреса регистров:

- `do.channels`: `channel`, `safe`, `timer_function`, `timer_deciseconds`,
  `minimum_off_s`; таймеры и минимальное отключение есть у первых шести DO.
- `di.channels`: `channel`, `mode`, `debounce_ms`, `long_press_ms`,
  `double_click_ms`.
- `ao.channels`: `channel`, `safe_raw` в шкале 0..1000.
- `ai.channels`: `channel`, `sensor_code`, `calibration`, `limit_low`,
  `limit_high`, при наличии поддержки `filters` (`kalman`, `sps`, `average`,
  `tau_ms`). Отображение и профиль описаны в [контракте AI](module-config-ai.md).
- `watchdog.inactivity_s` для модулей с выходами; применимые `relay`-настройки
  определены в [контракте реле](module-config-relay.md).

Номера каналов начинаются с 1, уникальны и ограничены фактическим профилем.
`coverage.included`, `coverage.unavailable`, `coverage.unsupported` перечисляют
именованные пути. Это отчёт, не полномочие записи: сервер заново определяет
тип, прошивку, допустимость полей и фактические значения. Разрешена замена
одного модуля другим того же типа с другим серийным номером. Противоречащие
друг другу свежие тип и сигнатура либо неподдерживаемый профиль дают отказ.

Экспорт включает только полностью прочитанные значения допустимого диапазона.
Неизвестное значение не заменяется нулём. Для неполного экспорта окно показывает
предупреждение перед сохранением. Указанная в файле версия не открывает функции,
недоступные на фактически прочитанной прошивке устройства.

Старый формат `_meta` + `mr` принимается с явным отчётом о неполноте. Массив
`safe_holding_regs` содержит адреса и никогда не используется как значения AO.
Пустые массивы не означают нулевые настройки. Старый нулевой блок реле у
неприменимого профиля и входной watchdog отмечаются как неприменимые;
ненулевые неприменимые настройки отклоняются. Старый `freq_mode` не применяется:
в актуальной прошивке запись 750+ является совместимым no-op, а частота читается
как телеметрия 759+. Редактируемого режима частоты в окне нет.

## HTTP и выполнение

Авторизованные POST `/device_config/export` и `/device_config/import` используют
общую с остальными маршрутами проверку сессии и CSRF. Оболочка запроса содержит
`port`, `device`; импорт дополнительно содержит `configuration`, строгие boolean
`preview_only` (по умолчанию true) и `allow_partial` (по умолчанию false).
Неизвестные ключи, повторяющиеся JSON-ключи, нечисловые/бесконечные значения,
boolean вместо integer, несовместимый тип и недопустимый последний элемент
отклоняются до первой записи. Неполный файл требует отдельного подтверждения.

Экспорт возвращает `ok`, `complete`, `configuration`. Импорт возвращает `ok`,
`complete`, `preview_only`, `module`, `changes`, `applied`, `unchanged`, `failed`,
`remaining`, `unavailable`, `unsupported`, `normalizations`, `warnings`.
Элементы описывают именованный `path` и известные `previous`, `requested`,
`expected`, `observed`. Неопределённый результат поля имеет `status: "unknown"`.
Сбой восстановления владельца порта сохраняется в `restoration_error` вместе
с уже подтверждённым результатом; общий `ok` в этом случае false.

Предварительная проверка не пишет. Применение повторяет проверку под одной
арендой UART, с одним транспортом и блокировкой настроек этого COM. Активная
задача прошивальщика проверяется до блокировки и после её получения.
Подтверждённые неизменившиеся настройки не записываются повторно. Нормализация
safe AO до шага 4 и среднего 0→1 видна в предварительном отчёте.

На прошивке без подтверждения применения типа AI экспорт остаётся доступным.
Он сохраняет наблюдаемый тип, пределы и фильтры и перечисляет ограничения
в `coverage.unsupported`. Для экспорта `complete` означает полноту чтения.
Импорт файла с любым `sensor_code`, пределом или WB-параметром
(`sps`, `average`, `tau_ms`) перечисляет эти пути в `unsupported` и возвращает
`apply_blocked:true`, `complete:false`. Проверка возвращает `ok:true`,
попытка применения — `ok:false` и ноль записей для всего файла. Совпадающий
тип, отсутствие типа в файле с пределами и `allow_partial:true` сохраняют
этот запрет. Неполный файл с независимыми настройками, в том числе калибровкой
и признаком Калмана, можно применить после обычного подтверждения неполноты.

При наличии [подтверждения применения типа AI](module-config-ai.md#подтверждение-применения-типа)
сервер получает исходное завершённое поколение до планирования. Связанные
P/N-типы проверяются до записи. Одна команда парного типа проверяет оба канала.
После завершения команд типа сервер заново читает значения, определяет порядок
записи границ по фактическому диапазону, затем проверяет запрошенные значения
и прежнее поколение. Пара 3-проводного RTD получает одну запись на общий предел
с чтением обеих сторон. Изменение поколения во время проверки оставляет зависимые
поля неподтверждёнными. При потере идентичности модуля или непрерывности времени
работы итоговый отчёт снимает подтверждение со всех настроек этого сеанса.
Потеря ответа на команду типа останавливает последующие
записи до каких-либо пределов или WB-фильтров.

Каждая FC06 выполняется один раз и требует полного корректного чтения результата.
Потерянный ACK, несовпадение, отсутствие чтения или истёкший бюджет останавливают
остаток последовательности. Автоматического повторения записи и обещания отката
нет. Транспорт закрывается до возврата аренды. В режиме вентилятора типа 11
импорт DI-настроек запрещён; автоматического перехода в другой режим нет.

Файл ограничен 48 КиБ, тело HTTP — 64 КиБ, план — 128 различными записями
и 256 обменами. Медленное тело ограничено общим бюджетом 2 с, ожидание
блокировки — 2 с, получение аренды — 45 с, обмен — 20 с, возврат — 45 с.
Внешний запрос окна ограничен 120 с включая чтение тела ответа. Эти бюджеты
ограничивают программные ожидания и не являются гарантией реального времени ОС.
Отказанный запрос закрывается без неограниченного дочитывания тела.

Окно сначала показывает изменения, отсутствующие поля и нормализацию. Только
явная кнопка применения отправляет одну операцию. Настройки могут изменить
автономную работу выходов, что указано рядом с кнопкой. Во время операции
управление заблокировано. После сбоя/таймаута отчёт сохраняется, а повторная
отправка того же предварительного отчёта отключена; доступно явное обновление
состояния и новая проверка файла.

Отчёт показывает название настройки и канал на языке интерфейса; технический
путь остаётся дополнительной диагностикой. Обычные группы настроек окна также
не позволяют сохранять непрочитанные поля: правила достоверности находятся в
[контракте AI](module-config-ai.md). Файловый экспорт читает собственные свежие
значения и не использует числовые заглушки снимка или несохранённый ввод.

## Проверки

`test_mr_configuration.py` проверяет типизированный план всех серийных профилей;
`test_mr_configuration_transport.py` — реальные Modbus-кодеки, порядок,
нормализацию, зависимые настройки и остановку при потере подтверждения;
`test_mr_configuration_http.py` — реальную маршрутизацию, сессию/CSRF,
аренду, блокировки, восстановление и медленное тело.
`scripts/dev/test-mr-configuration-file.mjs` проверяет реальные кнопки,
файлы, запросы и ответы в Chromium, русский/английский интерфейс и обе темы.
