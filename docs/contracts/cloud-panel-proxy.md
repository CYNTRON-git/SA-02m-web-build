# Контракт: панель устройства за обратным прокси («облачный путь»)

Что веб-панель СА-02м требует от **любого** reverse proxy, через который её
открывают, и что она сама гарантирует прокси. Сегодня такой прокси один —
`cloud.cyntron.ru`: браузер → `https://cloud.cyntron.ru/devcfg/<id>/…` →
`device_proxy` (`backend/server.py` в репозитории `CYNTRON-git/cloud`) →
туннель frpc → nginx платы. Дом шва **со стороны устройства**; облачная
сторона — их `device_proxy` и их проверка (cloud commit: `<to be filled after
the cloud merge>` — **TODO (backlog, 2026-09-23, round 2):** заменить на
squash-коммит их `main`, как только облачный PR влит; до этого каждый факт
«relayed» ниже подтверждён только словами облачной команды). Sibling для API
устройства — `cloud-enrollment.md`.
Машинная грамматика (заголовки, пути, коды) — латиницей (`PROTOCOL.md`
invariant 5); пояснения — по `docLanguage: ru`.

Зачем: 2026-09-23 «Применить» и «Проверить» через облако заканчивались
страницей входа — прокси пересылал cookie, но срезал заголовок
`X-SA02M-CSRF`, а панель читала отказ `E_CSRF` как потерю сессии
(`docs/bugs/BUGLOG.md` 2026-09-23). Факты о прокси до этого жили только в
прозе CHANGELOG 1.0.5.43 и комментарии `app.js`; здесь они становятся
проверяемыми.

## 1. Что панель требует от прокси

| Требование | Зачем | Как проверяется |
|---|---|---|
| **Заголовки запроса: пропускать семейство `X-SA02M-`** (сравнение имени без учёта регистра) рядом с четырьмя именованными (`Content-Type`, `Accept`, `User-Agent`, `X-Requested-With`); всё остальное прокси вправе срезать | `X-SA02M-CSRF` — единственный транспорт CSRF-токена (`docs/decisions/selective-csrf-policy.md`): без него любая мутация — `E_CSRF reason:no_header` | По словам облачной команды (relayed, здесь не проверяемо): их проверка пинит три вещи — `X-SA02M-CSRF` приходит дословно, второй заголовок семейства приходит, заголовок вне семейства — нет; при **дублированном** заголовке семейства прокси пересылает **первое** значение, а дубликаты, различающиеся только регистром имени, доходят до платы **одной строкой на каждое написание, все с первым значением**. У нас: сегодня панель шлёт **ровно один** свой заголовок — `X-SA02M-CSRF` (`grep -rn "X-SA02M-" www/network_config/static/js` → `withCsrfHeaders` в `app.js` и два XHR-сайта в `app/status.js`); новый заголовок семейства облачных изменений не требует. Семейство содержит и **доверительный** заголовок — `X-SA02M-Auth`, секрет `INTERNAL_TOKEN` демона flasher (`opt/sa02m-flasher`): nginx платы перезаписывает клиентское значение пустым на обеих flasher-локациях (`etc/nginx/network_config.conf`, гейт `flasher-auth-header-strip`), поэтому пересылка всего префикса облаком **ничего не стоит** — до демона он не доходит. Оговорка: срез действует на плате после полной установки (`install.sh` / `scripts/03-webserver.sh`), офлайн-пакета (`scripts/offline-update-deploy-map.json` → `/etc/nginx/sites-available/network_config`) или образа; **GitHub-OTA через «Обновление веб» конфигурацию nginx не несёт** (`map_dst` раннера без ветки `etc/nginx/`), и на плате, обновлённой только так, заголовок по-прежнему доходит до демона — инертно, пока `INTERNAL_TOKEN` пуст |
| **Cookie: каждый `Set-Cookie` пересылается** (на логине их два: `session_token`, `sa02m_csrf`) с переписанным `Path` → `/devcfg/<id>`; заголовок `Cookie` пересылается целиком | сессия и зеркальный токен живут в браузере; панель чистит cookie на каждом префиксе пути (`clearSessionCookie`, `app.js`), потому что не знает свой `<id>` | подтверждено облаком (relayed); на плате — `js-unit` (`scripts/dev/test-clear-session-cookie.mjs`: «cloud path: clears Path=/devcfg/sa02m-abc») |
| **Заголовки ответа проходят как есть** (кроме `Content-Length`/`Transfer-Encoding`/`Connection`; `Location` и `Set-Cookie` переписываются); **ответы `/cgi-bin/*` не кэшируются** прокси | `Cache-Control: no-store` с `csrf_token.cgi` обязан дойти до браузера: закэшированный ответ отдал бы токен одной сессии другой; `Content-Type` не переписывается (`nosniff`) | облако: заголовки проходят, `proxy_cache` в их nginx нет (relayed, измерено в их коде); у нас `cgi-csrf-behaviour` 11b проверяет, что плата их шлёт |
| **Без переписывания HTML**, `<meta viewport>` панели не трогается, `<iframe>` нет — браузер открывает панель напрямую по `/devcfg/<id>/` | вёрстка ≤560 px и `data-hide-for` — панели; чужая обёртка ломает медиазапросы | облако: подтверждено (relayed); на плате — `ui-layout` (h)/(i) при 360 px, проверка V-B2 с телефона |
| **Транспорт ошибок CGI — HTTP 200 + тело** не превращать в статус-коды | панель различает `ok:false`/`error_code` по телу (`web-code-rigor.md`, идиома слоя) | `cgi-csrf-behaviour`, `web-update-apply-guard` (тела) |
| **Относительные пути — обязанность панели, а не прокси.** Referer-based 307 (`backend/server.py:4629-4641`): корневой запрос `/cgi-bin/…`, `/static/…`, `/api/…` прокси перенаправляет на `/devcfg/<id>/…` только по `Referer` — это **fallback для старых закэшированных бандлов, панель на него не полагается**; префиксный bounce по `cloud_session` на их стороне, по словам облачной команды (relayed, не проверено здесь), нереализуем — корневой запрос не называет плату, только Referer несёт `/devcfg/<id>/` | запрос без `Referer` (настройка приватности, префетч) — 404 | у нас `no-absolute-api-paths` (ниже) |

## 2. Что панель гарантирует прокси

| Гарантия | Дом | Гейт |
|---|---|---|
| Все ресурсы и вызовы — **относительными путями** (`static/…`, `cgi-bin/…`, `api/…`, `VERSION`): `index.html`/`login.html`/`cloud.html` без абсолютных `/static`, `/cgi-bin`; `main.css` без `url()`; с 1.0.6.53 и `devices.js` (`api/devices…`, последние восемь абсолютных сайтов — F-B3). Через `/devcfg/<id>/` всё резолвится в маршрут платы **без** 307 | `app.js` (комментарий у `clearSessionCookie`), CHANGELOG 1.0.5.43 | `no-absolute-api-paths` (свип по всем бандлам, comment-stripped; floor — ≥4 относительных сайта в `devices.js`) |
| Отказ `E_CSRF` **называет причину** (`reason`), и панель на `no_header` **не разлогинивает**: сообщает о транзите, сессию сохраняет | `docs/decisions/selective-csrf-policy.md` «Реакция панели» | `web-auth-behaviour` 30a–f, `app-csrf-recovery` |
| Токен восстанавливается тем же origin: `GET cgi-bin/csrf_token.cgi` (только живая сессия, `no-store`, `nosniff`) | там же, «Механика токена» | `cgi-csrf-behaviour` 11–14 |
| Один свой заголовок запроса — `X-SA02M-CSRF`; `X-Requested-With` там, где он уже был | этот файл, §1 первая строка | `grep` из §1 (гейта нет — заметка) |
| **Ровно одна** строка `X-SA02M-CSRF` на запрос: `withCsrfHeaders` (`app.js`) кладёт один ключ в plain-объект заголовков, оба XHR-сайта (`app/status.js`) вызывают `setRequestHeader` по одному разу — дублей, на которых облако пересылает «первое значение», панель не создаёт. Приёмная сторона: CGI читает `HTTP_X_SA02M_CSRF` (CGI-соглашение складывает любое написание имени в одну переменную) и `web_csrf_validate` (`lib_web_auth.sh`) сравнивает **значение целиком** солёными sha256 — склеенный дубль вида `tok, tok` даёт `mismatch`, одинаковые значения под разными написаниями дают тот же токен, какая бы строка ни победила; какую именно строку оставляет nginx→fcgiwrap при двух написаниях, этот репозиторий не пинит | `app.js`, `app/status.js`, `lib_web_auth.sh` | `web-auth-behaviour` 25 (чужое значение → deny), `app-csrf-recovery` 2 (заголовок повтора — один) |
| Ни один заголовок семейства `X-SA02M-`, пришедший от клиента, не является **доверительным** для платы: `X-SA02M-Auth` (секрет демона flasher) срезается на edge — действует на плате после полной установки / офлайн-пакета / образа; GitHub-OTA конфигурацию nginx не несёт, — `X-SA02M-CSRF` сверяется с файлом сессии | `etc/nginx/network_config.conf` (flasher-локации), `docs/threat-model.md` §4, `docs/deployment.md` «Чего OTA/офлайн-пакет не делает никогда» | `flasher-auth-header-strip` (зелёный в репозитории — не свидетельство о плате, поднятой через OTA), `web-auth-behaviour` |

## 3. Что проверено и что нельзя проверить здесь

- **Здесь, без облака:** гейты из таблиц выше на каждом build-бите; headless-
  прогон вёрстки «Управление» при 360/375/393/414 px × две темы × два варианта
  (одна колонка, ничего не обрезано — `ui-layout` (h)/(i) и прямой прогон
  Playwright, 1.0.6.53).
- **Только с облаком (Оператор, телефон):** V-A3 — до их фикса «Проверить»
  через облако даёт тост «Прокси не пропускает заголовок…» и НЕ разлогинивает;
  после — «Обновлений нет»/«Доступно обновление», «Применить» → прогресс.
  V-B2 — `…/devcfg/<id>/#system`: карточки одна под другой, кнопки на всю
  ширину, обе темы (после bump `&r=`, иначе телефон держит старый `main.css`).
- **Нельзя проверить из этого репозитория:** код облака. Факты о нём выше
  помечены «relayed» — переданы координатором облачной команды; их
  подтверждение — коммит облака в шапке.

## 4. Известные ограничения

- TLS завершается на облаке: оно видит сессию и токен в открытом виде
  (`docs/threat-model.md` §3 «Облако видит UI-трафик»); контракт просит
  **пересылать**, а не **доверять**.
- Пока облако не пересылает `X-SA02M-CSRF`, **ни одна** плата через облако не
  выполнит мутирующего действия — «Применить» в том числе: заголовок до платы
  не доходит, и 1.0.6.53 этого не меняет. Разница между версиями только в
  реакции: ниже 1.0.6.53 панель выбрасывает на страницу входа, 1.0.6.53
  сохраняет сессию и называет причину (тост о прокси). Путь обновления до их
  фикса — LAN/SSH/offline-пакет.
