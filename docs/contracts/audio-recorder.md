# Контракт: запись звука по команде (`sa02m-audio`)

**Гарантия:** по команде авторизованного источника плата записывает **один**
ограниченный по длительности клип с USB-микрофона, кладёт его только на тот
носитель, который выбран в конфиге, в пределах жёстких лимитов, и никуда больше.
Результат — успех или названный отказ — публикуется в MQTT. Retained-команда,
команда при уже идущей записи, команда сверх лимита частоты и команда с
неверной полезной нагрузкой запись не начинают. Каждый старт, конец, отказ и
удаление пишется в журнал событий. Пока модуль выключен, процесс не работает и
ничего не пишет.

Зачем сначала запись, а распознавание потом — `docs/decisions/speech-recognition.md`;
драйвер микрофона и автозагрузка — `docs/usb-audio-microphone.md`.

Машинная грамматика (топики, значения, ключи, пути, коды) — на английском
(`PROTOCOL.md` invariant 5); пояснения — на русском. Код:
`opt/sa02m-audio/sa02m_audio/`; каждое перечисление ниже существует в коде
ровно один раз — в `constants.py`, если у раздела не назван другой модуль, — и
`test_contract_tables.py` сравнивает таблицы этого файла с кодом как множества.

Этот файл покрывает демон: MQTT, носители, хранение, захват, аренду микрофона,
конфиг, статус и журнал. CGI панели, привилегированный хелпер, отправка на URL
и ACL внешнего слушателя получают свои разделы вместе со своим кодом.

---

## 1. Зависимости и границы

- Python stdlib плюс apt `python3-paho-mqtt` (на плате 1.6.1, API 1.x;
  `tests/test_stdlib_only.py`). paho импортирует только `mqttio.py`.
- `arecord` из `alsa-utils` и `timeout` из coreutils — оба уже есть на плате.
- Брокер — только `127.0.0.1:1883` (константы, не конфиг).
- Точки монтирования съёмных носителей — данные `etc/storage-mount.sh`,
  потребляются только на чтение (§5).
- Модуль ничего не меняет в движке сценариев, `storage-mount.sh`,
  `status.cgi` и `mqtt_set.cgi`: `record` в список контролов `mqtt_set.cgi`
  **не** добавлен, поэтому ни панель через этот эндпоинт, ни агентский
  `mqtt.publish` записи не запускают.

## 2. MQTT

Устройство — постоянный id `sa02m-audio` (как `sa02m-bridge`, никогда не имя
платы). Конвенция — `docs/MQTT_TOPICS.md`: всё состояние retained, QoS 1,
субтопики `/meta/<key>` и сводный блоб `/meta`; при каждом (пере)подключении
демон заново публикует всё своё retained-состояние. LWT —
`/devices/sa02m-audio/meta/error = "r"` (retained); в работе — `""`; при
штатной остановке демон сам публикует `"r"`: команды больше никто не принимает.

| Топик | Направление | Содержимое |
|---|---|---|
| `/devices/sa02m-audio/meta`, `/meta/name`, `/meta/driver` | наружу | `{"driver":"sa02m-audio","title":{…}}`; `SA-02m audio recorder`; `sa02m-audio` |
| `/devices/sa02m-audio/meta/error` | наружу | `""` в работе, `"r"` — демона нет |
| `/devices/sa02m-audio/controls/<control>` (+ `/meta`, `/meta/type`, `/meta/readonly`, `/meta/order`, `/meta/units`) | наружу | таблица контролов ниже |
| `/devices/sa02m-audio/controls/record/on` | **внутрь**, без retain | команда записи (грамматика ниже) |
| `/devices/sa02m-audio/controls/delete/on` | **внутрь**, без retain | `<id>` или `all` |

Контролы (`constants.CONTROLS`). Записываемый — только `record` (его `/on` —
команда), остальные `readonly`.

| control | WB type | units | Значение |
|---|---|---|---|
| `record` | `switch` | — | `1` идёт запись, `0` нет |
| `mic` | `text` | — | `present` \| `absent` \| `busy` |
| `medium` | `text` | — | выбранный в конфиге носитель: `emmc` \| `usb` \| `sdcard` |
| `medium_state` | `text` | — | вердикт по выбранному носителю (§5): `ok` \| `absent` \| `readonly` \| `full` |
| `last_file` | `text` | — | id последнего сохранённого клипа (§7) |
| `last_status` | `text` | — | исход последней команды (§3) |
| `last_duration_ms` | `value` | `ms` | длительность последнего клипа |
| `last_size` | `value` | — | размер файла последнего клипа, байт (с заголовком WAV) |
| `last_peak_dbfs` | `value` | — | пиковый уровень последнего клипа, ≤ 0; `-90` — тишина |
| `last_upload` | `text` | — | доставка последнего клипа; пока отправки на URL нет — всегда `off` |
| `count` | `value` | — | число клипов на всех присутствующих носителях |

`last_file`, `last_duration_ms`, `last_size`, `last_peak_dbfs`, `last_upload`
меняются только при сохранённом клипе; `last_status` — при каждом исходе
команды, даже повторяющемся (тот же текст публикуется заново). `last_status`
публикуется **последним** из всего, что меняет исход: к его приходу файл,
событие, `record`, `count`, `last_file` и `status.json` уже окончательные.

Грамматика `record/on` закрыта (`mqttio.parse_record`). Всё, что не в таблице,
— `last_status = bad_command`, ничего не записывается:

| Полезная нагрузка | Действие |
|---|---|
| `1` \| `on` \| `true` (регистр не важен) | запись на `default_duration_s` (§8) |
| целое `2`…`max_duration_s` | запись на столько секунд |
| целое больше `max_duration_s` | **отказ** `bad_command`, без обрезки: просивший 60 с должен узнать, что не получил ничего |
| `0` \| `off` \| `false` \| `stop` | досрочная остановка идущей записи: клип ≥ 1 с сохраняется (`ok`), короче — отбрасывается (`interrupted`); без идущей записи — ничего |
| пустая | игнорируется молча (это возврат собственной очистки retained, §2 ниже) |

`1` — длительность по умолчанию, а не одна секунда: движок сценариев
переводит `True`/`1`/`"on"` в `"1"`, и так же шлёт выключатель в стиле
Алисы/HomeKit (`opt/sa02m-rules/sa02m_rules/service.py`, `RulesApp.pub`).
JSON не принимается: движок отдаёт словарь через `str()` — это repr Python, не
JSON.

`delete/on`: id по грамматике §7 или `all`; поиск — по каталогам всех
присутствующих носителей. Иное — `bad_command`.

Охрана на входе (`mqttio.py`, `service.py`):

- **Retained-команда** (флаг retain у входящего сообщения) не выполняется
  никогда: иначе она перезаписывала бы при каждом старте демона. Предупреждение
  — один раз на топик, событие `mqtt`, и демон очищает её пустой retained
  публикацией.
- **Одна запись за раз**: старт во время записи — `busy`, идущая запись
  продолжается (дубликат QoS 1 попадает сюда же и безвреден).
- **Частота**: не больше `RATE_MAX_STARTS` = 60 начатых записей за скользящий
  час `RATE_WINDOW_S`, в памяти; сверх — `rate_limited`. Считаются только
  реально начатые записи.
- **Очередь**: сетевой поток paho только ставит сообщения в очередь
  `INBOX_MAX` = 64; переполнение отбрасывается и считается в журнале.
- **Доверие на 1883** (loopback, анонимно): записать может любой локальный
  процесс — тот же круг доверия, что уже переключает релейные выходы (движок
  сценариев, Node-RED, MPLC4/CODESYS, контейнеры с host-сетью). Источник
  команды по MQTT не устанавливается; в событиях он `mqtt`.

Порядок проверок старта (первый отказ выигрывает): грамматика → одна запись →
частота → микрофон есть → выбранный носитель пригоден → аренда микрофона.
Отказ ничего не пишет ни на какой носитель.

## 3. Исходы: `last_status`

| last_status | Когда |
|---|---|
| `ok` | клип сохранён (в том числе после досрочной остановки, если ≥ 1 с) |
| `busy` | старт во время идущей записи |
| `disabled` | модуль выключен — значение для отвечающих за демона (панель); сам демон в выключенном состоянии не работает и его не публикует |
| `no_mic` | микрофона нет (§6) или arecord сообщил «нет устройства» |
| `mic_busy` | аренда микрофона занята (§11) или arecord сообщил «Device or resource busy» (открывший мимо аренды) |
| `storage_full` | на выбранном носителе после очистки по лимитам свободного места меньше порога (§5) |
| `medium_absent` | выбранного съёмного носителя нет (§5) |
| `medium_readonly` | носитель смонтирован `ro` или пробный файл не создаётся |
| `medium_lost` | носитель пропал между стартом и переименованием клипа |
| `rate_limited` | превышен лимит частоты (§2) |
| `bad_command` | полезная нагрузка вне грамматики |
| `interrupted` | запись не дала клипа по внешней причине: перезагрузка/падение (найден `.part`), остановка демона, досрочная остановка короче 1 с |
| `error` | прочее: arecord завершился раньше срока, ошибка записи файла, не запустился дочерний процесс |

Сообщение arecord «overrun» клип не портит: `ok` плюс событие `xrun`.

## 4. Сценарии — без изменений движка

Сценарий записывает обычным действием записи:

- блок: `{"kind":"set","device":"sa02m-audio","cap":"record","value":10}`
  (или `"value": 1` — длительность по умолчанию);
- код: `Hub.set('sa02m-audio', 'record', 10)`.

`sa02m-audio` нет в документе устройств Алисы, поэтому движок пишет «сырой»
топик `/devices/sa02m-audio/controls/record/on` с полезной нагрузкой `"10"`
(`"1"` для `1`/`True`/`"on"`) и `retain = false`
(`docs/contracts/cloud-scenarios.md` §«Цель записи»). Запись считается в
`MAX_WRITES` и в окно 8 записей за 10 с, как любая другая. Реакция на результат
кода не требует: триггер `state` на `sa02m-audio`/`last_status` (или
`last_file` `changed`). Поведение закреплено тестом
`opt/sa02m-rules/tests/test_audio_seam.py` (строка `py-unit-rules`).

Не проверено: умеет ли **облачный** редактор сценариев адресовать устройство,
которого нет в каталоге Алисы (это код облачного репозитория). Работает
сохранённая строка: агентский `rules.upsert`, облачная доставка написанной
вручную строки, `type=code`.

## 5. Носители

Единственный дом — `constants.MEDIA`; остальные модули и панель читают вердикт
демона из `status.json` (§9) и не выводят его заново.

| Носитель | Точка монтирования | Каталог хранения | Порог свободного места, МБ | Предел `keep_mb` |
|---|---|---|---|---|
| `emmc` | — (корневая ФС) | `/var/lib/sa02m-audio` | 200 | 256 |
| `usb` | `/media/usb` | `/media/usb/sa02m-audio` | 16 | 4096 |
| `sdcard` | `/media/sdcard` | `/media/sdcard/sa02m-audio` | 16 | 4096 |

Внутри каталога хранения — `rec/` (готовые клипы) и `tmp/` (`.part` идущей
записи). Порог eMMC защищает ОС; порог съёмного носителя — ≥ 16 максимальных
клипов (заполнение флешки ОС не вредит). По умолчанию — `emmc`.

**Присутствие.** Точки монтирования съёмных носителей — литералы
`etc/storage-mount.sh` `set_device_context`; `tests/test_drift.py` сверяет их с
`MEDIA`. Съёмный носитель **присутствует**, только если одновременно:

1. путь — точная точка монтирования в `/proc/mounts` (восьмеричные экраны
   раскрыты; для пути действует последняя строка, как у ядра);
2. источник этой строки — блочное устройство `/dev/…`;
3. `st_dev` точки монтирования отличается от `st_dev` корня `/`.

Судить по таблице монтирования, а не по «каталог существует», — несущее, не
перестраховка: `storage-mount.sh` создаёт точки монтирования `mkdir -p` +
`chmod 777`, и после размонтирования каталог остаётся на корневой ФС (стенд
1.135: фантомный `/media/usb` — 0777 на `mmcblk2p2`, и юнит с
`ProtectSystem=strict` мог в него писать). Такой фантом отсекает условие 1;
условия 2 и 3 отсекают строку таблицы, за которой нет носителя (tmpfs или
bind каталога корневой ФС поверх пути). Без них «отсутствующая» флешка была бы
каталогом eMMC, и клипы молча ложились бы на eMMC.

**Пригодность.** Носитель пригоден, если опции монтирования не содержат `ro`
(для eMMC — опции `/`), пробный файл в `tmp/` создаётся и удаляется, и
свободного места не меньше порога. Пробу и создание `sa02m-audio/rec`,
`sa02m-audio/tmp` демон делает только при старте записи; периодическая проверка
(каждые `MEDIA_CHECK_S` = 10 с, без запуска процессов) судит присутствие, `ro`
и свободное место и ничего не пишет. Неизвестное — непригодно: нечитаемый
`/proc/mounts` или сбой `stat` — `absent`, сбой `statvfs` или пробы —
`readonly`.

**Выбранный носитель непригоден — отказ, без подмены.** Ни в какую сторону:
`emmc` тоже никогда не переливается на съёмный носитель.

| Состояние при старте | Результат |
|---|---|
| нет (не вставлен, размонтирован, фантомный каталог) | `medium_absent`, `medium_state = absent`, ничего не записано нигде |
| `ro` или проба не прошла (EROFS, `errors=remount-ro`, чужой владелец, подложенный файл или ссылка вместо `sa02m-audio`) | `medium_readonly` |
| свободного места меньше порога после очистки по лимитам | `storage_full`, `medium_state = full` |
| носитель извлечён или лениво размонтирован во время записи (`do_unmount` делает `umount -l`) | перед переименованием демон заново проверяет присутствие и тот же `st_dev` ⇒ `medium_lost`, `.part` удаляется |

Почему отказ, а не eMMC: Оператор выбрал носитель ради ёмкости или чтобы
унести записи физически; тихая подмена кладёт звук туда, куда он не выбирал, и
под другие лимиты, а отказ виден (`last_status`, `medium_state`) и
исправляется очевидно (вставить носитель).

Отличие от `status.cgi`: его запасной путь `sdcard_mountpoint` (любой
смонтированный `mmcblk1/3` вне `/media/sdcard`) здесь **не** принят — ручное
монтирование вне жизненного цикла `storage-mount`. В этом крайнем случае
дашборд может показать «SD смонтирована», а вердикт рекордера — `absent`.

Смена носителя в конфиге клипы не переносит: клип остаётся там, где записан.

## 6. Формат, захват, устройство

- Формат: WAV, PCM S16_LE, 16 000 Гц, моно. 30 с = 960 000 байт данных плюс
  заголовок — под синхронным лимитом 1 МБ SpeechKit; потребитель, которому
  нужен LPCM без заголовка, снимает RIFF.
- Захват (`capture.py`): `timeout -k 2 <длительность+5> arecord -q -D <устройство>
  -f S16_LE -r 16000 -c 1 -t raw` в собственной группе процессов, вывод — в
  канал. Демон сам пишет WAV через `wave`, поэтому заголовок несёт настоящее
  число сэмплов при любом завершении arecord. Останов — ровно на
  `длительность × 32 000` байт, затем группа процессов получает SIGTERM (через
  3 с — SIGKILL); `timeout` — вторая граница.
- Пиковый уровень (dBFS) считается по сэмплам: заглушённый микрофон виден
  числом (`-90`), а не «успешным» тихим файлом.
- Устройство (`alsa.py`): `device = auto` разрешается **при каждом старте** по
  `/proc/asound/cards` — первая карта с драйвером `USB-Audio`, у которой есть
  PCM захвата (`/proc/asound/cardN/pcmMc`), как `plughw:CARD=<id>,DEV=0`
  (стенд 1.135: `plughw:CARD=Microphone,DEV=0` пишет); если id карты вне
  `^[A-Za-z0-9_]{1,32}$` — `plughw:<индекс>,0`. Индекс карты не постоянен
  после переподключения. `plughw` обязателен: 16 кГц даёт пересэмплирование
  слоя plug (родные частоты Fifine — 44,1–192 кГц). Явное имя ALSA в конфиге
  допускается по `^[A-Za-z0-9:=,_.-]{1,64}$`; микрофон тогда считается
  присутствующим, если у любой карты есть PCM захвата.

## 7. Хранение

- Id клипа: `YYYYMMDDTHHMMSSZ-<6 hex>` в UTC, регулярное выражение
  `^[0-9]{8}T[0-9]{6}Z-[0-9a-f]{6}$` — единственная форма, которую принимает
  `delete/on`; случайный хвост держит уникальность и при неверных часах. Id
  уникален на всех носителях.
- Запись: `<каталог>/tmp/<id>.wav.part` (`O_EXCL`, без перехода по ссылке) →
  `fsync` → повторная проверка присутствия и `st_dev` → `rename` в `rec/<id>.wav`
  (та же ФС, атомарно) → `fsync` каталога. Дескрипторы каталогов держатся от
  старта до переименования: лениво размонтированный носитель через них ещё
  достижим, поэтому повторная проверка обязательна.
- Каждое имя внутри каталога хранения открывается относительно дескриптора с
  `O_NOFOLLOW`: подложенная ссылка на месте `sa02m-audio/`, `rec/`, `tmp/` или
  клипа не проходится.
- При старте демона и всякий раз, когда носитель становится присутствующим,
  каждый `.part` на нём удаляется; если он был — `last_status = interrupted` и
  событие `interrupted` (перезагрузка, падение, OOM, извлечение во время записи).
- Индекс — сам листинг `rec/`, отдельного файла нет. В листинг попадают только
  имена `<id>.wav`, являющиеся обычными файлами с одной ссылкой; подложенная
  ссылка, FIFO, жёсткая ссылка, чужое имя — не клип.
- Очистка по лимитам — на **каждом присутствующем** носителе отдельно, не
  только на выбранном (клип, оставшийся на флешке от прежнего выбора, тоже
  стареет, когда флешка вставлена): старше `keep_hours`, затем самые старые,
  пока файлов больше `keep_files` или байт больше `keep_mb`. Возраст и порядок
  — по mtime файла (при равенстве — по id). Очистка идёт при старте, после
  каждой записи, перед проверкой места при старте записи, при появлении
  носителя и раз в час.
- Удаляет клипы только демон (`delete/on`, очистка); выключение модуля клипы
  не удаляет.

## 8. Конфиг

`/etc/sa02m-audio/sa02m-audio.conf`, INI, секция `[recorder]`, без секретов.
Единственный дом грамматики — `config.py` (`load` / `save`): значения
проверяются при чтении (вне границ — к границе или к умолчанию, с
предупреждением) и при записи (`save` отказывает). Демон только читает и
перечитывает файл каждые `CONF_POLL_S` = 2 с.

| Ключ | По умолчанию | Границы |
|---|---|---|
| `enabled` | `false` | `true` \| `false` (`1/0`, `yes/no`, `on/off`) |
| `storage` | `emmc` | `emmc` \| `usb` \| `sdcard`; иное ⇒ `emmc` и событие `config` с отвергнутым значением |
| `device` | `auto` | `auto` или имя ALSA (§6) |
| `default_duration_s` | `10` | `2`…`max_duration_s` |
| `max_duration_s` | `30` | `2`…`30` (жёсткий потолок) |
| `keep_files` | `50` | `1`…`50` |
| `keep_mb` | `32` | `1`…предел носителя (§5) |
| `keep_hours` | `24` | `1`…`168` |
| `delete_after_upload` | `true` | `true` \| `false` |

Файл есть, но не открывается ⇒ демон пишет состояние `conf_unreadable` и не
записывает ничего; это не «выключено». Нет файла или секции, ошибка разбора ⇒
умолчания (выключено).

## 9. Статус: `/run/sa02m-audio/status.json`

Пишет только демон (0640, группа каталога), атомарно: при каждом исходе
команды, при старте и конце записи, при смене конфига и при каждой
периодической проверке носителей (10 с), так что `ts` старше ~30 с при
работающем демоне — признак, что он не отвечает.

| Состояние | Смысл |
|---|---|
| `idle` | работает, записи нет |
| `recording` | идёт запись |
| `disabled` | `enabled = false`; процесс завершился (выход 0) |
| `conf_unreadable` | конфиг есть, но не читается; ничего не записывается (выход 0) |
| `missing_deps` | нет paho (выход 0) |
| `stopped` | штатная остановка при `enabled = true` |
| `error` | неожиданная ошибка (выход 1, systemd перезапустит) |

| Ключ | Значение |
|---|---|
| `state` | состояние из таблицы выше |
| `ts` | время записи файла, секунды эпохи |
| `version` | версия пакета |
| `enabled` | значение конфига |
| `message` | пояснение к `state` (≤ 200 символов) |
| `mic` | как контрол `mic` |
| `mic_device` | разрешённое имя ALSA или `""` |
| `medium` | выбранный носитель |
| `medium_state` | вердикт по выбранному носителю |
| `media` | по каждому носителю §5: `state`, `free_bytes`, `files`, `bytes` |
| `recording` | `null` или `{id, medium, seconds, started_ts}` |
| `last_file` | как контрол |
| `last_status` | как контрол; `""` до первого исхода |
| `last_duration_ms` | как контрол |
| `last_size` | как контрол |
| `last_peak_dbfs` | как контрол |
| `last_upload` | как контрол |
| `count` | как контрол |
| `rate_used` | начато записей за скользящий час |
| `rate_max` | лимит частоты |
| `conf_warnings` | предупреждения разбора конфига (≤ 10) |

## 10. Журнал событий: `/var/lib/sa02m-audio/events.jsonl`

Всегда на eMMC, какой бы носитель ни был выбран. Последние `EVENTS_MAX` = 200
событий, по одному JSON-объекту в строке, файл переписывается атомарно; каждое
событие — ещё и строка журнала демона (journald, постоянный с 1.0.6.51). Ключи
события (`service.EVENT_KEYS`): `ts`, `event`, `status`, `id`, `medium`,
`seconds`, `detail` (≤ 200 символов), `source`; пустые опускаются.

| Событие | Когда |
|---|---|
| `start` | запись началась (`detail` — устройство ALSA) |
| `end` | клип сохранён |
| `refused` | команда отвергнута (`status` — `last_status`) |
| `failed` | запись началась, но клипа нет: ошибка, `medium_lost`, `mic_busy`, `no_mic` |
| `interrupted` | найден и удалён `.part`; остановка демона во время записи |
| `discarded` | досрочная остановка короче 1 с |
| `xrun` | arecord сообщил overrun, клип сохранён |
| `delete` | команда `delete/on` (`detail` — сколько удалено) |
| `retention` | очистка по лимитам удалила клипы |
| `config` | конфиг изменился (в том числе носитель) или содержит отвергнутые значения |
| `medium` | вердикт по выбранному носителю изменился |
| `mqtt` | retained-команда отвергнута и очищена |

## 11. Аренда микрофона

Каждый, кто открывает USB-микрофон, берёт **аренду**: открыть (создать, если
нет) `/run/lock/sa02m-mic.lock` и взять `flock(LOCK_EX | LOCK_NB)`; держать всё
время, пока устройство открыто; отпустить закрытием дескриптора. Занятая
аренда — отказ, а не ожидание. Рекордер создаёт файл с режимом 0644 (другой
пользователь откроет его на чтение — для `flock` этого достаточно) и держит
аренду на время жизни arecord; периодическая проверка микрофона пробует
аренду и сразу отпускает (`mic = busy`, если она занята).

Сегодня микрофон не открывает больше никто; `scripts/dev/stt-eval-board.py` —
инструмент разработчика, аренду не берёт. Будущие потребители (светомузыка
LED, живое распознавание) **обязаны** её брать. Если устройство всё же открыто
мимо аренды, ALSA отказывает arecord («Device or resource busy»), и рекордер
отвечает `mic_busy`.

## 12. Передача клипа

- В MQTT — только метаданные (§2: `last_*`); байты звука в MQTT не
  публикуются никогда.
- Шов для будущего клиента распознавания (потребителя в этой версии нет):
  следить за `last_file` и отбрасывать повторы по id (retained-значение
  повторяется при подписке); читать `<каталог хранения>/rec/<id>.wav` того
  носителя, который назван в `status.json`, разбирая чанки RIFF, а не считая
  заголовок 44-байтным; удалять через `…/controls/delete/on`. Право чтения
  потребитель получает членством в группе — решается в его собственном плане.

## 13. Файлы и права

| Путь | Владелец, режим | Кто пишет / читает |
|---|---|---|
| `/etc/sa02m-audio/` | `www-data:sa02m-audio` 2750 | панель пишет конфиг, демон читает через группу |
| `/var/lib/sa02m-audio/`, `rec/` | `sa02m-audio:www-data` 2750 | демон пишет; `www-data` читает через группу |
| `/var/lib/sa02m-audio/tmp/` | `sa02m-audio` 0700 | только демон (`.part`) |
| `/run/sa02m-audio/` (`status.json`, `daemon.lock`) | `sa02m-audio:www-data` 2750 | демон пишет, `www-data` читает |
| `/run/lock/sa02m-mic.lock` | 0644, создаёт первый арендатор | аренда §11 |
| `/media/{usb,sdcard}/sa02m-audio/` | права даёт ФС носителя (vfat/exfat/ntfs монтируются `umask=000`) | **любой** локальный пользователь и любой, у кого носитель в руках |

Каталоги и режимы задаёт `opt/sa02m-audio/tmpfiles.d/sa02m-audio.conf`
(systemd-tmpfiles пересматривает их при каждой загрузке). Демон, создающий
недостающие `rec/` и `tmp/` на eMMC, использует те же режимы.

## 14. Жизненный цикл

- Запуск: `python3 -m sa02m_audio`. Одна копия — `flock` на
  `/run/sa02m-audio/daemon.lock`; вторая завершается с кодом 75 и ничего не
  пишет.
- Выходы 0 (systemd `Restart=on-failure` их не трогает): `disabled`,
  `conf_unreadable`, `missing_deps`, SIGTERM. Неожиданное — `error`, выход 1.
- Старт: мета и `record = 0`, проверка всех носителей (очистка `.part` и по
  лимитам на каждом присутствующем), статус `idle`, подключение к брокеру.
- `enabled = false` во время работы ⇒ остановка (идущая запись — `interrupted`).
- SIGTERM: группа процессов arecord завершается, `.part` удаляется,
  `record = 0`, `last_status = interrupted`, `meta/error = "r"`, статус
  `stopped`.
- Один главный поток владеет состоянием; сетевой поток paho только ставит
  команды в очередь, поток захвата только возвращает результат.
