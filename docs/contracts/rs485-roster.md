# Контракт: ростер модулей RS-485 (bus-free)

Домашний адрес контракта для нормализованного кеша ростера RS-485 и его
отражения в `status.cgi?part=rs485`. Машинная грамматика (имена и формы JSON) —
на английском (`PROTOCOL.md` invariant 5); прозаические пояснения — на русском.

Ключевой инвариант: **ни один потребитель этого контракта не открывает
последовательный порт.** Данные производит только агрегатор из файлов, уже
записанных сервисами-владельцами шины (мост MQTT) или прошлым сканом флешера.

## 1. `/run/sa02m-rs485-roster.json` (tmpfs, world-readable 0644)

Единственный писатель — агрегатор `sa02m-rs485-roster` (systemd timer, тик 8 с).
Отсутствие/устаревание файла трактуется потребителем как «нет данных».

```json
{
  "ts": 1737000000.0,
  "ports": {
    "COM4": {
      "source": "bridge",
      "live": true,
      "ts": 1737000000.0,
      "ours": [ { "addr": 6, "model": "6AI6AO", "online": true, "source": "bridge" } ],
      "third_party": { "total": 3, "online": 2 }
    },
    "COM5": {
      "source": "scan",
      "live": false,
      "ts": 1736900000.0,
      "ours": [ { "addr": 3, "model": "4DO6DI", "online": null, "source": "scan" } ],
      "third_party": { "total": 0, "online": null }
    }
  }
}
```

- `source`: `"bridge"` (живой опрос моста) либо `"scan"` (последний скан флешера).
- `live`: `true` только для источника `bridge`. Для `scan` — всегда `false`
  (данные последнего скана, не реального времени; честность — не выдавать
  устаревшее имя за живое).
- `ours[].online`: `true`/`false` только у живого источника; у `scan` — `null`.
- `third_party.online`: `null`, когда порт не имеет живого источника (нельзя
  показывать ложный ноль онлайна вместо неизвестности).

## 2. `status.cgi?part=rs485` — аддитивное поле `modules`

Каждый объект порта дополнительно (только при наличии кеша) несёт `modules`.
Старые поля (`n`,`dev`,`st`,`tx`,`rx`,`fe`/`pe`/`oe`,…) сохранены без изменений —
устаревший кешированный бандл фронтенда просто игнорирует `modules`.
Соответствие портов: RS-485-N ↔ COM(N+1).

```json
{
  "n": 3, "dev": "ttyS4", "st": "present", "tx": 1234, "rx": 1200,
  "modules": {
    "source": "bridge", "live": true, "ts": 1737000000.0,
    "ours": [ { "addr": 6, "model": "6AI6AO", "online": true } ],
    "third_party": { "total": 3, "online": 2 }
  }
}
```

## 3. Согласование с облачным контрактом (superset)

Поле `modules` — **надмножество** замороженного облачного шва
(`cloud-backend/docs/contracts/cloud-enrollment.md`): базовые `addr`/`model`/
`online` сохранены, чтобы облачный heartbeat-филлер мапил их без изменений;
`ours`/`source`/`live` — дополнительные поля, которые филлер игнорирует.
Облачный филлер и UI устройства читают ОДИН и тот же
`/run/sa02m-rs485-roster.json`, поэтому карточка флота и UI устройства не
расходятся.
