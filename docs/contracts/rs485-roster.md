# Ростер модулей RS-485

Агрегатор `sa02m-rs485-roster` раз в 8 секунд атомарно публикует
`/run/sa02m-rs485-roster.json` с правами 0644. Агрегатор и веб-панель читают
локальные файлы. Доступ к шине остаётся у сервиса, который её опрашивает.

## 1. Инвентаризация и настроенный опрос

В одном снимке находятся время генерации `ts` и две проекции.

| Поле | Состав и источник | Потребитель |
| --- | --- | --- |
| `ports` | Объединение ростера работающего моста и последнего сканирования по COM и адресу. При совпадении приоритет у моста. | Облачный агент передаёт эту проекцию без изменений в `{"ports": ...}`. |
| `polling_ports` | Принятые мостом записи Modbus RTU из текущего сохранённого конфига. Адрес и COM берутся из созданного объекта опроса. | Карточки COM на панели. |

В `ports` сохраняется `source: "bridge" | "scan"`. У результата сканирования
`live:false` и `online:null`. В смешанном блоке у каждого элемента `ours`
сохраняется собственный источник. Полная запись о сканировании остаётся у флешера.

Для `polling_ports` фоновый процесс читает `SA02M_MQTT_CONFIG` (обычно
`/etc/sa02m-modbus-mqtt.yaml`) и использует штатный отбор драйверов моста.
При прежней ревизии конфигурации, производителя и целей ссылок COM используется закрытый кеш
проверенных привязок. Сетевые транспорты и Mercury HDLC в ростер Modbus RTU
не входят. Ошибка всей конфигурации даёт пустую проекцию. Отказ отдельной
регистрации обрабатывается по тем же правилам, что при запуске моста.

| Состояние привязки | Карточка COM |
| --- | --- |
| Запись удалили, перенесли на другой COM или нашли только при сканировании | На прежнем COM запись отсутствует. |
| Устройство настроено, экземпляр моста подтвердил успешный опрос | `online:true` |
| Тот же экземпляр подтвердил ошибку опроса | `online:false` |
| Мост остановлен, первого результата ещё нет, результат устройства или экспорт старше 60 с, привязка отличается, идентификатор неоднозначен или старый мост не передаёт время наблюдения | Устройство остаётся в составе опроса с `online:null`. |

Для подтверждения связываются текущий запуск службы и точная привязка
устройства, включая идентификатор, тип/подтип, COM, адрес и параметры линии.
Мост сохраняет `observed_online` и `observed_at` одной парой при успешном
чтении или достижении порога ошибок. Повторный опрос с тем же результатом
обновляет время. Удержание линии, пустой цикл и повторная запись файла
сохраняют время последнего наблюдения. Помощник проверяет его отдельно
для каждого модуля и для всех устройств стороннего счётчика.
Сохранение конфигурации без перезапуска меняет состав после очередного
успешного запуска агрегатора и обновления панели. У нового состава может ещё
не быть подтверждённых ответов. Счётчик `third_party.total` включает каждое
принятое стороннее устройство. `third_party.online` содержит число отвечающих,
когда состояние известно для всех, иначе `null`.

## 2. Поле `modules` в `status.cgi?part=rs485`

Помощник читает только свежую проекцию текущей ревизии. Панель принимает блок
с `source:"configured"`. При пустой проекции, старом поколении помощника
или просроченном снимке физические порты и их счётчики остаются видны. Номер
RS-485-N соответствует COM(N+1). Поля UART, признаки присутствия и занятости,
TX/RX и приращения ошибок сохраняют прежнюю семантику.

```json
{
  "n": 3, "dev": "ttyS5", "st": "present", "tx": 1234, "rx": 1200,
  "modules": {
    "source": "configured", "live": true, "ts": 1795680000,
    "ours": [
      {"addr": 3, "model": "DTV-RS-45", "online": null, "source": "configured"},
      {"addr": 6, "model": "6AI6AO", "online": true, "source": "configured"}
    ],
    "third_party": {"total": 2, "online": 0}
  }
}
```

`live` показывает наличие подтверждённого результата хотя бы у одного
устройства на порту. Цвет отдельного модуля определяет только его `online`.
Таймер и кеширование статуса описаны в [контракте опроса панели](status-polling.md).

## 3. Проверка контракта

`py-unit-roster` проверяет проекции, совместимость облачного
`read_roster_modules`, границы свежести и привязку к экземпляру моста.
`rs485-roster-consumer` проводит конфигурацию и старый скан через настоящий
экспорт моста, агрегатор, помощник и функции штатного CGI. Проверяются перенос
со стабильным id, исключение лишнего COM, счётчики сторонних устройств,
передача блока `modules` и сохранение приращений ошибок UART.
`comment-mutation-proof` проверяет, что потеря строки `modules_frag` делает
потребительский тест красным.
