# Контракт: веб-консоль

`cmd_exec.cgi` исполняет команду из панели и возвращает JSON с `ok`, `rc`,
`mode`, `output`, `truncated`, `capture_timed_out`; stdout и stderr объединены.
Доступ требует серверной сессии, POST и `X-SA02M-CSRF`. Проверки проходят до
создания временных файлов и исполнения команды. Режим `root` дополнительно
проверяет пароль через `sa02m-web-root-cmd.sh`; обычный режим работает от
пользователя веб-сервера.

| Граница | Поведение |
|---|---|
| Команда | Непустая строка до 1000 символов; режим `web` или `root` |
| Исполнение | 15 секунд, затем до 2 секунд до SIGKILL; в `root` проверка пароля входит в эти 15 секунд |
| Внешнее ожидание root-helper | 18 секунд плюс 1 секунда до SIGKILL; защищает ответ от задержки sudo или старого helper |
| Сбор вывода | Непривилегированный `lib_cmd_capture.py`: порции до 65536 байт, хранение последних 32768 байт, монотонный предел 18 секунд даже при непрерывном потоке или отсутствии EOF |
| Временный вывод | Не больше 32768 байт плюс фиксированная 19-байтная отметка тайм-аута; полный поток на диск не записывается |
| Ответ | Последние 32768 байт, включая отметку тайм-аута; чтение только хвоста, UTF-8 с заменой некорректных байт. Экранирование JSON может увеличить размер ответа |
| `truncated` | Наблюдённый вывод вместе с отметкой тайм-аута длиннее 32768 байт |
| `capture_timed_out` | Сбор остановлен по времени до EOF. Возможный будущий вывод не учитывается в `truncated` |
| Код результата | Настоящий код producer-команды, независимо от collector. Завершившаяся с `rc: 0` оболочка может оставить фоновый процесс с открытым stdout и дать `capture_timed_out: true` |
| Ошибка сборщика | `ok: false, error: "capture_failed"` при недоступном collector, ошибке чтения/записи или неверной metadata; успешный пустой вывод не подставляется |
| Кеширование | `Cache-Control: no-store` |

`ok: true` означает сформированный результат исполнения, а не нулевой `rc`.
Обычные тайм-ауты дают коды GNU timeout (124 либо 137 после SIGKILL) и общую
отметку `[command timeout]`: она не приписывает внешнему 18-секундному ожиданию
15-секундный срок. Интерфейс отдельно показывает усечение и неполный сбор;
предлагает ограничить непрерывную команду либо закрыть/перенаправить stdout и
stderr фонового процесса. `capture_failed` получает локализованное сообщение.

Привилегированный verifier остаётся в root-owned helper: изолированный Python
проверяет shadow и исполняет фиксированный `/bin/bash -c` внутри одного срока.
Он не импортирует код из веб-каталога. Пароль не попадает в argv, metadata или
вывод. Существующие ограничения имён временных файлов и запрет symlink
сохранены. Нового sudo-разрешения и нового endpoint нет. Collector доставляется
с веб-деревом; helper — существующими full/www-only/update путями.

Сроки рассчитаны на работающую ОС и укладываются в nginx `fastcgi_read_timeout`
20 секунд. Это не жёсткая гарантия при зависшем ядре, планировщике или worker.
Получение тела POST предшествует этим срокам и ими не ограничивается. Консоль
не является sandbox: ограничения захвата не запрещают произвольной команде
писать другие файлы, запускать отделённые процессы или создавать systemd jobs.
Внешний timeout непривилегированного CGI не доказывает остановку произвольных
root-потомков. Временные файлы удаляются EXIT-обработчиком; удерживаемый stdout
сам по себе не означает, что завершённая оболочка ещё работает.

Проверки: `scripts/dev/test-cmd-exec.py` выполняет настоящий CGI/auth,
ограниченный reader и collector, ошибки metadata, виртуальный 10-ГиБ хвост,
8-МиБ поток с измерением spool, реальный GNU TERM/KILL и verifier с синтетическим
shadow. `console-bounds-browser.mjs` соединяет настоящий CGI с Chromium и
проверяет предупреждения и восстановление интерфейса. Дополнительная настоящая
CGI→sudo→helper проверка в одноразовом Noble-контейнере использует синтетический
пароль и узкий grant; она не меняет пароль или sudoers хоста. Её результаты
отдельно записываются в аудите и не подразумеваются одним unit-прогоном.
