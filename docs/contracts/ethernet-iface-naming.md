# Контракт: канонические имена Ethernet-интерфейсов (`eth0`/`eth1`)

Домашний адрес контракта для именования Ethernet-интерфейсов SA-02m, для нового
ключа `klogic` в `config.cgi` и для шва «панель ↔ сторонний писатель» в
`/etc/network/interfaces.d/`. Машинная грамматика (имена файлов, юнитов, полей
JSON) — на английском (`PROTOCOL.md` invariant 5); пояснения — на русском.

---

## 1. Гарантия

> На каждой плате SA-02m первый Ethernet называется `eth0`, второй — `eth1`, при
> каждой загрузке, независимо от политики именования systemd/udev.

Обеспечивает `sa02m-iface-canonical.service` (`etc/systemd/`) →
`/usr/local/sbin/sa02m-iface-canonical.sh` (`etc/sa02m-iface-canonical.sh`).

**Почему это не возврат к 1.0.3.38/39.** Откат 1.0.3.39 убрал `10-end0.link` /
`10-end1.link`, потому что `.link`-файл — это **вход политики именования
systemd-udevd**: обновление `systemd`/`udev` может изменить или обнулить его
эффект, и сеть падает с `ifup: Cannot find device`. Юнит отличается по трём осям:

| Ось | `.link` (1.0.3.39, откачено) | `sa02m-iface-canonical.service` |
|---|---|---|
| Механизм | вход политики udev | собственный вызов `ip link set … name` через стабильный netlink ABI `RTM_SETLINK` |
| Когда | один раз при применении политики | **каждую загрузку** — после `apt upgrade`, вернувшего `end0`, следующая загрузка чинит имя сама |
| Направление | авторитетное переименование | **сходящееся**: только legacy → канон, никогда обратно; no-op, когда каноническое имя уже есть |

`.link`-файлы (`10-*`, `11-*`, для `eth0/eth1/end0/end1`) с этой версии
удаляются установщиком **безусловно**: имя владеет юнит, любой `.link` — либо
мусор, либо конкурирующий именователь.

### 1.0 Ворота «udev-initialized»: существование имени ≠ устоявшееся имя

На ядрах класса 6.1 драйверы регистрируют `eth0`/`eth1` **нативно**, а udev
затем **асинхронно** переименовывает их в `end0`/`end1` (coldplug-проход
политики предсказуемых имён). Отсюда класс отказа (8D 2026-07-29, стенд
`192.168.1.136`, kernel 6.1.0-rc6, udev 255, журнальные доказательства):
проверка «имя уже существует» не отличает устоявшееся каноническое имя от
kernel-native имени, которое udev вот-вот заберёт. Четыре подтверждённых
механизма (первые два — класс «имя ≠ устоявшееся имя», третий — соседний,
вскрыт стендовой перезагрузкой № 1 после установки ворот; четвёртый —
мс-гонка внутри самих ворот, вскрыта ночным простоем 2026-07-29/30):

- **юнит стартовал до udevd** → увидел kernel-named `eth0`/`eth1` → «already
  canonical» → no-op; udev переименовал в `end0`/`end1`; `ifup eth0` →
  `Cannot find device` → `networking.service` FAILED, плата на ненастроенном
  `end0` — **недоступна при автономной загрузке**;
- **с `Wants=systemd-udev-settle`** → settle всей очереди упирался в таймаут
  120 с (мусорная занятость очереди — отдельный backlog-пункт), позднее
  переименование запускало `fix-eth@eth0` ровно во время `ifup -a` →
  дублирующий `ip addr add` → `RTNETLINK answers: File exists` → networking
  FAILED + ~2 мин задержки загрузки;
- **бэкапы конфигов сорсились как живой конфиг** (стенд, перезагрузка № 1
  2026-07-29): `/etc/network/interfaces` содержал
  `source /etc/network/interfaces.d/*` **без фильтра `.conf`**, поэтому
  бэкап `eth0.conf.sa02m-bak` (§3/§5.4) с полной дублирующей стансой
  `auto eth0` обрабатывался `ifup -a` вторым проходом → второй
  `ip addr add` → `RTNETLINK answers: File exists` → networking FAILED
  (а `end0.conf.sa02m-bak` с `allow-hotplug end0` заставлял udev-овский
  `ifup@end0` дёргать несуществующее устройство — шумно, но безвредно).
  Исправление: `source /etc/network/interfaces.d/*.conf` в
  `scripts/02-network.sh` (безусловная перезапись `/etc/network/interfaces`
  установщиком — сама по себе полевая миграция); инертность бэкапов
  **держится на этом фильтре**.
- **db-запись udev опережает применение переименования на миллисекунды**
  (стенд, boot 2026-07-29 20:52) → ворота honest-но увидели «settled eth0»,
  через 15 мс udev забрал имя → `Cannot find device` → плата ночь на
  ненастроенном `end0`. Механизм 4, полное описание и закрытие — ниже.

Исправление класса — **пер-устройственные ворота по initialized-состоянию
самого udev**: `/run/udev/data/n<ifindex>` существует ⇔ udev обработал `add`
этого устройства и применил свою политику именования, то есть **текущее имя
initialized-устройства и есть его устоявшееся имя**. Скрипт действует только
на initialized-устройствах, в пределах ограниченного ожидания; `ifindex`
стабилен при переименовании, поэтому проверка не гоняется с самим
переименованием (рваное чтение читается как «не initialized», следующий тик
перепроверяет — отказ закрыт в сторону ожидания). Ворота **пер-устройство**,
поэтому невосприимчивы к занятости всей очереди udev (settle всей очереди —
120 с; NIC-и initialized на ~10-й секунде того же boot).

**Деградация**: если udev-db так и не появилась за бюджет (udevd
мёртв/завис, либо будущий udev переместил путь db) — скрипт действует по
**текущему** имени с честным `WARN` в журнале, сохраняя сегодняшнюю
дисциплину кодов выхода; худшая патологическая цена — `2 × WAIT_SECS`
ожидания, поведение деградирует ровно до прежнего, не хуже.

**Механизм 4 — db-запись раньше переименования (мс-гонка); закрыт
событийным перезапуском (1.0.5.57).** Подтверждено покадрово на стенде
(журнал boot id `55c9ae67d1b94d01b1338e4ebee15d7f`, 2026-07-29 20:52): udev
записывает `/run/udev/data/n<ifindex>` за несколько **миллисекунд до**
применения своего переименования — ворота увидели «eth0 already canonical
(settled)» на 10,1008 с, udev переименовал `eth0`→`end0` на 10,1155 с
(15 мс спустя), `networking.service` упал на 19,86 с (`Cannot find device
eth0`), и плата провела ночь на ненастроенном `end0` (admin down → PHY
down → нет link-LED — совпало с утренним наблюдением оператора). Вывод:
ворота §1.0 **необходимы, но не достаточны** — «initialized» не строго
следует за применением имени.

Закрытие — **событийная сходимость**, а не расширение ворот: udev-правило
`etc/98-sa02m-iface-canonical.rules` на каждом `add|move` устройства `end*`
стартует `sa02m-iface-canonical-retry.service` (`--no-block` — дедлок-заметка
`99-lan-recovery.rules`), который повторно запускает тот же сходящийся,
идемпотентный скрипт: как бы поздно udev ни применил `end*`-имя, само это
событие возвращает имя в канон. Правило — **отдельный файл**: в
`99-lan-recovery.rules` строки `end*` запрещены (они запускали бы
`fix-eth@end0` против legacy-имени). Retry-юнит — без секции `[Install]`
(только событийный запуск), `Before=networking.service` — бесплатная
страховка порядка, когда networking ещё не стартовал; параллельный запуск с
boot-юнитом безопасен (проигравший исход «legacy исчез, канон есть»
скрипт логирует INFO и выходит 0).

**Остаточное окно (честно):** переименование udev, попадающее **ровно** в
момент `ifup -a` внутри networking.service, событийным перезапуском не
устраняется — retry вернёт имя, но `ifup` этого прохода уже упал.
Сдерживание — карьерно-событийная лестница `fix-eth@`
(`99-lan-recovery.rules` поднимет `eth0` после возврата имени).

### 1.1 Отказоустойчивость

Юнит объявлен `Type=oneshot` с **только** упорядочиванием `Before=` — `Before=`
это порядок, а не требование, поэтому **упавший юнит не блокирует
`networking.service`**. Худший случай — «плата осталась на старом имени и громко
об этом сообщила», а не «плата без сети».

| Сбой | Эффект | Что удерживает |
|---|---|---|
| Юнит не установлен / выключен / замаскирован | Плата остаётся `end0` | Установщик удаляет legacy-конфиг **только после подтверждённого** переименования (§3) |
| Переименование не удалось (EBUSY/EEXIST/нет устройства) | Плата остаётся `end0` | Скрипт выходит с **ненулевым** кодом → виден в `systemctl --failed`; DUAL-CONF (§3) держит `end0` настраиваемым через `allow-hotplug` |
| Юнит стартовал слишком рано | Ожидание, не no-op | Ограниченное ожидание «устройство существует **и** udev-initialized» (§1.0; `IFACE_CANONICAL_WAIT_SECS`, по умолчанию 10 с) плюс `TimeoutStartSec=30`; юнит упорядочен `After=`+`Wants=` `systemd-udevd.service` и `systemd-udev-trigger.service` |
| udev-db так и не появилась (udevd мёртв/завис, путь db переехал) | Скрипт действует по текущему имени | Деградация §1.0: `WARN` в журнале, сегодняшние коды выхода, худший случай `2 × WAIT_SECS` |

Матрица состояний платы:

| `end0` | `end1` | Результат |
|---|---|---|
| нет | нет | обе пары — no-op, exit 0 (текущий образ SA-02m, оба варианта HW) |
| есть | нет | `end0`→`eth0`; вторая пара «отсутствует», exit 0 |
| есть | есть | обе переименованы, exit 0 |
| нет | есть | первая пара no-op, вторая переименована, exit 0 |
| есть (переименование не удалось) | — | ERROR в журнал, admin-состояние восстановлено, **exit ≠ 0** |

Скрипт **не читает** `sa02m_hw_variant`: он опирается на наличие устройства, а
не на вариант платы (на A40i второй MAC может существовать и на `sa02m-1eth`).

## 2. Честность: что проверено и что нет

Статус на 2026-07-30. Пункты, помеченные «не воспроизводилось», отгружаются
проверенными по построению — не позволяйте CHANGELOG, PR или обзору
подразумевать обратное.

**Поправка честности (2026-07-30, механизм 4):** ворота udev-initialized,
объявленные ниже «отработавшими ровно как спроектированы», оказались
**необходимыми, но не достаточными** — db-запись может опережать применение
переименования на миллисекунды (§1.0, механизм 4; boot id
`55c9ae67d1b94d01b1338e4ebee15d7f`: verdict ворот 10,1008 с, переименование
udev 10,1155 с). Цена класса зафиксирована: ночной простой платы
2026-07-29/30 на ненастроенном `end0`. Закрытие — событийный перезапуск
(правило `98-sa02m-iface-canonical.rules` +
`sa02m-iface-canonical-retry.service`), **проверен на живой плате** (стенд,
2026-07-30, две перезагрузки): перезагрузка № 1 (11:30) — boot-юнит
переименовал `end0`/`end1`→`eth0`/`eth1` на 10,27/10,45 с, событийный
retry-юнит **реально сработал** на 15,01 с и дважды подтвердил «already
canonical (settled)» — ретриггер механизма 4 наблюдался на железе;
`networking` active, `eth0` с адресом, ноль failed-юнитов. Перезагрузка № 2
(11:31) — повтор чистый: переименования 10,48/10,61 с, ноль failed-юнитов,
SSH через 35 с. Один борт, два прогона — не статистика; гейт-тест
(`scripts/dev/test-iface-canonical-gate.sh`) остаётся системным покрытием
логики.

**Проверено на 6.1.0-rc6 (стенд `192.168.1.136`, udev 255, журнальные
доказательства):**

- **Все три механизма отказа §1.0 воспроизведены** (8D 2026-07-29): boot 0 —
  преждевременный no-op по kernel-named имени → `Cannot find device`;
  boot -1 — settle-таймаут 120 с + гонка `fix-eth@eth0` ↔ `ifup -a` →
  `File exists`; перезагрузка № 1 (ниже) — сорсинг бэкапов без фильтра
  `.conf` → дублирующая станса → `File exists`.
- **Ворота udev-initialized и исправление механизма 3 проверены живыми
  перезагрузками** (стенд, 2026-07-29). Перезагрузка № 1 (ворота
  установлены, фильтр `.conf` ещё нет): переименования на 10,3 с сразу после
  прохода udev — ворота отработали ровно как спроектированы; отказ
  `networking.service` трассирован до механизма 3 (сорсинг `*.sa02m-bak`),
  не до ворот. Перезагрузка № 2 (с фильтром `.conf`): полный проход по всем
  пяти критериям приёмки — переименования через ворота на 10,9/11,3 с
  (после udev); `networking.service` завершился чисто на 21,65 с (ни
  `File exists`, ни `Cannot find device`); `eth0` UP с
  `192.168.1.136/24` + `192.168.137.10/24` и маршрутом по умолчанию через
  `192.168.137.1`, `end0` отсутствует; `fix-eth@eth0` стартовал на 21,76 с —
  строго после завершения networking; шум `ifup@end0` исчез; в
  `systemctl --failed` только доизменные codemeter/docker; загрузка без
  регрессии (1:42 против 1:43 базовой). Один борт, два прогона — не
  статистика; гейт-тест (`scripts/dev/test-iface-canonical-gate.sh`)
  остаётся системным покрытием логики ворот.
- **`/run/udev/data/n<ifindex>` существует для initialized-NIC** — проверено
  на стенде (udev 255): несущая посылка ворот наблюдалась на живой плате.
- **Переход `end0`→`eth0` воспроизведён на живой плате один раз**
  (2026-07-29, тот же стенд, ещё до-воротная версия скрипта — механика
  переименования не менялась): юнит на загрузке переименовал обе пары
  (`journalctl`: `end0 -> eth0: renamed`, `end1 -> eth1: renamed`), `ifup`
  поднял `auto eth0` на прежнем адресе, DUAL-CONF-миграция и вывод
  legacy-конфига в комментарии при сохранении из панели отработали, сторонние
  `post-up`-строки пережили сохранение. Порядок запуска подтверждён
  `systemd-analyze critical-chain`.

**Только по построению:**

- **Платы 5.10.35 (udev 247) с воротами не перезагружались.** Путь и формат
  db `/run/udev/data/n<ifindex>` предполагаются идентичными (давно стабильное
  поведение udev), но ни одна 5.10.35-плата с этим изменением не грузилась.
  Деградация §1.0 ограничивает вред: `≤ 2 × WAIT_SECS` ожидания плюс ровно
  прежнее поведение.
- **Ветка деградации (udev-db не появилась) не воспроизводилась**: на
  исправной плате нельзя заставить udevd зависнуть, не ломая её — тот же
  класс, что ветка отказа DUAL-CONF ниже. Покрыта гейт-тестом (случай 5).
- **Посылка «udev не переименовывает initialized-устройство на `move`»** —
  согласуется с наблюдениями (переименование на 130-й секунде boot -1
  удержалось), но не подтверждена цитатой из спецификации. Страховка:
  сходящийся каждый-boot дизайн + деградация + `fix-eth`.
- **Защита от altname не срабатывала.** Ядро (5.10.35) резолвит altname в том же
  пространстве имён, что и основные имена (`netdev_name_in_use` →
  `netdev_name_node_lookup`), поэтому переименование в имя, занятое чужим
  altname, должно вернуть `EEXIST`. Рассуждение не подтверждено ни на железе, ни
  цитатой. Защита оставлена сознательно: она условная и наблюдаемая (один
  read-only `ip -d link show`, срабатывает только когда altname реально есть, её
  отказ не прерывает переименование). Асимметрия решает: если посылка верна и
  защиты нет — переименование падает ровно на тех платах, ради которых всё это
  сделано. Стендовая legacy-плата altname-ов не несёт (проба 2026-07-29) —
  **подтвердить при первой плате, у которой `ip -d link show` покажет altname.**
- **Ветка ОТКАЗА DUAL-CONF при загрузке не воспроизводилась** (успешная ветка —
  да, на стенде): нет способа заставить `ip link set … name` упасть на
  исправной плате, не ломая её.
- **Проверка сосуществования с KLogic — постановочная.** KLogic на стенде не
  установлен; предпосылки создаются вручную (`touch`, дописанный `post-up`).
  Это доказывает поведение **панели** и ничего не доказывает про то, что
  двоичный файл KLogic доволен результатом. Первая настоящая KLogic-плата —
  единственная настоящая проверка.

Самый дешёвый способ закрыть пробел позже: на стенде с подключённой serial-
консолью сделать legacy-плату вручную (`ip link set eth0 down && ip link set eth0
name end0`, переименовать конфиг), перезагрузиться и убедиться, что юнит вернул
имя. ~30 минут, полностью обратимо с serial.

## 3. Миграция состояния на диске

Установщик (`scripts/02-network.sh`) идемпотентен: каждый шаг защищён проверкой
«legacy-артефакт ещё существует», поэтому повторный запуск — no-op.

Ворота миграции (перенос конфига **связан** с подтверждённым переименованием —
иначе это катастрофа 1.0.3.38 через другую дверь):

```
если eth0 уже есть в /sys/class/net      -> мигрировать (переименовывать нечего)
иначе если SA02M_ROOTFS_BUILD            -> писать канонический конфиг напрямую
иначе если живое переименование удалось  -> мигрировать
иначе (отложено до перезагрузки)         -> DUAL-CONF
```

**DUAL-CONF.** Пишется `eth0.conf` с каноническим содержимым, а `end0.conf`
остаётся с тем же адресом, но со стансой `allow-hotplug end0` вместо `auto end0`.

- Переименование на следующей загрузке **удалось** → `ifup -a` поднимает
  `auto eth0`; `end0.conf` игнорируется (`ifup -a` не трогает `allow-hotplug`), а
  устройства уже нет → `networking.service` чист, упавших юнитов нет. Следующий
  запуск установщика видит `eth0` и удаляет `end0.conf` — окно дублирования ровно
  одна загрузка.
- Переименование **не удалось** → `end0` на месте, hotplug-путь udev поднимает
  его на прежнем адресе → **плата доступна**, а упавший
  `sa02m-iface-canonical.service` называет причину.

Честная цена: одну загрузку адрес живёт в двух файлах. Если в это окно сменить IP
через панель, `apply.cgi` пишет `eth0.conf` (и зеркалит в `end0.conf`, §5), так
что окно закрыто со стороны панели — но на пути отказа переименования плата
вернётся на прежний адрес, если зеркало не применилось.

| Артефакт | Действие |
|---|---|
| `interfaces.d/end{0,1}.conf` | копия в `eth{0,1}.conf` с заменой имени **внутри** файла, затем удаление источника — только под воротами выше |
| `/etc/systemd/network/1{0,1}-{eth,end}{0,1}.link` | `rm -f` **безусловно** |
| `/etc/sa02m_network.conf` | если задан `WATCHDOG_PING_END0/END1` и нет `ETH0/ETH1`-аналога — дописывается аналог с тем же значением. Причина: `fix-eth.sh` выводит имя переменной из **живого** имени интерфейса, поэтому после переименования `WATCHDOG_PING_END0` молча перестаёт читаться. Строка оператора никогда не удаляется |
| `/etc/dhcp/dhclient-exit-hooks.d/eth1-default-route` | перегенерация, только когда файл ещё называет legacy-интерфейс, и только при реальном изменении содержимого |
| `/var/lib/dhcp/dhclient.end1.leases` | **без действия.** dhclient напишет свежий `dhclient.eth1.leases`; старый файл инертен — не гоняйтесь за ним |
| `99-lan-recovery.rules` | **без изменений.** Правила матчат `KERNEL=="eth0"/"eth1"`. На legacy-плате события `add`/`bind` при загрузке несут `end0` и **пропускаются**; после переименования ядро сообщает новое имя, и все последующие `change` (carrier up/down) матчатся. Разрыв в одну загрузку закрывают сам `networking.service` и `net-watchdog` через 60 с. Строки `end0`/`end1` добавлять **нельзя** — они запустят `fix-eth@end0.service`, который работает с `end0.conf` и воюет с миграцией |

**Живое переименование — только по опту.** По умолчанию переименование
откладывается до следующей загрузки: переименование работающего интерфейса
роняет управляющий линк (SSH). Опт-ин: `SA02M_CANONICAL_IFACE_NOW=1` или
`install.sh --canonical-iface-now`. Плата без консольного доступа обязана
использовать значение по умолчанию.

**Инертность бэкапов `<conf>.sa02m-bak` держится на фильтре `.conf`** в
`source /etc/network/interfaces.d/*.conf` (`/etc/network/interfaces`, пишет
`scripts/02-network.sh` — единственный дом этой строки): без фильтра бэкап с
дублирующей стансой сорсится как живой конфиг — механизм 3 в §1.0.

### 3.1 Ремонт `gateway`/`dns-nameservers` установщиком

Установщик намеренно **не перезаписывает** уже существующий `ethN.conf` (иначе
повторный запуск сбросил бы статический IP, заданный оператором, и плата стала
бы недоступна). Следствие, которое до этой версии не закрывал никто: если
сторонний писатель вырезал из стансы `gateway` и `dns-nameservers`, плата
остаётся без маршрута и DNS **навсегда** — ни один запуск установщика этого не
чинит.

`ensure_gw_dns` (`scripts/02-network.sh`) закрывает ровно этот разрыв и является
строго более узкой версией правила слияния панели (§5.2): она умеет **только
дописать отсутствующий ключ**.

| Правило | Поведение |
|---|---|
| `address` / `netmask` | **никогда** не читаются на запись и не изменяются |
| Присутствующее значение `gateway` / `dns-nameservers` | **никогда** не изменяется |
| Закомментированный `#gateway …` | считается **присутствующим** — это осознанное действие человека; ремонт добавляет лишь **отсутствующее** |
| Порядок строк, чужие строки (`hwaddress`, `post-up`, комментарии, `no-auto-down`) | сохраняются дословно и на своих местах |
| Точка вставки | после последней строки `address`/`netmask`/`broadcast`/`network` тела стансы; отступ берётся у строки `address` |
| Не ровно одна станса `iface <ifN> inet` | ничего не пишем + WARN (то же правило, что §5.2 для дубля) |
| Станса не `inet static` | ничего не пишем (маршрутом DHCP владеет сам) |
| Повторный запуск | файл байт в байт прежний, бэкап не снимается (mtime не трогается) |
| `address 192.168.1.136/24` (CIDR, без строки `netmask`) | **поддерживается**: маска берётся из префикса. Это валидная современная станса ifupdown, и объявлять её «непонятной» значило бы молча не чинить исправный конфиг |
| Префикс и строка `netmask` противоречат друг другу | ничего не пишем + WARN |
| Ключ `address`/`netmask` повторяется внутри одной стансы | ничего не пишем + WARN. ifupdown такой конфиг сам считает ошибочным, а для проверки подсети две строки `netmask` — единственный найденный способ протащить шлюз из чужой подсети |

**Проверка подсети обязательна, и весь ремонт fail-closed.** `$GATEWAY`
выводится из варианта платы (`sa02m_default_gw` → `192.168.1.1` / `192.168.0.1`),
а оператор мог задать адрес в другой подсети. Строка `gateway 192.168.1.1` в
стансе с адресом `10.5.0.0/24` роняет следующий `ifup` («Network is
unreachable») → `networking.service` FAILED → класс «плата недоступна» из
§1.0 через новую дверь. То же правило действует и у панели (CHANGELOG 1.0.5.62
отвергает шлюз вне подсети).

- Стансу не удалось разобрать (нет строки `address`, нет маски ни строкой, ни
  префиксом, маска или адрес не разбираются, ключ повторяется, математика
  подсетей недоступна) → **не пишем ничего**, включая `dns-nameservers`.
  Это сознательное сужение относительно «не пишем только gateway»: файл, форму
  которого мы не понимаем, не наш, чтобы его править. Каждая такая ветка обязана
  назвать в WARN то, что она действительно увидела, — журнал установки
  единственная поверхность отказа у этого кода, и сообщение, противоречащее
  файлу, уводит следующего отладчика не туда.
- Станса разобрана, но кандидат в шлюзы **вне её подсети** → `gateway` не
  пишем, WARN с обоими значениями; `dns-nameservers` при этом добавляется —
  строка DNS не может сделать плату недоступной.

Математика подсетей (`ipv4_to_int` / `netmask_is_contiguous` /
`same_ipv4_subnet`) живёт в `scripts/lib.sh`; веб-копия в
`cgi-bin/lib_web_validate.sh` остаётся — другой контекст развёртывания, тот же
приём, что и `first_existing_iface`. Обе стороны закрыты тестами: `subnet-validate`
(веб) и `iface-gw-repair` (установщик).

**Бэкап — `<conf>.sa02m-gwbak`, а не `<conf>.sa02m-bak`.** Второе имя — точка
восстановления панели (§5.4), и запуск установщика не вправе её затирать. Оба
файла инертны благодаря тому же фильтру `.conf`.

**Запись атомарна, и её результат проверяется чтением.** Новое содержимое
собирается во временный файл `<conf>.sa02m-gwtmp.*` **в том же каталоге** (иначе
`mv` пойдёт через границу ФС и перестанет быть атомарным), права и владелец
копируются с оригинала, замена делается `mv` — то есть `rename(2)`: на диске либо
старый файл целиком, либо новый целиком. Оборванная запись (ENOSPC на плате, где
переполненный `/var/log` и был поводом для этой правки) не может оставить
обрезанный `ethN.conf` — плату без адреса. Плата за это — смена inode; она
безопасна, конфиг интерфейса никто не держит открытым, `ifup` читает его заново.

Каждый шаг записи проверяется, и **успех не объявляется, пока файл на диске не
перечитан**: строки `gateway`/`dns-nameservers` ищутся в нём точным сравнением и
**в границах той же стансы**, в которых принималось решение, — одноимённая строка
в соседней стансе не должна ни подтверждать нашу запись, ни откатывать верную.
Не удалось создать временный файл, собрать его целиком, снять бэкап или заменить
конфиг — WARN, файл остаётся прежним, `gateway` считается **не** добавленным.
Если запись не подтвердилась, конфиг откатывается из `.sa02m-gwbak`, и **сам
откат тоже проверяется**: удался — WARN «восстановлен»; не удался — ERR о
НЕОПРЕДЕЛЁННОМ состоянии с обоими путями (конфиг и копия), чтобы человек мог
доделать вручную. Сообщение о восстановлении, которого не было, — та же ложь в
логе, только на один отказ глубже.
Это несущее требование, а не аккуратность: по флагу «шлюз добавлен» ниже
поднимается живой маршрут и пишется resolvconf head, и ложный успех создал бы
head со шлюзом, которого в конфиге нет, — ровно ту патологию, которую
`sa02m_write_resolvconf_head` и снимает.

**Живое применение — только `ip route replace`**, и только когда ремонт реально
добавил шлюз, это не сборка rootfs и маршрута по умолчанию сейчас нет.
`ifup`/`ifdown` здесь запрещены: перезапуск интерфейса рвёт SSH-сессию посреди
установки. Нужно это потому, что `install.sh` запускает `01-system.sh` **до**
`02-network.sh`, и правка только в конфиге оставила бы текущий запуск без DNS.

**Выключатель:** `SA02M_SKIP_GW_REPAIR=1` или `install.sh --no-gw-repair` — для
сегмента, где шлюза нет намеренно.

**Чего этот ремонт НЕ объясняет и не чинит:** наблюдавшийся на стенде **пустой**
`/etc/resolv.conf`. У этого файла есть второй писатель мимо resolvconf
(`etc/ppp/ip-up.d/sa02m-modem`), и репозиторий пустой файл не объясняет.
Ремонт возвращает `dns-nameservers` в стансу, откуда его подхватывает
`ifup` → resolvconf; если после этого `getent hosts` на плате всё ещё не
резолвит — это отдельная нить, а не следствие данной правки.

## 4. `config.cgi` — новый ключ `klogic` (аддитивный)

```json
"klogic": { "present": true, "eth0_hook": true, "eth1_hook": false }
```

| Поле | Тип | Значение |
|---|---|---|
| `present` | boolean | KLogic установлен: `[ -x /home/klogic/klogic-sa02 ]` **или** `[ -f /etc/systemd/system/klogic.service ]` |
| `eth0_hook` | boolean | конфиг `eth0` содержит строку `post-up`/`up` со ссылкой на `/home/klogic/` |
| `eth1_hook` | boolean | то же для `eth1` |

Только boolean, никогда строки. Отсутствие и нечитаемость файла одинаково дают
`false` — **fail closed** в сторону «не утверждать, что KLogic управляет
интерфейсом».

- **Аддитивность.** Все существующие ключи (`eth0`, `eth1`, `timezone`,
  `datetime`, `rtc_datetime`) сохраняют имя, тип и смысл, поэтому старый
  закешированный бандл просто игнорирует `klogic`.
- **Не в `status.cgi`.** `config.cgi` запрашивается один раз на загрузку
  страницы; части `status.cgi` — на скользящем опросе 6–12 с. Файловая проба на
  опрашиваемом эндпоинте нарушила бы ресурсную модель. Добавленная стоимость на
  hot-path опроса — **ноль**; на `config.cgi` — два builtin-теста плюс один форк
  `grep` на интерфейс (~25 % к восьми существующим форкам, один раз на загрузку
  страницы).
- **Авторизация.** `config.cgi` отвечает `{"error":"unauthorized"}` до любой
  пробы, поэтому ключ **никогда** не выдаётся неаутентифицированному клиенту.
- **Инвентарь.** Ключ раскрывает один бит локального инвентаря ПО уже
  аутентифицированному оператору. PII нет, новых потоков данных нет.
- **Особенность прав.** `klogic-install` оставляет `/home/klogic` в режиме 0740
  root, а CGI выполняется под `www-data` (`fcgiwrap.service`), поэтому проба
  `[ -x /home/klogic/klogic-sa02 ]` практически всегда ложна — несущая половина
  этого `ИЛИ` — юнит-файл, читаемый всем.

Соответствующая подпись в интерфейсе («Сеть», по одной на карточку Ethernet):

| Состояние | Текст (RU) | Класс |
|---|---|---|
| `present` и hook есть | «IP-адрес этого интерфейса также задаёт KLogic» | `field-hint` |
| `present`, hook **отсутствует** | «KLogic установлен, но не управляет этим интерфейсом» | `field-hint warn` |

Второе состояние — действенное: это ровно та плата, у которой прежнее сохранение
из панели вырезало hook.

## 5. Шов «панель ↔ сторонний писатель» в `interfaces.d`

**Формат ifupdown не меняется.** Меняется то, что `apply.cgi` теперь
**сохраняет** строки, которых не писал, вместо полной регенерации файла.

### 5.1 Почему это исправление, а не украшение

`post-up`-hook в конфиге — **единственный** механизм применения IP у KLogic:
двоичный файл переписывает `/home/klogic/set-ip0`, а `post-up
/home/klogic/adjust-eth0` выполняет его при каждом `ifup` (ветка `set-ip0` в
вендорском `pre-start` работает только на сборке `klogic-nls`, а не на штатной
`klogic-sa02`). Прежняя регенерация конфига удаляла эту строку, то есть **одно
сохранение из вкладки «Сеть» навсегда и молча отключало управление IP со стороны
KLogic**.

### 5.2 Правило слияния

Управляемый allow-list — единственное, что мы пишем, и потому единственное, что
мы заменяем:

| Управляемые заголовки стансы | Управляемые ключи опций |
|---|---|
| `auto <if>`, `allow-hotplug <if>`, `iface <if> inet <static\|dhcp>` | `address`, `netmask`, `gateway`, `dns-nameservers`, `metric` |

Всё остальное — чужое и переносится **дословно**, в исходном порядке. Порядок
записи: чужие строки до стансы → заголовок → строка `iface` → управляемые опции →
чужие строки внутри стансы.

- **Идемпотентность.** Два сохранения с одинаковым вводом дают побайтово
  одинаковый файл.
- **Границы (анти-амплификация).** Максимум **64** чужих строки, суммарно **8 КБ**,
  каждая — не длиннее **512** байт; `\r` вырезается; строка с управляющим
  символом (кроме табуляции) отбрасывается. Превышение логируется счётчиком.
- **Битый / правленный руками конфиг.** Если файл нечитаем, не содержит строки
  `iface <if> inet …` или содержит **больше одной** стансы для этого интерфейса —
  слияние не выполняется: файл копируется в `<conf>.sa02m-bak`, причина пишется в
  `/var/log/sa02m_install.log`, дальше идёт чистая регенерация по шаблону. Неверное
  слияние в сетевой конфиг хуже чистой регенерации с восстановимым бэкапом.
  Следствие: станса IPv6 в таком файле окажется только в бэкапе (IPv6 на этих
  платах отключён вендорским образом — зафиксировано, не исправляется).
- **Бэкап на каждом разрушающем пути**, включая отключение Ethernet № 2:
  `<conf>.sa02m-bak`, одно поколение, без накопления истории.
- **Отключение Ethernet № 2 роняет вендорский hook.** Восстановление — только из
  `<conf>.sa02m-bak`.

### 5.3 Граница безопасности (не расширена)

- Сохраняемое содержимое происходит **только** из существующего файла, которым
  владеет root в каталоге root, и записать который можно лишь через закреплённый
  хелпер `sa02m-iface-conf-write.sh` (§5.4) за аутентификацией. **Ни одно значение
  запроса не может создать, дополнить или повлиять на сохраняемую строку**: слияние
  читает старый файл и форму раздельно, а значения формы попадают только в
  управляемые ключи.
- Существующая allow-list-валидация (`valid_ipv4`, `valid_ipv4_list`,
  `reject_bad_input`) не тронута и по-прежнему выполняется до любой записи.
- Уровень доверия **не повышен**: сохраняемая `post-up` уже лежала в файле и уже
  выполнялась ifupdown от root при каждом `ifup`. Прежнее вырезание не было мерой
  защиты — это была молчаливая ошибка доступности; кто мог записать этот файл, мог
  записать что угодно в `/etc`.
- Что путь сохранения **добавляет**: границы длины и количества, отбрасывание
  управляющих символов, вырезание `\r`, отказ сохранять заголовки станс
  (сохранённая строка не может изменить, какой интерфейс настраивает станса) и
  переход с `echo -e` на `printf '%s\n'`, который убирает интерпретацию
  backslash-escape из пути записи целиком.

### 5.4 Правило соседа (замещает наивное удаление соседнего конфига)

Прежний код после записи удалял соседний конфиг. В окне миграции это **активно
неверно**: на мигрированной, но ещё не перезагруженной плате живым остаётся
`end0`, `resolve_lan_iface` предпочитает **живое** имя, поэтому сохранение писало
`end0.conf` и **удаляло `eth0.conf`**, отменяя миграцию; на следующей загрузке
переименованный `eth0` не нашёл бы конфига и поднялся бы без адреса.

Действующее правило:

```
всегда:                       пишем eth{0,1}.conf   (auto/allow-hotplug + управляемые + сохранённые)
если /sys/class/net/end{0,1}: пишем end{0,1}.conf   (allow-hotplug + те же управляемые + те же сохранённые)
                              и бросаем ifdown/ifup на ЖИВОЙ (legacy) интерфейс
иначе:                        бэкап + вывод legacy-конфига из строя
                              и бросаем ifdown/ifup на канонический интерфейс
```

`allow-hotplug` (не `auto`) на legacy-зеркале — обязателен: после удачного
переименования `ifup -a` его игнорирует и `networking.service` остаётся чистым.

**Удаление файла — через закреплённый хелпер (с 1.0.5.54).** Прямой `rm` у
`www-data` нет и не появится; sudoers (`scripts/03-webserver.sh`) выдаёт ровно
`/usr/local/sbin/sa02m-conf-rm.sh` — единственную rm-способность панели:
allow-list из четырёх имён LAN-конфигов (`case`, не regex), отказ по symlink,
бэкап `.sa02m-bak` перед удалением, идемпотентный выход. `lan_conf_retire`
пробует хелпер первым; там, где хелпера/строки sudoers ещё нет (деплой до
1.0.5.54), действует прежний путь: бэкап плюс перезапись комментариями —
файл без стансы игнорируется `ifup -a`, установщик удаляет его при следующем
запуске (и не переносит содержимое конфига без стансы). Сам бэкап
`<conf>.sa02m-bak` инертен **только благодаря фильтру `.conf`** в строке
`source` (§3, дом — `scripts/02-network.sh`): без него бэкап сорсится как
живой конфиг (механизм 3 в §1.0).

**Запись файла — тоже через закреплённый хелпер (с 1.0.6.10, аудит B1).** Прямого
`tee` у `www-data` больше нет: и сам конфиг, и его бэкап `.sa02m-bak` пишутся через
`/usr/local/sbin/sa02m-iface-conf-write.sh` — то же семейство, что `sa02m-conf-rm.sh`:
`case`-allow-list из четырёх имён LAN-конфигов и их `.sa02m-bak`, отказ по symlink.
Прежняя строка sudoers давала `www-data` raw `/usr/bin/tee` — произвольную запись
любого файла от root (эскалация до root без пароля root).

**Пиновки пути МАЛО — хелпер валидирует СОДЕРЖИМОГО живого `.conf`** (round-2 B1):
`www-data` может вызвать хелпер напрямую, в обход валидации `apply.cgi`, а `eth0.conf`
сорсится в `/etc/network/interfaces` и пиннованный `ifup eth0` выполнит любой
`pre-up`/`post-up` из него ОТ ROOT. Поэтому хелпер разбирает stdin построчно и
допускает только грамматику ifupdown, которую реально пишут панель и установщик:
комментарии, пустые строки, `auto`/`allow-hotplug`/`no-auto-down`,
`iface <имя> inet {static|dhcp|manual}`, `address/netmask/gateway/broadcast/network`,
`dns-nameservers`, `dns-search/dns-domain`, `metric`/`mtu`, `hwaddress ether <MAC>`.
**exec-директивы** (`pre-up`/`up`/`post-up`/`pre-down`/`down`/`post-down`) и
`source`/`mapping` — ТОЛЬКО в перечисленных точных формах, параметризованных лишь
уже-валидированным IPv4 / allow-list-именем интерфейса / целым:
- `(post-up|up) /home/klogic/adjust-<eth0|eth1|end0|end1>` [` || /bin/true`|` || true`]
  — единственный механизм применения IP у KLogic (§5.3 выше);
- `post-up ip route replace default via <IPv4> dev <if> metric <int>` [` || true`]
  — hook установщика для LAN1 DHCP (`scripts/02-network.sh`).

Любой другой хук, любое незнакомое ключевое слово, любой `source`/`mapping`, любой
управляющий символ (кроме табуляции) → **отказ без записи (fail-closed)**. Следствие
для §5.3 (перенос чужих строк): чужой `post-up`, не совпадающий с этими формами,
теперь НЕ переносится — сохранение отклоняется, старый конфиг остаётся (в этом
продукте единственные легитимные хуки — klogic и install-route, оба в allow-list).
Бэкапы `.sa02m-bak` инертны (фильтр `.conf` в `source` их не сорсит), поэтому им
валидация содержимого не применяется — только allow-list пути и отказ по symlink.

Строка sudoers теперь одна на всё (`etc/sudoers.d/sa02m-www`, ставится целиком во всех
путях установки — переустановка убирает старую опасную строку). Гейт:
`sudoers-pin-contract` (RED→GREEN, включая composition-кейс с `pre-up /bin/sh …`).

### 5.5 Что этим НЕ закрыто

- Панель **не восстанавливает** вырезанный hook и не пишет вендорский код в
  конфиг из веб-формы — это возможность, от которой отказались сознательно.
  Восстановление вручную: вернуть в `/etc/network/interfaces.d/eth0.conf` строку
  `post-up /home/klogic/adjust-eth0 || /bin/true` (или восстановить файл из
  `<conf>.sa02m-bak`) и выполнить `ifdown eth0 && ifup eth0`.
- `set-route` в KLogic делает `route del default` и может воевать с `gateway`
  панели и с управлением метриками в `inet-failover.sh`. Вне рамок.
- **Живая гонка** «сохранение из панели ↔ запись KLogic» присуща двум независимым
  писателям и с нашей стороны не закрывается. Блокировка сознательно **не**
  добавлена: два одновременных сохранения сети от одного аутентифицированного
  оператора нереалистичны, а зависший lock на CGI, который могут убить посреди
  запроса, — худший отказ (он заблокирует все будущие сохранения).
- **VLAN-подынтерфейсы.** В таблице KLogic есть также `eth0.1`/`eth0.2`. Эта
  версия их не создаёт и не мигрирует: конфигурация KLogic, которой нужны VLAN,
  работать не будет.
- Опция `metric` входит в управляемый allow-list, поэтому сохранение из панели
  убирает строку `metric` из конфига (как и раньше). `post-up`-строка установщика
  с маршрутом по умолчанию при этом сохраняется.
- Прежний подход `.tmp/klogic/safe/` (переименование **скриптов** KLogic в
  `end0`) **замещён**: он не достаёт до вкомпилированной таблицы `.rodata`, а
  вендорский `pre-start` восстанавливает двоичный файл из `klogic.upd`/`klogic.tar`
  при каждом обновлении. На такой плате вендорскую поставку нужно разложить
  заново, предварительно сверив строки, роняющие линк, с реальной топологией.

## 6. Смежные компоненты

- **`hardpy_tests`** (объявленный сосед в `.ai-dev/components.json`) читает MAC
  платы с fallback `end0,eth0` (`lib/sa02m_ssh.py:90`,
  `lib/stand_config.py:318`, `lib/license_activation.py:593`,
  `deploy/etc/default/sa02m-test:72`). Канонизация его **не ломает**:
  переименование интерфейса не меняет MAC, а fallback находит `eth0`. Изменения в
  соседнем репозитории не требуются — проверено, чтобы следующий читатель не
  выводил это заново.
- **`cloud`** — сетевых имён интерфейсов не касается.
- **`docs/contracts/boot-network-dns.md`** — что происходит **после**
  переименования: uevent от него доходит до `ifupdown-hotplug`, тот поднимает
  `ifup@eth0` до согласования carrier, и упавший `ifup` оставляет плату без
  DNS. Ожидание carrier и пересборка резолвера живут там; здесь про них
  ничего не дублируется.

## 7. Что проверяет статический гейт

Строка реестра `iface-naming-contract`
(`.ai-dev/quality/checks/iface-naming-contract.sh`, бит `build`):

1. Множество файлов **кода**, упоминающих `end0`/`end1`, совпадает с ведомостью
   слоя совместимости — новый потребитель, захардкодивший legacy-имя, роняет
   гейт; ведомость non-vacuous в обе стороны (устаревшая запись тоже роняет).
2. `scripts/02-network.sh` устанавливает и включает
   `sa02m-iface-canonical.service`.
3. `apply.cgi` не содержит `echo -e` (регрессия F6) и пишет конфиги только через
   две известные функции.
4. Пины systemd-упорядочивания и ворот §1.0 (каждый именует симптом, который
   предотвращает):
   - юнит объявляет `Before=` `networking.service` (симптом 1.0.3.38
     `Cannot find device`);
   - юнит объявляет `After=` **и** `Wants=` для `systemd-udevd.service` и
     `systemd-udev-trigger.service` (потеря → возвращается boot-0 no-op до
     udevd);
   - юнит **не** содержит `Wants=systemd-udev-settle` (возврат → 120-секундный
     блокирующий settle всей очереди);
   - `etc/fix-eth@.service` объявляет `After=` `networking.service` (потеря →
     возвращается гонка двойного `ifup` / `File exists`);
   - скрипт содержит функцию `udev_initialized` и вызывает её в
     `canonicalize_pair` (удаление ворот → boot-0 класс возвращается молча);
   - `scripts/02-network.sh` пишет `source /etc/network/interfaces.d/*.conf`
     и не содержит строки с нефильтрованным `*` (расширение глоба → бэкапы
     `.sa02m-bak` сорсятся как живой конфиг — механизм 3 в §1.0).
5. Пины механизма 4 (событийный перезапуск, §1.0):
   - `etc/98-sa02m-iface-canonical.rules` существует, матчит `end*` на
     `add|move` и стартует `sa02m-iface-canonical-retry.service` с
     `--no-block` (потеря → мс-гонка db-записи снова открыта);
   - `etc/systemd/system/sa02m-iface-canonical-retry.service` существует,
     объявляет `Before=networking.service` и **не** содержит
     `[Install]`/`WantedBy` (юнит только событийный);
   - `99-lan-recovery.rules` по-прежнему **не** содержит строк `end*`
     (появление → `fix-eth@end0` против legacy-имени);
   - `etc/fix-eth.sh` сбрасывает счётчик `link_cycle_count` при живом
     carrier (потеря → исчерпанный бюджет блокирует восстановление линка до
     перезагрузки — ночной симптом eth1 2026-07-29/30);
   - `scripts/02-network.sh` устанавливает оба новых файла.

Функциональные регрессии — три отдельные строки реестра (все на бите `build`):
