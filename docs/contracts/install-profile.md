# Контракт: профиль установки платы (`/etc/sa02m_install_profile.conf`)

Дом гарантии «модуль, который плате не нужен, на неё больше не приезжает»:
формат файла профиля, поддерживаемые модули, кто его пишет и читает, какие пути
доставки его соблюдают, что делает удаление и где честные пределы. Код — один
файл `etc/sa02m-install-profile-lib.sh` (на плате
`/usr/local/lib/sa02m-install-profile-lib.sh`): таблица модулей, чтение, запись,
удаление. Машинная грамматика (ключи, значения, пути, флаги) — латиницей
(`PROTOCOL.md` invariant 5); пояснения — по `docLanguage: ru`.

Соседи, с которыми профиль не смешивается: `/etc/sa02m_stacks.conf` — политика
сторонних стеков (Node-RED, CODESYS, MPLC, Docker, KLogic;
`docs/contracts/installer-refresh-policy.md`), `/etc/sa02m_hw_variant.conf` —
вариант железа. Разовый пропуск `SA02M_SKIP_<ID>=1` остаётся разовым: ничего не
записывает и ничего не удаляет. Сравнение трёх механизмов и рецепт «плата без
модуля» — `docs/deployment.md`.

## 1. Гарантии

| ID | Гарантия |
|---|---|
| G-P1 | Модуль с `MODULE_<ID>=skip` не ставится, не обновляется и не доставляется заново ни одним путём доставки из §4. |
| G-P2 | `install.sh` удаляет уже стоящий пропущенный модуль: код, юниты, грант sudoers, служебные файлы. Данные оператора остаются; `install.sh --keep-module <ID>` возвращает модуль, и он продолжает работать со старыми данными. |
| G-P3 | Профиль — файл root, который никогда не исполняется (`source`) и не перезаписывается OTA: подмена может только вернуть поведение «файла нет», но не расширить его. |

## 2. Модули

Поддерживаемые ID (таблица в библиотеке — `sa02m_profile_ids`; гейт сверяет
этот список с кодом):

| ID | Что не доставляется и удаляется | Что остаётся (данные) |
|---|---|---|
| `AGENT_API` | `/opt/sa02m-agent-api/`; хелперы `/usr/local/sbin/sa02m-agent-api-ctl.sh`, `sa02m-agent-token-store.sh`, `sa02m-agent-root-cap.sh`, `sa02m-agent-root-exec.sh`, `sa02m-rules-store-apply.sh`, `sa02m-user-unit.sh`, `sa02m-agent-journal.sh`; юниты `/etc/systemd/system/sa02m-agent-api.service`, `sa02m-user@.service`; `/etc/sudoers.d/sa02m-agent-api`; `/etc/tmpfiles.d/sa02m-agent-api.conf`; только установщик: `/etc/logrotate.d/sa02m-agent-api`. Запущенные программы агентов `sa02m-user@…` останавливаются и выключаются. | токены и записи root-доступа `/etc/sa02m-agent-api/`, программы агентов `/opt/sa02m-user/`, журналы `/var/log/sa02m-agent-api/`, учётная запись `sa02m-user` |

Строка таблицы появляется только полной: каждый путь, который пишет модуль
установщика (`scripts/13-agent-api.sh`), — либо доставляется OTA и стоит в
«не доставляется», либо пишется только установщиком, либо данные. Ни одна
строка не может назвать `/var/www/`, `/usr/local/libexec/`, `/etc/nginx/` или
`/usr/local/lib/`: модуль убирает только свои файлы, никогда раннер, site-файл,
веб-дерево или общую библиотеку.

Остальные продуктовые модули предусмотрены, но не поддержаны — у каждого есть
причина:

| Модуль | Почему пока нет |
|---|---|
| `DEVICES` | шлюз здоровья OTA требует активный `sa02m-devices-api` (`etc/sa02m-update-runner.sh`, `health.units_active`) |
| `MQTT` | от брокера и моста зависят устройства и мосты |
| `ALICE`, `RULES` | их пакеты импортируют HomeKit и облачные сценарии |
| `HOMEKIT`, `HOMECONNECT` | уже ставятся только по флагу (`--with-homekit`, `--with-homeconnect`); OTA при этом всё ещё привозит их файлы `/opt` и юниты |
| `GATEWAY` | блокеров не найдено, но не проверено — не заявляется |
| `VPLC` | этот репозиторий рантайм vPLC не ставит (`docs/contracts/vplc-page-seam.md` §7) |

## 3. Файл

`/etc/sa02m_install_profile.conf`, `root:root 0644`. Ровно такие строки:

```
# SA-02m install profile: product modules this board does not carry. Written by install.sh --skip-module/--keep-module; hand-editable.
# MODULE_<ID>=skip|keep   skip = never installed, refreshed or delivered by OTA; install.sh removes it (data kept).
MODULE_AGENT_API=skip
```

- **Чтение** — `awk` по ключу `MODULE_<ID>`, никогда `source`. Нет файла, нет
  ключа, значение не `skip` (мусор, CRLF вокруг `skip` допустим) ⇒ `keep`.
- **Запись** — только `install.sh` (§5): весь файл заново (шапка + каждый
  поддерживаемый ID по порядку), рядом временный файл, `chmod 0644`, `mv -f`;
  то же значение — файл не трогается. Ни один CGI профиль не пишет. При сборке
  образа (`SA02M_ROOTFS_BUILD`) файл не пишется — образ профиль не запекает.
- **OTA его не трогает**: `/etc/sa02m_*.conf` — в `PRESERVE_PATHS` раннера и в
  `never_deploy` карты пакета.
- Сброс к заводским профиль не стирает (это решение об установке, как
  `stacks.conf`). Веб-резервная копия его содержит (`/etc/sa02m_*.conf`,
  `etc/sa02m-web-backup.sh`), восстановление записывает обратно — см. §7.

## 4. Пути доставки, которые соблюдают профиль

| Путь | Где фильтр | Чем подтверждено |
|---|---|---|
| полная установка и `install.sh --refresh` (и офлайн-обёртка, она запускает `install.sh`) | `install.sh` экспортирует `SA02M_SKIP_<ID>=1` для каждого `skip` из файла — модуль не запускается | гейт `install-profile` P5 |
| GitHub-OTA и подписанный офлайн-пакет, применяемые раннером ≥ 1.0.7.2 | раннер: `prepare_profile_excludes` один раз на транзакцию под `update.lock` пишет `meta/profile.exclude`; единственный цикл `apply_deploy_items`, через который проходят оба манифеста, не пишет такие пункты, логирует `apply: profile skip <dst>`; `files_done == files_total` по оставшимся | P3, P4 |
| `scripts/update-www-only.sh` | цикл хелперов и цикл sudoers пропускают пути модуля | P9 |
| старый путь `sa02m-web-update-apply` (rsync, только где раннера нет) | цикл хелперов пропускает пути модуля; библиотека берётся из клонированного дерева | P9 |

Новый путь доставки без такой проверки — находка ревью.

**Профиль есть, а читателя нет** (библиотеку удалили руками или профиль
написан руками на старой плате): раннер отказывает `E_COMPAT` «install profile
present but its reader is missing: run install.sh --refresh» и ничего не
ставит. Решение Оператора 2026-10-14 (Q5): гарантия важнее обновления.

## 5. Установщик

```
sudo ./install.sh --refresh --skip-module AGENT_API   # записать skip и удалить модуль
sudo ./install.sh --refresh --keep-module AGENT_API   # записать keep и поставить модуль обратно
```

- Флаги повторяемые; неизвестный ID или один ID в обоих списках ⇒ `ERR`,
  выход 2, ничего не записано.
- Каждый `skip` из файла ⇒ модуль в этом прогоне не запускается (строка
  `Профиль установки: модуль <ID> не ставится …` в журнале, строка `Профиль:` в
  шапке). `--keep-module` действует уже в этом прогоне.
- **Удаление** (`sa02m_profile_enforce` сразу после блока модуля) — только когда
  в ФАЙЛЕ `skip` и на диске что-то от модуля есть; на чистой плате — одна строка
  «удалять нечего», ни одного вызова `systemctl`. Под `update.lock`
  (`flock -w 300`) — не пересекается с OTA и сбросом к заводским; не дождались
  ⇒ `WARN`, ничего не удалено, повторить `install.sh --refresh`. Порядок:
  грант sudoers (затем `visudo -c`), остановка и выключение юнитов (у шаблона
  `sa02m-user@.service` — каждый экземпляр), файлы, каталог кода (только
  буквальный путь таблицы), `daemon-reload`. Любой сбой ⇒ `WARN` с путём,
  удаление продолжается, установка не прерывается. Глаголы `systemctl` — только
  сужающие (`stop`, `disable`, `daemon-reload`).

## 6. Панель

Профиль не пишется из панели. Карточка модуля на плате без него говорит
«Не установлен на этой плате» и скрывает форму; для `AGENT_API` ответ CGI —
`docs/contracts/agent-api.md` «Плата без модуля». Маршруты nginx модуля
(`/api/v1/`, `/health`, `/mcp`) остаются в site-файле на каждой плате: один
шаблон для всех путей доставки, неиспользуемая локация ничего не стоит, нет
сокета — 502 за той же авторизацией.

## 7. Честные пределы

- OTA, которое **привозит** 1.0.7.2, применяет прежний раннер платы — без
  фильтра. Записать профиль может только `install.sh` ≥ 1.0.7.2, который ставит
  и новый раннер, поэтому окно — профиль, написанный руками на старой плате, или
  откат ниже 1.0.7.2.
- Перепрошивка образа профиль не переносит — его надо записать снова (или
  восстановить веб-копию, в которой он есть).
- Профиль, вернувшийся из веб-копии на плату, где модуль ещё стоит, сразу
  включает фильтр OTA, но сам модуль не удаляет: до следующего
  `install.sh --refresh` его файлы остаются и OTA их больше не обновляет.
- На плате фильтр OTA впервые наблюдаем на обновлении ПОСЛЕ 1.0.7.2
  (`grep 'profile skip' /var/lib/sa02m-update/update.log`); до этого
  доказательство — песочница гейта.

## 8. Проверка контракта

Строка реестра `install-profile` (`scripts/dev/test-install-profile.sh`): P1
чтение (в том числе строка-инъекция читается `keep` и ничего не исполняет); P2
запись (точные байты, no-op, отказ на неверный ID, сборка образа); P3 фильтр в
извлечённом `apply_deploy_items`; P4 `prepare_profile_excludes` и отказ
`E_COMPAT`; P5 флаги и порядок в `install.sh`; P6 удаление в песочнице с
заглушками `systemctl`/`flock`/`visudo`; P7 полнота и допустимость таблицы;
P8 библиотека доставляется обоими OTA-путями в `/usr/local/lib/`; P9 проверки в
`update-www-only.sh` и старом пути; P10 таблица §2 == `sa02m_profile_ids`; P11
ответ CGI агента без модуля. На плате — сценарий в `docs/deployment.md`.
