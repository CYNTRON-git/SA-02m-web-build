# Контракт: API истории устройств (ДТВ / СЭ-02м-3 / Carel / MTD)

Домашний адрес контракта на **чтение архива устройств по HTTP** — графики,
сводка СЭ за период (кВт·ч и рубли) и выгрузка в Excel/TSV — для любого
потребителя вне вкладки «Устройства»: страница установки vPLC, агентский API
(`devices.history` / `devices.summary`, `docs/contracts/agent-api.md`),
скрипты интегратора. Машинная грамматика (маршруты, параметры, ключи JSON) —
на английском (`PROTOCOL.md` invariant 5); пояснения — на русском
(`docLanguage: ru`).

Здесь закреплена **форма** ответа и правила разбора запроса. Ветка
`kind=mr` (каналы AI модулей MR-02m) — в `docs/contracts/devices-mr-history.md`,
здесь не повторяется. Архив Carel (широкая таблица, группа состояния,
max-корзина, журнал фронтов) — `docs/contracts/carel-ahu.md` §7; здесь — только
то, что из него видно по HTTP.

Реализация: `opt/sa02m-devices/sa02m_devices/api.py` (маршруты, `handle_history`,
`handle_summary`, `_range_key_from_qs`, `_handle_export`, проверка сессии),
`history_query.py` (`history`, `history_batch`, `history_carel`,
`history_carel_batch`, `period_summary_ce`), `history_ranges.py` (окна и
корзины), `history_metrics.py` (каталог метрик и групп), `history_export.py`
(выгрузка), `history_ce_roll.py` (столбики мощности/энергии СЭ). UI —
`www/network_config/static/js/devices.js`.

Валидирующий тест: `opt/sa02m-devices/tests/test_history_api_contract.py` —
он **читает этот файл** и сверяет три таблицы ниже (окна, группы, ключи сводки)
с кодом; расхождение документа и кода — красный тест (§ «Проверка контракта»).

## 1. Транспорт и авторизация

Демон `sa02m-devices-api` слушает unix-сокет `/run/sa02m-devices/api.sock`
(и, только на плате после одного GitHub-OTA со старым файлом сайта nginx,
`127.0.0.1:8765` — правило `STAND_API_TCP_COMPAT` в шапке `api.py`). Снаружи
маршруты доступны через nginx `/api/devices*` (`etc/nginx/network_config.conf`).

- **Каждый** маршрут ниже требует живую сессию панели: cookie `session_token`,
  проверяемую по тому же хранилищу сессий, что у CGI и прошивальщика
  (`websession.check_session_store`). Проверку делает **сам демон, на каждом
  слушателе**; `auth_request` nginx перед ним — дополнительная защита, а не
  гарантия. **Обхода для localhost нет**: запрос с `127.0.0.1` или из сокета без
  сессии получает тот же отказ.
- Отказ — настоящий HTTP `401` с телом `{"ok":false,"error":"unauthorized"}`
  (идиома слоя демонов, а не CGI-идиома «200 + ok:false» —
  `docs/agent-rules/web-code-rigor.md`).
- Все маршруты этого контракта — `GET`; токен `X-SA02M-CSRF` им не нужен (он
  нужен только POST демона — `docs/decisions/selective-csrf-policy.md` «Демоны»).
- Без авторизации отвечает только `GET /api/health` — данных он не несёт.

## 2. Маршруты

| Маршрут | Что отдаёт |
|---|---|
| `GET /api/devices/history` | ряды одной метрики, группы метрик или Carel (§5) |
| `GET /api/devices/history/summary` | сводка СЭ за период: средняя мощность, ΔE, стоимость (§6) |
| `GET /api/devices/history/export` | файл `.xlsx` (по умолчанию) или `.txt` (TSV) (§7) |

Неизвестный путь — HTTP `404` `{"ok":false,"error":"not found"}`.

## 3. Параметры запроса

Все параметры — строка запроса; повтор ключа — берётся первое значение, края
обрезаются от пробелов.

| Параметр | Маршруты | Смысл |
|---|---|---|
| `kind` | history, export | `mr` — контракт MR; `carel` — ветка Carel (§5.3); любое другое значение игнорируется |
| `metric` | history, export | id метрики из `METRICS` (`history_metrics.py`); при `kind=carel` — имя **без** префикса `ahu_` (`supply_temp`) |
| `group` | history, export | группа из таблицы §4.2; непустой `group` важнее `metric` |
| `range` | все | ключ окна из таблицы §4.1; по умолчанию `1h` |
| `window_s` | все | произвольное окно в секундах; важнее `range` (§4.1) |
| `device_id` | все | id устройства (`dtv-COM4-3`, `ce02m3-COM2-14`, `carel-COM3-1`, `carel-tcp-<a_b_c_d>-<addr>`, …); без него берётся первое по алфавиту устройство, у которого в окне есть строки |
| `kwh_rub` | summary | тариф, ₽/кВт·ч; десятичная запятая допустима (`10,5`) |
| `format` | export | `xlsx` (по умолчанию) или `txt` / `tsv` / `text` |

Порядок разбора `/history`: `kind=mr` → контракт MR; `kind=carel` → §5.3;
иначе непустой `group` → §5.2; иначе `metric` → §5.1; иначе HTTP `400` (§8).

`device_id` не проверяется по форме: он передаётся в SQL только как связанный
параметр; неизвестный id даёт пустые `series`, а не ошибку.

## 4. Окна и группы

### 4.1. Ключи `range` и корзины

Дом ключей и чисел — `RANGES` и `EXPORT_BUCKET_S` в
`opt/sa02m-devices/sa02m_devices/history_ranges.py`. Ниже — их копия для
потребителя; тест сверяет её с кодом ключ в ключ и число в число.

<!-- contract:ranges:begin -->
| `range` | окно, с | корзина графика, с | корзина выгрузки, с |
|---|---|---|---|
| `1h` | 3600 | 5 | 60 |
| `6h` | 21600 | 30 | 1800 |
| `24h` | 86400 | 120 | 3600 |
| `7d` | 604800 | 600 | 86400 |
| `30d` | 2592000 | 3600 | 86400 |
| `mtd` | календарь | 3600 | 86400 |
| `month` | календарь | 86400 | 86400 |
<!-- contract:ranges:end -->

- Окно заканчивается «сейчас» и длится указанное число секунд. «Календарь»:
  `mtd` — с 1-го числа текущего месяца 00:00 местного времени до сейчас;
  `month` — весь предыдущий календарный месяц. Часовой пояс — `STAND_TZ`
  (по умолчанию `Europe/Moscow`).
- **Неизвестный ключ `range` молча заменяется на `1h`.** Ответ всегда несёт
  фактический ключ в поле `range` — потребитель сверяет его со своим запросом.
- `window_s` превращается в токен `w:<секунды>` (`custom_range_key`), и дальше
  этот токен идёт везде, где стоит ключ `range`, включая поле `range` ответа.
  Значение зажимается в `[60, 2592000]` (1 мин … 30 сут); нечисловое значение
  даёт `w:60`. Корзина графика — окно/400, выгрузки — окно/200 (не меньше 60 с),
  обе округлены **вверх** до ступени из `_BUCKET_STEPS` того же файла.
- Одиночные графики `metric=power` и `metric=energy_kwh_import` (§5.1) берут
  ширину столбика не из этой таблицы, а из `ce_chart_bucket_s`
  (`history_ce_roll.py`) и сообщают её в поле `bucket_s`.

### 4.2. Группы

Дом — `HISTORY_GROUPS` в `opt/sa02m-devices/sa02m_devices/history_metrics.py`;
ярлык, единица и точность каждой метрики — там же (`METRICS`) и приходят в
каждом ответе (`label`, `unit`, `decimals`). Порядок метрик в ответе группы —
порядок этой таблицы.

<!-- contract:groups:begin -->
| `group` | `device` | метрики (порядок ответа) |
|---|---|---|
| `climate` | `dtv` | `room_temp`, `humidity`, `eco2_ppm`, `tvoc_mg_m3`, `pressure_mmhg`, `light_pct`, `presence` |
| `energy` | `ce` | `voltage`, `current`, `power`, `frequency_hz`, `energy_kwh_import` |
| `ahu` | `carel` | `ahu_supply_temp`, `ahu_return_water_temp`, `ahu_room_temp`, `ahu_outdoor_temp`, `ahu_setpoint`, `ahu_heat_valve`, `ahu_fan_supply`, `ahu_fan_exhaust`, `ahu_fan_step`, `ahu_alarm`, `ahu_alarm_count`, `ahu_plant_state`, `ahu_unit_on` |
| `mtd` | `mtd` | `mtd_illuminance`, `mtd_target_distance`, `mtd_presence` |
<!-- contract:groups:end -->

`group=ahu` отдаёт Carel с **префиксными** id и без журнала событий — это
общий движок как есть. Для Carel предпочтительна ветка `kind=carel` (§5.3):
имена без префикса, только снятые пробы, плюс `events[]`.

## 5. Ответы `/api/devices/history`

Общее для всех форм:

- `t0`, `t1` — границы окна, секунды epoch (float); `t0_ms`, `t1_ms` — то же в
  миллисекундах (int).
- Ряд (`series[]`): `{"field", "label", "points"}`, `points` —
  `[[ts_ms, value], …]` по возрастанию времени, `ts_ms` — начало корзины в
  миллисекундах epoch, `value` — агрегат корзины (среднее; максимум у метрик с
  `agg: "max"` в `METRICS`), округлённый до `decimals`. Ряд без единой точки
  **отсутствует** в массиве (а не присутствует пустым).
- В каждый успешный JSON-ответ демон добавляет сведения о носителе архива —
  ровно эти ключи:

<!-- contract:storage-keys:begin -->
`history_backend`, `history_mount`, `history_db_dir`, `history_db_path`, `history_free_bytes`, `history_fstype`, `history_archives_count`
<!-- contract:storage-keys:end -->

### 5.1. Одна метрика (`metric=<id>`, без `group`)

`{"ok":true, "metric", "label", "unit", "decimals", "device", "device_id",
"range", "t0", "t1", "t0_ms", "t1_ms", "series"}` + ключи носителя.
`device` — `dtv` / `ce` / `carel` / `mtd`; `device_id` — устройство, которое
реально прочитано (при пустом запросе — выбранное автоматически).

Для `metric=power` и `metric=energy_kwh_import` добавлены `bucket_s` (ширина
столбика, с), `prepared: true` (точки уже сведены в корзины — повторно не
группировать) и `value_kind`: `"avg"` у мощности (средняя мощность корзины, Вт)
и `"delta"` у энергии (**приращение** счётчика за корзину, а не показание).

### 5.2. Группа (`group=<имя>`)

`{"ok":true, "range", "group", "device_id", "t0", "t1", "t0_ms", "t1_ms",
"metrics", "errors"}` + ключи носителя.

- `device_id` верхнего уровня — **запрошенный** (может быть `""`); фактически
  прочитанное устройство — в `metrics[].device_id`.
- `metrics[]` — по одному элементу на каждую метрику группы, в порядке §4.2,
  даже без точек: `{"metric", "label", "unit", "decimals", "device",
  "device_id", "series"}`; у метрики, которую не удалось прочитать, ещё
  `"error"`, а строка `"<id>: <причина>"` — в `errors[]`.
- В группе `energy` метрики `power` и `energy_kwh_import` идут общим движком на
  корзине графика §4.1 (средние значения корзины), а не столбиками §5.1.

### 5.3. Carel (`kind=carel`)

С `metric=<имя без префикса>` — форма §5.1 (`metric` без префикса, у каждого ряда
ещё `unit`). Без `metric` — обзор:

`{"ok":true, "range", "t0", "t1", "t0_ms", "t1_ms", "group":"all",
"device":"carel", "device_id", "metrics"}` + ключи носителя, без `errors`.

- `metrics[].metric` — имена колонок архива Carel (`CAREL_COLUMNS`:
  `history_metrics.py`, перечень — `carel-ahu.md` §7) **без** префикса `ahu_`;
  у каждого ряда есть `unit`.
- Метрика без единой точки в окне (неукомплектованная проба) в `metrics[]`
  **отсутствует**.
- `device_id` — фактически прочитанное устройство.
- В обоих видах ответа добавлены `events[]` — строки журнала Carel того же
  устройства в окне `t0..t1`, **от старых к новым**, не больше 500 (при
  переполнении остаются 500 самых новых), — и `event_kinds`:
  `["carel_alarm_on", "carel_alarm_off", "carel_plant_state"]`. Строка:
  `{"id", "ts", "ts_label", "device_id", "kind", "phase", "port_num", "addr",
  "value", "ref_value", "message"}`; смысл видов — `carel-ahu.md` §7.

## 6. Сводка `/api/devices/history/summary`

Только СЭ-02м-3 (`ce_samples`). Параметры — `range`/`window_s`, `device_id`,
`kwh_rub`.

<!-- contract:summary:begin -->
| Ключ | Тип | Смысл |
|---|---|---|
| `ok` | `true` | — |
| `device` | `"ce"` | вид устройства |
| `device_id` | string | прочитанное устройство (`""`, если в окне нет строк) |
| `range` | string | фактический ключ окна (§4.1) |
| `t0` | number | начало окна, с epoch |
| `t1` | number | конец окна, с epoch |
| `samples` | int | число строк архива в окне |
| `power_w` | object | `{"a","b","c","total"}` — средняя мощность по фазам и сумма, Вт; значение без данных — `null` |
| `energy_kwh_import` | object | `{"first","last","delta","unit":"kWh"}` — первое и последнее показание счётчика в окне (три знака — шаг 1 Вт·ч) и `delta`: `last − first`, если последнее показание не ниже первого; если ниже (разрыв счётчика: сброс, смена единицы) — сумма неотрицательных шагов по строкам окна (`energy_total`, правило шага `_counter_step` в `history_ce_roll.py`). Предел: разрыв, после которого счётчик в том же окне снова поднялся выше первого показания, не распознаётся — `delta` тогда `last − first`. Объект есть всегда, значение без данных — `null` |
| `kwh_rub` | number | применённый тариф, ₽/кВт·ч |
| `kwh_rub_default` | number | тариф по умолчанию: `STAND_DEVICES_KWH_RUB` (конечное число 0…1000000, запятая допустима), иначе — и при неверном значении — 10.50 с одним предупреждением в журнале |
| `kwh_rub_unit` | `"RUB/kWh"` | — |
| `cost_rub` | number \| null | `round(delta × kwh_rub, 2)`; `null`, если `delta` нет или произведение не конечно (никогда не `NaN`/`Infinity`) |
| `cost_basis` | `"energy_kwh"` | стоимость считается по ΔE счётчика, **не** по средней мощности |
| `cost_note` | string | пояснение по-русски для UI |
<!-- contract:summary:end -->

плюс ключи носителя (§5). Тариф демон нигде не хранит: без `kwh_rub` берётся
значение по умолчанию; вкладка «Устройства» держит тариф пользователя в
`localStorage` браузера и передаёт его в каждом запросе. `kwh_rub` — конечное
число от 0 до 1000000 включительно (десятичная запятая допустима); `nan`, `inf`,
отрицательное, больше 1000000 или нечисло — `400` (§8).

## 7. Выгрузка `/api/devices/history/export`

Параметры — как у `/history` (§3) плюс `format`. Набор столбцов: `kind=mr` —
контракт MR; `kind=carel` — снятые метрики Carel (как обзор §5.3); иначе
`group` (все поля всех метрик группы) или `metric` (поля одной метрики).
Корзина — «корзина выгрузки» §4.1; счётчик `energy_kwh_import` выгружается
**максимумом** корзины (показание на её конец), остальные — средним.

- Ответ HTTP `200`, `Content-Disposition: attachment; filename="…";
  filename*=UTF-8''…`, `Cache-Control: no-store`.
- `format=xlsx` (по умолчанию) — `Content-Type:
  application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. Лист
  «Данные»: шапка (устройство, метрика, период, шаг, строк), затем таблица
  `Время` × столбцы `"<ярлык поля>, <единица>"`. Без `openpyxl` на плате —
  упрощённая книга того же содержания (шапка короче). «Метрика» в шапке
  (и `# метрика:` в `txt`) — ярлык метрики или название группы; у каждой
  группы §4.2 своё (`_GROUP_TITLES` в `history_export.py`).
- `format=txt` (`tsv`, `text`) — `Content-Type: text/plain; charset=utf-8`:
  строки `# устройство:`, `# метрика:`, `# период:`, `# шаг:`, затем строка
  заголовков и строки данных через TAB; пустая ячейка — нет значения.
- Имя файла: `<kind>_export_<device_id>_<metric|group|ai|ahu|data>_<range>_<YYYYmmdd_HHMMSS>.<xlsx|txt>`,
  где `<kind>` — `dtv` / `ce` / `carel` / `mtd` / `mr` / `mixed`, а `w:<с>`
  записан как `w<с>`.
- Без `metric`/`group`, с неизвестной метрикой или группой (и не
  `kind=mr|carel`) файла нет: `400` с тем же JSON-телом, что у `/history` без
  `metric`/`group` (§8), в любом `format`.

## 8. Ошибки

| Случай | HTTP | Тело |
|---|---|---|
| нет сессии | `401` | `{"ok":false,"error":"unauthorized"}` |
| `/history` без `kind=mr\|carel`, без `metric` и без `group` | `400` | `{"ok":false,"error":"укажите metric=… или group=climate\|energy\|ahu\|mtd"}` + ключи носителя |
| `/export` без `kind=mr\|carel`, без `metric`/`group` или с неизвестными | `400` | то же, что строкой выше (JSON, без `Content-Disposition`) |
| `/summary` с `kwh_rub` вне конечных 0…1000000 (нечисло, `nan`, `inf`, отрицательное, больше 1000000) | `400` | `{"ok":false,"error":"kwh_rub: число 0…1000000"}` |
| неизвестный `metric` (в т.ч. при `kind=carel`) | `200` | `{"ok":false,"error":"unknown metric","metric":"<id>"}`; при `kind=carel` ещё `events`, `event_kinds` |
| неизвестный `group` | `200` | `{"ok":false,"error":"specify group=climate\|energy\|ahu\|mtd or metrics=…"}` |
| выгрузка `xlsx` не собралась | `503` / `500` | `{"ok":false,"error":"<текст>"}` |
| неизвестный путь | `404` | `{"ok":false,"error":"not found"}` |

Поэтому потребитель проверяет **и** код HTTP, **и** `ok` в теле: неизвестная
метрика и группа в `/history` приходят с `200` (в `/export` — `400`). Упоминание `metrics=…` в тексте ошибки
группы относится к внутреннему вызову: HTTP-параметра `metrics` нет. Текст
`error` — для человека; машинно сравнивать можно только `unauthorized`,
`unknown metric` и `not found`.

## 9. Честность: единица энергии СЭ

Единица числа `energy_*` — не этого контракта. Её дом —
`docs/contracts/ce-energy-mqtt.md` (пересчёт делает мост, один раз; демон
делит на 1000 и архивирует `energy_kwh_import` с тремя знаками):

- правило пересчёта по версиям прошивки (три строки таблицы), маркер
  `/devices/<id>/meta/energy_unit` и пределы этого маркера — только там, здесь
  не повторяются;
- архив, записанный до этого релиза на прошивке СЭ-02м-3 ≤ 1.0.7.10, остаётся
  в единицах счётчика, а не Вт·ч (решение Оператора 2026-10-07): ряд и
  выгрузка за такое окно показывают числа в сотни раз больше; ΔE окна,
  пересекающего переход, считается по правилу разрыва (§6), а не как
  отрицательный расход.

Поэтому этот контракт закрепляет **форму** полей `energy_kwh_import` (ряд
§5.1/§5.2, объект сводки §6, столбец выгрузки), а **не физическую единицу**:
метка `"kWh"` / `"RUB/kWh"` — имя поля, а не подтверждённая размерность, и
`cost_rub` — рубли ровно настолько, насколько ΔE — кВт·ч. Смена единицы меняет
значения этих полей, но не их имена и форму. Мощность (`power`, `power_w`) и
остальные метрики СЭ этой оговорки не имеют.

## 10. Совместимость / гарантии

- Перечисленные ключи ответов и коды HTTP — гарантия: новые ключи могут
  **добавляться**, существующие не переименовываются и не удаляются без
  правки этого файла, теста и всех потребителей (вкладка «Устройства» с
  кэшированным бандлом, агентский API, страница vPLC) в одном PR.
- Набор ключей `range` и состав групп меняются только вместе с таблицами §4 —
  тест не даст им разойтись.
- Метрики внутри группы могут добавляться (новая строка `METRICS` + строка
  группы); потребитель ищет метрику по `metric`, а не по индексу.
- Авторизация из §1 не ослабляется: обход по адресу или по слушателю —
  нарушение контракта.

## Проверка контракта

`opt/sa02m-devices/tests/test_history_api_contract.py` под строкой
`py-unit-devices` (её `covers` перечисляет этот файл, поэтому правка документа
перезапускает тест). Тест закрепляет:

  `HISTORY_GROUPS` (состав и порядок), таблицу §6 + ключи носителя = ключи
  ответа сводки — документ читается из файла, пустая или пропавшая таблица —
  красный тест;
- `window_s` → `w:<с>` (зажим `[60, 2592000]`, приоритет над `range`) и
  неизвестный `range` → `1h`;
- форму §5.1 (включая `bucket_s`/`prepared`/`value_kind` у `power`), §5.2
  (`group=energy`: ключи и порядок `metrics[]`), §5.3 (имена метрик
  `kind=carel` = `CAREL_COLUMNS`, `events`/`event_kinds`), §6 и §7 (`txt`:
