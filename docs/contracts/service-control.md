# Асинхронное управление службами

Авторизованный `POST cgi-bin/services_ctrl.cgi` с действующим CSRF-токеном принимает `id` службы и `action` (`start`, `stop`, `install`, `uninstall`). Ответ `ok:true,pending:true` подтверждает приём команды, а не её выполнение. Он содержит `id`, `action` и новый случайный `op_id` из 32 шестнадцатеричных символов нижнего регистра.

Панель читает `GET ?result=1&id=…&op_id=…`. Отсутствующий результат или результат другой операции означает `pending:true`. Завершить команду может только ответ с соответствующими `op_id`, `id`, `action`; ошибка предыдущей операции также не завершает новую. Служба сохраняет недоступные кнопки всех действий до завершения команды, в том числе после очередного обновления списка.

После соответствующего успешного результата панель сразу запрашивает полный список и независимо проверяет состояние службы. Кнопки остаются недоступными до этой проверки. Последующие попытки сохраняют интервал 2 с.

| Ограничение | Время |
| --- | --- |
| Один запрос списка, POST, результата или проверки состояния, включая полное чтение JSON | До 20 с, но не дольше остатка общего времени |
| Вся операция start/stop, начиная перед POST | 90 с |
| Вся операция install/uninstall, начиная перед POST | 600 с |

Каждый вызов `/etc/init.d/{codemeter,codesyscontrol,mplc4} start|stop` в helper ограничен 45 с (+5 с на принудительное завершение) и пишет в журнал установки строку `init.d <скрипт> <действие> timed out after 45s`; повторный запуск helper под защитой координатора для start/stop ограничен 300 с и по истечении отвечает ошибкой `guard_timeout` (не `port_busy`); install/uninstall по времени не ограничиваются — их ограничивает срок панели 600 с. Проверки: `scripts/dev/test-initd-bounded.sh`, `opt/sa02m-port-coordinator/tests/test_service_guard_timeout.py`.

По истечении времени панель показывает существующее сообщение ошибки, снимает локальное ожидание и обновляет список с тем же ограничением запроса. Отмена браузерного запроса не отменяет принятую системную операцию и не доказывает её завершение. Автоматического повтора POST нет. Ручное обновление при ошибке освобождает кнопку; поздний ответ старого поколения списка не заменяет новый.

Список использует один запрос systemd с ключами `Id`, `ActiveState`, `LoadState` для всех кандидатов установленных служб и один существующий пакет `is-enabled`. Полные однозначные записи связываются только по `Id`; каноническое имя вместо запрошенного alias, неполная или повреждённая запись и отказ пакета возвращают прежние отдельные проверки. Порядок каталога и кандидатов, определение установки, резервные проверки SysV/файлов, состояние процессов CODESYS/MPLC4 и отдельная политика автозапуска сохраняются. Helper сохраняет каждый ответ списка в `/run/sa02m-svcctl/list.json` (0644); `GET services_ctrl.cgi` и `status.cgi?part=services` отдают копию моложе 10 с без повторного запуска helper. Любая команда start/stop/install/uninstall удаляет копию до и после работы, а список, собранный во время команды, не сохраняется — поэтому проверка состояния после команды всегда видит свежий список; изменение службы в обход helper может быть видно с задержкой до 10 с. Проверка: `scripts/dev/test-status-cache.sh`.

Корневой helper проверяет идентификаторы до использования в путях, передаёт `op_id` через существующий повторный запуск под защитой координатора и публикует целый JSON атомарной заменой файла. Защита служб RS-485 описана в [контракте владения портами](port-ownership.md); результат веб-команды её не заменяет. Сбой самого vPLC при завершении не скрывается сбросом системного состояния ошибки.

Совместимость: прежний `GET` без `op_id` возвращает последний результат службы; вызов helper без третьего аргумента допустим. Хранится один последний результат на службу. Одновременные команды из разных вкладок могут перезаписать его, и ожидающая вкладка завершится тайм-аутом; чужой результат не выдаётся за её успешное выполнение. Старая панель без проверки `op_id` сохраняет прежнее поведение до загрузки обновлённого JS.

Проверки: `scripts/dev/test-service-operations.py` выполняет настоящий CGI и атомарную публикацию; под root он также проверяет полный путь helper → координатор → повторный helper и отказ MQTT при lease. `scripts/dev/test-service-operation-ui.mjs` проверяет корреляцию, блокировку кнопок, общий срок и зависание запроса/тела на каждой стадии. `scripts/dev/test-service-list-batch.py` выполняет настоящий POSIX helper с моделью systemd, сравнивает JSON и проверяет два вызова в обычном случае. `scripts/dev/status-reliability-browser.mjs` проверяет реальные клики и незавершённые HTTP-тела через общий fetch guard в RU/EN на desktop/mobile.
