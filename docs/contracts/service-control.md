# Асинхронное управление службами

Авторизованный `POST cgi-bin/services_ctrl.cgi` с действующим CSRF-токеном принимает `id` службы и `action` (`start`, `stop`, `install`, `uninstall`). Ответ `ok:true,pending:true` подтверждает приём команды, а не её выполнение. Он содержит `id`, `action` и новый случайный `op_id` из 32 шестнадцатеричных символов нижнего регистра.

Панель читает `GET ?result=1&id=…&op_id=…`. Отсутствующий результат или результат другой операции означает `pending:true`. Завершить команду может только ответ с соответствующими `op_id`, `id`, `action`; ошибка предыдущей операции также не завершает новую. Служба сохраняет недоступные кнопки всех действий до завершения команды, в том числе после очередного обновления списка.

Корневой helper проверяет идентификаторы до использования в путях, передаёт `op_id` через существующий повторный запуск под защитой координатора и публикует целый JSON атомарной заменой файла. Защита служб RS-485 описана в [контракте владения портами](port-ownership.md); результат веб-команды её не заменяет. Сбой самого vPLC при завершении не скрывается сбросом системного состояния ошибки.

Совместимость: прежний `GET` без `op_id` возвращает последний результат службы; вызов helper без третьего аргумента допустим. Хранится один последний результат на службу. Одновременные команды из разных вкладок могут перезаписать его, и ожидающая вкладка завершится тайм-аутом; чужой результат не выдаётся за её успешное выполнение. Старая панель без проверки `op_id` сохраняет прежнее поведение до загрузки обновлённого JS.

Проверки: `scripts/dev/test-service-operations.py` выполняет настоящий CGI и атомарную публикацию; под root он также проверяет полный путь helper → координатор → повторный helper и отказ MQTT при lease. `scripts/dev/test-service-operation-ui.mjs` проверяет старые ответы, повторное нажатие и сохранение блокировки кнопок.
