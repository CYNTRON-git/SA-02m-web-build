# Режимы и расширенные настройки реле MR

Окно использует фактический профиль, прочитанный режим и подтверждённые настройки.
Команда, Modbus-состояние выхода и измерение клемм являются разными результатами.
ACK не переключает индикатор оптимистично: после команды показано чтение выхода.

## Возможности моделей

| Тип | Режимы 130 | Приводы | Особенности управления |
| --- | --- | --- | --- |
| 1, 6DO8DI | 0..5 | 3 | Обычная кнопка DO предупреждает о переходе в Modbus |
| 8, 4DO6DI | 0..5 | 2 | Как тип 1, только четыре физических DO |
| 11, 6DO5DI2AO | 0..5 | 3 | Без автоматического перехода; в 1/2 прямой DO закрыт; в 3/4 команда только coil1 |
| 2, 16DO; 4, 6DO | 0 | Нет | Фиксированный режим, обычный DO не зависит от чтения 130 |
| 15, 4TO6DI | 0..2 | Нет | Коды 1/2 — режимы триаковой панели; DO и яркость задаются отдельно |

Тип 11 в режиме 3 не имеет нужных DI-разрешений для полноценного управления двумя
вентиляторами. В режиме 4 coil1 управляет запуском только вентилятора 1, AO —
скоростью. Редактирование DI 630..694 при режиме 3/4 закрыто. Окно ограничивает
управление по конфигурационному режиму; скрытое состояние degraded boot прошивки
не выдаётся за подтверждённое разрешение.

`mode_known`, `options_known`, `power_stagger_known` сопровождают прежние числовые
поля. Неудача чтения означает неизвестность и закрывает зависимые действия.
Только обычные DO типов 1/8 сохраняют переход в режим 0: нужен валидный ACK записи
130 и свежий ответ ровно 0. При неудаче перехода coil не пишется. Типы 11/15 не
получают скрытой записи 130.

## Явные команды

Существующий POST `/device_config/coil` принимает необязательный `relay_action`:

- `drive`: типы 1/8/11, текущий режим 5, coil 1..2×число приводов. Нечётный coil
  открывает, чётный закрывает; true запрашивает направление, false отменяет его,
  в том числе при физическом OFF во время deadtime.
- `fan`: только тип 11, режим 3/4, coil1; true/false запрашивает запуск/остановку.

Эти действия требуют свежего типа, режима и версии не ниже 1.0.12.22. Значение
строго boolean, coil строго integer; неизвестный/пустой intent отклоняется.
Ни один explicit intent не пишет 130. Отсутствие intent сохраняет обычное поведение.
Прошивка владеет задержками и блокировками; веб не посылает две встречные команды.

## Настройки и сохранность

Основные настройки — режим, опции и stagger 0..60 с; минимальное отключение
первых шести DO ограничено 0..999 с. UI меняет только применимые биты опций и
сохраняет остальные. Бит 0 отдельно не редактируется. Файл переносит полную
маску `relay.options`; для типов 1/8 в итоговых режимах 1/2 бит 0 нормализуется
по режиму и показывается в preview. Запись опций сохраняет текущий производный
бит; финальная запись режима и чтение 131 подтверждают итоговую маску. Если
финальный шаг не подтверждён, промежуточная маска не считается итоговым успехом.

Расширенные поля доступны при свежей версии ≥1.0.12.22. Это проверенная граница
поддержки, а не заявленная версия первого появления функции. Старые/неизвестные
версии не получают эти записи даже при нулевом ответе или версии из файла.

| Настройка | Поля формата файла | Область |
| --- | --- | --- |
| Основные вентиляторы | `relay.primary_fans`, маска 0..3 | Типы 1/8/11 |
| Расписание | `relay.schedule.days`: day 0..6, start/end hour 0..23, minute 0..59, enabled boolean | Типы 1/8/11; применяется в режимах 3/4 с опцией планировщика |
| Приводы | `relay.drives.deadtime_ms`, `default_run_s`, `channels` с opening/closing_deciseconds, enabled, powerup_action, safe_action | Типы 1/8/11; action 0 нет, 1 открыть, 2 закрыть |
| Фронт диммирования | `relay.dimming.channels`: channel 1..4, edge 0/1 | Только тип 15 |

Времена приводов — uint16; нулевой deadtime означает 500 мс, общее время 0 —
10 с, время направления 0 использует общее. Настройка одного packed-поля
сохраняет соседние каналы. Предварительная проверка всех полей и применение
под одной арендой описаны в [контракте файла](module-config-file.md).

Расписание работает по времени с момента запуска и дням цикла 1–7, а не по
календарю СА. Одинаковые начало/конец означают пустое окно; переход через полночь
допустим. Расписание, приводы и таймеры релейных модулей действуют в RAM и могут
сброситься после перезапуска. Эти ограничения показаны возле управления;
успешное чтение не обещает EEPROM-сохранение.

В режиме 3 показаны два вентилятора, в 4 — четыре: Input109 — состояние,
Input113 — аварии и пожар. `fans.known` требует обоих полных чтений. Отдельный
сброс HR137=1 требует подтверждения пользователя, текущего fan-режима и новой
поддержанной прошивки; он не попадает в файлы. После ACK показывается новое
чтение, включая сохранившуюся аварию. Сброс может разрешить повторный запуск.

## Проверки

`test_mr_relay_capabilities.py` проверяет профиль, реальные кадры, HTTP intent,
нулевые записи при отказе, нормализацию и неизвестный финальный результат.
`test-flasher-mr-relay.mjs` проверяет настоящие элементы и HTTP-команды в Chromium,
ограничения типа 11, отмену направления при OFF, сохранение ввода и RU/EN.
Первоисточник семантики — MR-02m `relay_modes.c`, `relay_modes.h` и
`doc/MODBUS_6DO8DI_4DO6DI_MODES.md`; тесты транспорта не доказывают клеммы или
сохранность после отключения питания.
