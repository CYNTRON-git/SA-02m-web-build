# Изолированные окружения Python

Состав пяти окружений определяется `opt/sa02m-python-manager/runtime.json`.
Для каждой службы, CGI и установочного вызова карта `consumers.json` задаёт
группу, конкретную точку входа и каталоги исходников приложения. В разделе
`preserved` перечислены отдельные потребители системного Python и HomeKit.

В каталоге поставки находятся пять полных hash-lock, wheelhouse с именем по
набору файлов и отдельный `bridge.json`. Подготовка проверяет SHA всех
файлов, версию и владельца системного интерпретатора и загрузочного pip-wheel,
архитектуру, Python ABI и пакеты dpkg. Для MQTT в изолированном site-packages
создаются ссылки только на проверенные файлы системных cryptography и
_cffi_backend. При проверке выполняются импорты от фактического интерпретатора,
проверка происхождения модулей, сверка полного установленного состава и
известный тестовый вектор AES-GCM.

Шлюз OPC UA использует отдельные wheel для cryptography и CFFI. Проверка
сопоставляет SHA внутренних ELF, версию встроенного OpenSSL и загруженные
пути семи системных библиотек с точными версиями и владельцами dpkg.
SNMP v1/v2c использует собственное окружение PySNMP, pyasn1 и Paho.
Публикация окружений сохраняет настроенное состояние опциональных служб.

    /usr/bin/python3 -I -S -B /opt/sa02m-python-manager/runtime.py prepare
    /usr/bin/python3 -I -S -B /opt/sa02m-python-manager/runtime.py verify RELEASE_ID

`prepare` требует root, берёт блокировку и собирает окружения в уникальном
каталоге `/opt/sa02m-python-runtimes/releases/RELEASE_ID`. Wheel устанавливается
из локальной поставки через `--no-index --require-hashes --only-binary=:all:
--no-deps`. Проверенная квитанция содержит идентификатор manifest, импорты,
дистрибутивы и SHA деревьев. Повторный вызов проверяет ранее собранное
окружение для тех же входов. Изменение ABI, целевого файла dpkg или
криптомоста требует поставки соответствующего проверенного каталога.

Обе команды выдают один JSON-объект. При успехе он содержит `ok`,
`release_id`, `manifest_sha256`, абсолютный `base` и группы
`["gateway","home","mqtt","opcua","snmp"]`. При ошибке `code` принимает одно из значений
`payload_missing`, `runtime_busy`, `verification_failed`, `verification_timeout`. Подготовка доступна
до активации, в том числе во временном окне обслуживания.

Если дочерний процесс команды `verify` исчерпал свой срок, через 15 секунд
команда один раз повторяет полную проверку выпуска. При втором истечении
она возвращает код `verification_timeout` и статус выхода 1. Служба активации
публикует причину `runtime_verification_timeout` и сохраняет печать образа.
Нарушение целостности завершает проверку с первого обнаружения. Служба удаляет
печать только после полной проверки выпуска и его потребителей.
Публикацию выбранного окружения выполняет владелец транзакции активации.

Потребитель вызывает `/usr/local/libexec/sa02m-python-consumer CONSUMER_ID`.
Окружение запускается с изоляцией от PYTHONPATH и пользовательского site,
с проверкой версии окружения и источников нативных модулей. До первой
активации поддерживается прежний путь запуска. После публикации селектора
обязательна проверенная точка входа выбранного окружения.
