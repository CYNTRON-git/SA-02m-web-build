# Контракт: мост Apple HomeKit (`sa02m-homekit`)

**Гарантия:** устройство, один раз настроенное в «Умном доме» (документ
устройств Алисы `/etc/sa02m-alice/sa02m-alice-devices.conf`) и отмеченное
«Показывать в HomeKit», появляется в приложении Apple «Дом» с той же
конверсией значений и той же правдой о доступности, что у Алисы; мост слушает
LAN только после включения на карточке, только на одном выбранном проводном
интерфейсе; код сопряжения видит только аутентифицированная веб-сессия; ключи
сопряжения читает только собственный непривилегированный пользователь демона.

Мост — необязательная установка (решение Оператора Q-A: некоммерческое
использование, в заводской образ не входит; пометку «не сертифицировано
Apple» с карточки убрали по решению Оператора 2026-09-28). Библиотека протокола — HAP-python 5.0.0
(Apache-2.0) в отдельном venv; почему она, почему venv и что проверено до
сборки — `docs/decisions/homekit-home-connect.md`. Лицензии зависимостей —
`opt/sa02m-homekit/THIRD_PARTY.md`.

Машинная грамматика (пути, ключи JSON, состояния, коды ошибок, имена сервисов
HAP) — на английском (`PROTOCOL.md` invariant 5); пояснения — на русском.
Код: `opt/sa02m-homekit/sa02m_homekit/`; каждое перечисление ниже
существует в коде ровно один раз (ссылка на модуль стоит у раздела).

## 0. Обещания

| # | Обещание | Где держится |
|---|---|---|
| P1 | **Одна модель устройства на все экосистемы.** HomeKit строится из того же документа устройств и тем же движком `DeviceRegistry`, что Алиса: масштаб, инверсия, `writable:false` и правило доступности применяются одним кодом. Второго списка устройств и шаблонов «под HomeKit» нет | §1, §3, §6 |
| P2 | **Честный статус.** Устройство, которое плата сейчас не читает, в «Доме» показывается «Не отвечает», а не устаревшим значением. Показание, для которого у HomeKit нет типа, перечислено на карточке с причиной (§4), а не выброшено молча | §4, §6 |
| P3 | **Локально, по согласию, с закрытым отказом.** Пока мост не включён на карточке, новый слушатель не открыт. Слушатель — ровно один IPv4 одного проводного интерфейса (никогда модем, никогда `0.0.0.0`); сопряжение возможно только пока пар нет; код сопряжения — только аутентифицированной веб-сессии | §8, §9 |
| P4 | **Секреты там, где нужны.** Долгосрочные ключи и пары HomeKit читает только пользователь `sa02m-homekit` — никогда `www-data`, никогда журнал, никогда веб-бэкап, никогда клон образа | §9, §13, §14 |

## 1. Зависимости

Направление одно: `sa02m_homekit` → `sa02m_alice.client.device_registry`,
`sa02m_alice.client.converters`, `sa02m_alice.common.config_store`,
`sa02m_alice.common.constants`, `sa02m_alice.client.reload_watch`,
`sa02m_alice.config.scene_devices` (сцены, §2), а через него — лениво —
`sa02m_rules.store` (только чтение хранилища сценариев; не импортируется —
значит «сцен нет», никогда `missing_deps`). Пакет
`sa02m_alice` никогда не импортирует `sa02m_homekit`. Это единственный дом
этой границы (`docs/architecture.md` — указатель без правил слоёв).

- Демон создаёт **собственный** `DeviceRegistry(doc, profile="homekit")` в
  своём процессе. Этот профиль отбрасывает элементы `cloud_only`, не
  присоединяет сцены «в Алису» и присоединяет сцены из `homekit_scenes` (§2)
  — поведение, на которое HomeKit опирается (`config/scene_devices.py`,
  `client/device_registry.py` `_items`). Второй наблюдатель
  (`RulesExposureWatcher(fingerprint=homekit_exposure_fingerprint)`) следит за
  хранилищем сценариев каждые 2 с: переименование, выключение или удаление
  сцены перестраивает проекцию без правки документа.
- Проекция читает каталог только через публичный
  `DeviceRegistry.catalogue_items()` → `[(device_id, device, capability_items,
  property_items)]` в порядке документа, глубокие копии, тот же фильтр
  `_items`. `discovery_devices()` не используется: его фильтр по
  `alice_visible` и зачистка параметров — политика Яндекса, не HomeKit.
- **Версия соседних пакетов.** Каждый символ, который мост берёт из
  `sa02m_alice` (и через сцены — из `sa02m_rules.store`), перечислен в одном
  месте: `sa02m_homekit/peers.py` (`REQUIRED_PEER_SYMBOLS`,
  `OPTIONAL_PEER_SYMBOLS`); тест выводит этот список из импортов пакета, так что
  забытый символ роняет сборку. Пакет Алисы старше моста (обновление только
  `www`, старая полная установка) → демон не стартует: `missing_deps` + причина
  `peer_package_outdated`, `message` называет символы, выход 0 (§10). Старый
  пакет сценариев — только «сцен нет», как и его отсутствие.
- Установщик: `06-alice.sh` раньше `06c-homekit.sh` (общая зависимость до
  потребителя). Без `/opt/sa02m-alice/sa02m_alice` модуль HomeKit не ставится
  (`scripts/06c-homekit.sh`: WARN и выход 0). Перед тем как что-либо ставить,
  06c проверяет список `peers.py` интерпретатором и путями юнита (`python3 -I`,
  таймаут 60 с): устаревший пакет обновляется из того же дерева его **собственным**
  модулем (`06-alice.sh`, `06b-rules.sh` — идемпотентны, перезапускают только
  активные службы), если оператор не пропустил этот модуль
  (`SA02M_SKIP_ALICE`/`SA02M_SKIP_RULES`); пакет Алисы, оставшийся старым, —
  ошибка и выход 1 до первой записи на плату («обновите пакет Алисы: запустите
  06-alice.sh или полную установку»); пустой список символов — тоже выход 1.
- CGI-диспетчер (`api.py`) — только стандартная библиотека системного
  `python3`: он не импортирует ни venv (pyhap, segno), ни `sa02m_alice`, так что
  плата со сломанным venv всё равно получает честную карточку.

## 2. Что видно в HomeKit

Экспозиция — **по согласию** (решение Оператора Q-D).

- Поле устройства `homekit_visible` в документе устройств: строгий bool
  (`config/models.py` `validate_device` отвергает всё прочее —
  `invalid homekit_visible`). Экспонируется **только** `true`. Отсутствие или
  `false` — скрыто (причина `hidden`). Это противоположно умолчанию
  `alice_visible` намеренно: устаревшая вкладка браузера, сохраняющая строку
  устройства без этого ключа (upsert заменяет строку целиком), может устройство
  только **скрыть**, но не открыть.
- Поле поставляется в форму «Умного дома» флажком «Показывать в HomeKit» и
  кнопкой «Отметить все для HomeKit»; оба видны, только пока модуль установлен.
  Форма сохраняет поле при каждой записи устройства.
- **Список на карточке «Apple HomeKit»** («Устройства для HomeKit», пока модуль
  установлен и в документе есть устройства): строка на устройство — флажок,
  имя, приглушённая причина пропуска уровня устройства из §4 (не `hidden`, не
  пропуск отдельного показания); ничего не отмечено — строка «Нет устройств:
  отметьте их ниже» и список раскрыт; отмечено, но все отмеченные пропущены
  (0 аксессуаров) — этой строки нет, объясняют причины у строк. «Сохранить» и «Отметить все для
  HomeKit» пишут **одним** запросом `set_homekit_visible` (контракт Алисы
  `alice-mqtt-mapping.md` §Tile fields — грамматика, пределы, отказы), никогда
  по записи устройства на каждое: так плата под нагрузкой отвечала HTTP 504
  (стенд 1.135). Алиса не перезапускается; мост перестраивается сам по
  изменению документа (§1, наблюдатель).
- **Сцены** (строка `M18`, решение Оператора O2). Отметка «Показывать в
  HomeKit» у сцены — список `homekit_scenes` верхнего уровня **в документе
  устройств** (`alice-mqtt-mapping.md` §Device document), не поле хранилища
  сценариев: у хранилища один писатель (облачный канал), и облачный `replace`
  молча стёр бы поле, записанное платой. Пишет список только
  `set_scene_homekit` (§11 Алисы — `config/api.py`), по умолчанию сцена не
  отмечена. В каталог профиля `homekit` попадает строка `scene-hk-<sid>`
  (`config/scene_devices.py` `homekit_scene_projection`) для каждой сцены,
  которая отмечена ∧ `type: scene` ∧ включена; отмеченная выключенная —
  пропуск `scene_disabled`. Идентификатор **не зависит от платы** намеренно:
  серийный номер контроллера может быть недоступен пользователю моста и
  появляется после регистрации, а сменившийся под мостом id выбил бы aid
  (новый аксессуар, сломанные автоматизации iOS); уникальность между платами
  HomeKit не нужна (один мост на плату). Комната — `captured_from.room_id`,
  если такая комната есть. **Строка изоляции:** «Сцена видна в HomeKit только
  пока её идентификатор есть в списке `homekit_scenes` документа устройств и
  сцена включена; флаг `alice_expose` никогда не открывает сцену в HomeKit, а
  `homekit_scenes` — в Алисе. Сцену в HomeKit может запустить только
  сопряжённый контроллер (пара HAP), выключить — никто.» Остаток, названный
  прямо: сцена, удалённая и созданная заново под тем же id, пока отмечена,
  появится снова — список чистится от несуществующих id только при следующей
  отметке.
- **Предел: 149 мостовых аксессуаров** (`constants.MAX_BRIDGED`) плюс сам мост —
  150 аксессуаров, потолок HomeKit для моста. HAP-python предел не соблюдает сам,
  поэтому его держит проекция. Порядок допуска при переполнении: сначала
  устройства, у которых уже есть aid (по возрастанию aid), затем новые по
  `device_id`; остальные — `bridge_full`.

## 3. Таблица соответствия

Код: `projection.py` `MAPPING` (одна копия); таблица ниже — вторая, и тест
сверяет их как множества строк (§16). Одно устройство — один аксессуар; у
аксессуара может быть несколько сервисов (по одному на подходящий элемент).

**Порядок для `on_off`:** сначала `writable: false` (строка `M06` — датчик при
любом типе устройства), затем тип устройства (`M01`, `M03`–`M05`), иначе
`M07`.

**Порядок сервисов в аксессуаре:** сервисы строк `M01`–`M14` идут в порядке
документа, сервисы строк `M15`–`M18` (добавлены после v1) — **после них**, тоже
в порядке документа (`projection.LATE_ROWS`). Так новый сопоставленный элемент
(CO₂, кнопка) не сдвигает внутренние номера характеристик уже сопряжённого
аксессуара (§5).

| Строка | Источник | Условие | HAP-сервис | Характеристики | Правило значения |
|---|---|---|---|---|---|
| `M01` | `capabilities.on_off` | `type=devices.types.light*` | `Lightbulb` | `On` | bool, запись разрешена |
| `M02` | `capabilities.range:brightness` | `with=M01` | `Lightbulb` | `Brightness` | линейно `parameters.range.min..max` → 0..100 (целое, с ограничением); обратно тем же отображением, с округлением до шага `precision` и ограничением диапазоном. Без лампы у того же устройства или без корректного `range` — `range_unsupported` |
| `M03` | `capabilities.on_off` | `type=devices.types.socket` | `Outlet` | `On`, `OutletInUse` | `On` — bool, запись разрешена; **`OutletInUse` — ПРОИЗВОДНОЕ: повторяет `On`** (нагрузка розетки неизвестна) |

| `M15` | `properties.float:co2_level` | `unit=unit.ppm` | `CarbonDioxideSensor` | `CarbonDioxideDetected`, `CarbonDioxideLevel` | `CarbonDioxideLevel` — число как есть, ограничение 0…100000. **`CarbonDioxideDetected` — ПРОИЗВОДНОЕ**: `1`, когда уровень ≥ порога; обратно `0` только ниже порога − 100 ppm (`constants.CO2_HYSTERESIS_PPM`: iOS уведомляет при каждом подъёме флага — шум датчика у порога не должен мигать). Записываемый `on_off` термостата остаётся своей строкой `M07`. Иначе — строки v1 (`range_unsupported`/`unit_unsupported`, `M08`) |
| `M18` | `capabilities.on_off` | `scene_id` | `Switch` | `On` | Строка каталога сцены (§2): **кнопка-импульс**, состояния не заявляет (значение не читается никогда). `On = true` → запуск сцены (§7); `On = false` не публикует ничего; через 1 с (`constants.SCENE_RESET_S`) мост сам возвращает `On` в `false` |

Слова событий не перепечатываются: пара берётся из
`sa02m_alice.client.converters.BOOL_EVENT_VALUES`; неактивно только первое
слово пары, любое другое принятое слово — активно (так `high` у дыма —
«обнаружен»). Конверсия через шов (масштаб, инверсия, слова событий) делается
**только** в конвертерах Алисы (`alice-mqtt-mapping.md` §Scale, §Inverted);
проекция лишь переводит уже нормализованное состояние в единицы HAP и обратно.

Прочие свойства аксессуаров: `AccessoryInformation` — Manufacturer `CYNTRON`,
Model = `type` устройства, SerialNumber = `device_id`, FirmwareRevision =
первые три числовые части веб-`VERSION` (формат HAP `x[.y[.z]]`: `1.0.6.57` →
`1.0.6`). Мост: Model `SA-02m HomeKit bridge`, SerialNumber = имя моста.

## 4. Причины пропуска

Код: `projection.py` `SKIP_REASONS`. Всё, чего нет в §3, пропускается **с
названной причиной**; список пропусков (устройство, элемент, причина) уходит на
карточку (не более 200 строк, общее число — отдельно, §10).

| Причина | Когда |
|---|---|
| `range_unsupported` | `range`, кроме яркости лампы и уставки композиции `Thermostat` (`M17`); яркость без лампы или без корректного `range` |
| `capability_unsupported` | `mode`, `color_setting` и прочие умения, кроме `on_off`/`range` |
| `no_homekit_type` | float `voltage`, `amperage`, `power`, `electricity_meter`, `pressure`, `tvoc`, `battery_level`, `water_level`; event `gas`, `vibration`, `battery_level`, `food_level`, `water_level`; свойство неизвестного типа |
| `scene_disabled` | сцена отмечена для HomeKit (`homekit_scenes`), но выключена в хранилище сценариев (§2) |
| `button_source_unsupported` | event `button`, привязанный не к `/devices/<mid>/controls/di_N` (нажатия считает только вход МР-02м в режиме «Кнопка») или без единого из `click`/`double_click`/`long_press` |
| `unit_unsupported` | температура не в `unit.temperature.celsius`/`.kelvin`; CO₂ не в `unit.ppm` |
| `nothing_mappable` | отмеченное устройство без единого элемента из §3 |
| `hidden` | `homekit_visible` не `true` (§2) |
| `bridge_full` | за пределом 149 (§2) |

## 5. Идентичность аксессуаров

- **aid** — постоянная карта `/var/lib/sa02m-homekit/aids.json`
  (`{"version": 1, "next": N, "aids": {device_id: aid}}`, `aid_store.py`).
  Новое устройство получает первое целое `≥ max(next, 2)`, не входящее в
  `{1, 7}` (1 — мост, 7 HAP-python не выдаёт) и не занятое. `next` только растёт:
  **aid удалённого устройства выбывает и никогда не выдаётся повторно** — iOS
  привязывает к aid автоматизации и комнаты, и повторно выданный aid молча
  перенаправил бы чужую автоматизацию на другое реле.
- Выбывает только устройство, **отсутствующее в документе**. Скрытое
  (`homekit_visible` снят) сохраняет aid: повторная отметка возвращает в «Дом»
  тот же аксессуар. Документ, который не прочитался, не выбивает ни одного aid
  («не прочитал» ≠ «всё удалено»). Сцена (`scene-hk-<sid>`) выбывает, только
  когда её строки нет в хранилище сценариев: снятая отметка или выключенная
  сцена сохраняет aid, а хранилище, которое не прочиталось, не выбивает ни
  одного aid сцены (`aid_store.retire_absent(keep=…)`). «Не прочиталось» —
  файл есть, но не открылся, не разобрался как JSON или его верхний уровень
  не объект, либо нет пакета сценариев; решает одно место,
  `scene_devices.read_rules_doc` (сам `sa02m_rules.store.load` отдаёт на такой
  файл пустой документ и различить не может). Отсутствующий файл — «сцен нет»
  (правда после сброса), и aid сцен выбывают. Повреждённая карта
  начинается заново, но не ниже любого числа, которое ещё читается в её байтах.
- **Имя** — `name` устройства без управляющих и форматных символов, эмодзи и
  символов, без ведущей/замыкающей пунктуации, пробелы схлопнуты, ≤ 64 символов;
  кириллица сохраняется; пустой результат → `device_id`. Комната в имя не входит.
- **Имя моста** — `SA-02m <6 hex>` из трёх последних байтов MAC выбранного
  интерфейса (уникально в LAN — две платы не сталкиваются в mDNS); без MAC —
  `SA-02m`. Идентификатор устройства HAP случаен и хранится в хранилище пар —
  перегенерированная идентичность для iOS это новый аксессуар (§14).
- **Изменение проекции** (набор аксессуаров, их aid, имена, модели, сервисы)
  перестраивает драйвер в процессе с задержкой 3 с: тот же файл пар, пары
  сохраняются, HAP-python поднимает номер конфигурации (`c#`) и iOS
  перечитывает мост. Правка документа, не меняющая проекцию, ничего не стоит.
  Смена сервисов у устройства может сдвинуть внутренние номера характеристик —
  автоматизации iOS на этом аксессуаре тогда приходится выбрать заново.

## 6. Доступность и значения

- Доступность аксессуара = **нет `error_code`** в ответе
  `registry.query_devices([id])`, то есть ровно правило доступности Алисы
  (`alice-mqtt-mapping.md` §Error codes: `/meta/error` устройства,
  `/meta/error` канала при отсутствии живого опроса, `STATUS_STALE_S` для
  не-Modbus-топиков). Недоступный аксессуар HAP-python отвечает на чтение
  характеристик статусом `-70402` (`SERVICE_COMMUNICATION_FAILURE`) — в «Доме»
  это «Не отвечает». Отсутствующее в ответе устройство считается
  `DEVICE_UNREACHABLE`.
- Значение, для которого честного HAP-значения нет (нет данных, не тот тип),
  не выдумывается: характеристика сохраняет прежнее значение, а о живости
  говорит доступность.
- Поток: сообщение MQTT → `registry.note_mqtt` → затронутые аксессуары помечаются
  «грязными» (по точному топику элемента; `<элемент>/meta/error` — только
  аксессуары этого элемента; прочие `/devices/<mid>/…` — все аксессуары модуля);
  раз в 0,5 с грязные перечитываются, и в HAP уходит только изменившееся.
  Раз в 30 с грязными помечаются все: недоступность по времени наступает без
  всякого сообщения.
- **События — не значения** (строка `M16`). Счётчики нажатий кнопки
  (`di_N_short|_double|_long`) добавляются к подписке MQTT
  (`engine.extra_topics()`) и в кэш реестра, «грязный» набор и дедупликацию
  значений не попадают: каждое наблюдённое **увеличение** счётчика — одно
  событие `ProgrammableSwitchEvent` (HAP-python уведомляет при каждой записи,
  так что два одиночных нажатия подряд — два события). Ограждения те же, что у
  движка сценариев (`sa02m_rules/engine.py` `_button_state`, константы сверены
  тестом): первое значение после старта — отправная точка; уменьшение — сброс
  счётчика, только новая отправная точка; переход uint16 `≥ 65535−8 → ≤ 8` —
  одно нажатие; нечисловое значение игнорируется. Строже движка: **retained**
  сообщение (повтор брокера после переподключения) — только отправная точка,
  нажатие во время обрыва позже не срабатывает. Скачок на несколько нажатий
  между двумя опросами шины — одно событие (с потерей, так задумано). События
  ждут в очереди ≤ 64 (переполнение — в журнал, старейшие отбрасываются) и
  уходят на цикл HAP с выгрузкой раз в 0,5 с: задержка ≤ период опроса шины +
  0,5 с. Резервного классификатора по фронтам `di_N` нет: нет счётчиков (вход
  не в режиме «Кнопка») — нет событий. Если тот же топик другое устройство
  привязало как обычный элемент, его значение идёт этому элементу обычным путём
  (кэш реестра, «грязный» набор); событие кнопки — как выше.
- Документ устройств читается **до** подписки MQTT (правка, сделанная пока демон
  стоял, подхватывается на старте) и отслеживается каждые 2 с
  (`reload_watch.DevicesWatcher`).
- MQTT: `127.0.0.1:1883`; **подписка делается внутри `on_connect`**, так что
  каждое переподключение (перезапуск брокера) переподписывает текущий набор
  (`mqtt_link.py`).

## 7. Путь записи

Запись из «Дома» → действие в форме Яндекса → `registry.apply_actions()` (те
же проверки, что у Алисы: `writable:false` не публикуется никогда) →
публикация каждой возвращённой пары `(topic, payload)` на `127.0.0.1:1883`,
топик `…/on`, QoS 1, **без retain** (`alice-mqtt-mapping.md` §Topics;
аналогия `mqtt-set-endpoint.md`). Любой отказ — ошибка движка, отказ
элемента, брокер не подключён — поднимает исключение внутри сеттера, и
HAP-python отвечает контроллеру `-70402`: **ложного успеха нет**; следующая
выгрузка значений возвращает в «Дом» настоящее состояние.

**Сцена** (`M18`): `On = true` → `apply_actions` (on_off true) → публикация
`/devices/sa02m-rules-<sid>/controls/run/on` = `"1"`, QoS 1, без retain
(правило реестра для сцен: свежесть не проверяется, `meta/error` устройства
учитывается — `alice-mqtt-mapping.md` §Scene devices). `On = false` **не
публикует ничего**: глагол выключения движка («выключить всё, что сцена
включила», `cloud-scenarios.md` §MQTT mirror) HomeKit не шлёт никогда — сброс
выключателя наш, а не пользователя. После успешной записи мост ставит `On`
обратно в `false` через `SCENE_RESET_S` = 1 с на цикле HAP; отказ — `-70402`,
и выключатель тоже сбрасывается. Доступность — реестр (сцена в ответе
`query_devices` без `error_code`). **Пробел, унаследованный от Алисы:** если
`sa02m-rules` стоит, публикация уходит в никуда, а «Дом» показывает успех
(`cloud-scenarios.md` «Availability gap»).

**Уставка термостата** (`M17`): `TargetTemperature` → `range:temperature`
абсолютно → `apply_actions`, прижим к диапазону элемента
(`converters.yandex_to_range`) → `/on`, QoS 1, без retain.

**Известное напряжение, не разрешённое этим контрактом.** `sh-model.md` §6
пишет, что командные точки проецируются только через `mqtt-set-endpoint.md`.
Живые клиенты Алисы уже публикуют `/on` напрямую в брокер, и мост HomeKit
делает так же. Точка разрешения — этап B `sh-model` (демон модели); до него
действует прецедент Алисы.

## 8. Сеть

Решение Оператора Q-H: один выбранный проводной интерфейс, никогда модем.

- Интерфейс — `eth0` или `eth1` (allow-list `^eth[01]$`, по умолчанию `eth0`).
  Проверяется при записи конфига **и** при чтении: вручную вписанный `ppp0` или
  занятый порт до слушателя не доходит (заменяется умолчанием, в журнале —
  предупреждение).
- Слушатель привязан к IPv4 этого интерфейса: `address = listen_address =
  advertised_address` = этот адрес; mDNS (`_hap._tcp`, UDP 5353) — внутри
  процесса (python-zeroconf, зависимость HAP-python), объявляется только на
  этом адресе. Адрес перечитывается каждые 10 с (поздний DHCP подхватывается);
  адрес `0.x` и link-local `169.254.x` считаются отсутствием адреса.
- Нет адреса → состояние `no_interface`, **ничего не слушает**, демон работает и
  повторяет попытку. Смена адреса, а также интерфейса или порта в конфиге →
  перестройка драйвера в процессе.
- Порт — по умолчанию `21064`; допустимо `1024–65535`, кроме портов других
  служб платы (`constants.FORBIDDEN_PORTS`: `1880, 1883, 1884, 4840, 4841,
  8082, 8765, 9999, 11740, 30750, 31550`, `502–506`, `8502–8506`, `9502–9506`).
  Порт занят другим процессом → `port_in_use`, ничего не слушает, повтор
  каждые 10 с.
- Через облачный туннель мост не публикуется (allow-list туннеля — `{80,
  9999}`, `threat-model.md` §3). Объявление на нескольких интерфейсах — вне v1.

## 9. Сопряжение и код

- **Pair-setup возможен, только пока пар нет** (HAP-python отказывает при
  любой существующей паре) и только на выбранном интерфейсе (§8).
- **Блокировка перебора.** Каждое неудачное доказательство SRP шага pair-setup
  M3→M4 (неверный код) считается; после **100** неудач pair-setup отвечает
  `kTLVError_MaxTries` до **перезапуска демона** (счётчик переживает
  перестройку драйвера в процессе). Ошибки pair-verify и эндпоинта пар не
  считаются — устаревший контроллер, повторяющий pair-verify, pair-setup не
  блокирует. Пока блокировка действует, статус несёт `pair_setup_locked: true`
  и `reason: "pair_setup_locked"`.
- **Код сопряжения** — `XXX-XX-XXX` из `random.SystemRandom`, с повторным
  выбором, пока код входит в запрещённые HAP (`000-00-000` … `999-99-999`,
  `123-45-678`, `876-54-321`). Код и setup id хранятся в хранилище пар
  (`state.json`, 0600) и **не меняются между перезапусками**, пока хранилище
  пар не удалено (§14): QR, уже показанный на карточке, остаётся верным.
- Код покидает демон **только** через `/run/sa02m-homekit/setup.json`
  (0640, группа `www-data`), который существует лишь пока мост в состоянии
  `running` и не сопряжён; любое другое состояние файл удаляет (при `disable`
  его удаляет и хелпер — остановленный демон этого сделать не может). В
  `status.json` кода нет никогда.
- Штатный вывод HAP-python (`setup_message()` печатает код и QR в stdout, то
  есть в постоянный журнал) заменён пустым методом; журнал демона кода не
  содержит.
- CGI отдаёт код только на `POST {"action":"setup"}` — после сессии и
  CSRF-токена, с `Cache-Control: no-store` — и только если диспетчер
  подтвердил `running` ∧ не сопряжён ∧ содержимое `setup.json` целиком
  проходит форму (код, `X-HM://…`, setup id на конце URI, квадратная матрица
  QR ≥ 21 строк). Всё иное — `not_available`, содержимое не эхом.
- QR строится на плате (`segno`, только в venv) и отдаётся строками `0/1`;
  страница рисует `<rect>` и не несёт библиотеки QR.

## 10. Статус

Три файла в `/run/sa02m-homekit/` (единственный писатель — главный поток
демона; `status.py`).

**Состояния** (`constants.STATES`):

| Состояние | Значение |
|---|---|
| `not_installed` | нет установочного следа (юнит `/etc/systemd/system/sa02m-homekit.service`, `/opt/sa02m-homekit-venv/bin/python`, `/opt/sa02m-homekit/sa02m_homekit`). Демон это состояние не пишет — его выводит диспетчер (плата получила пакет только по OTA) |
| `disabled` | в конфиге `enabled = false`; демон пишет статус и выходит с кодом 0 |
| `starting` | включён, первый статус ещё не записан, или демон остановлен в ожидании рестарта |
| `running` | слушатель поднят |
| `missing_deps` | зависимость не импортируется (`_cffi_backend`, cryptography, zeroconf, pyhap, segno, paho, пакет Алисы) или пакет Алисы старше моста (причина `peer_package_outdated`); выход 0, `message` называет модуль или символы |
| `no_interface` | у выбранного интерфейса нет IPv4; ничего не слушает |
| `port_in_use` | порт занят; ничего не слушает |
| `error` | непредвиденная ошибка (выход 1, `Restart=on-failure`), незнакомое состояние в файле или устаревший статус |

**Причины** (`constants.REASONS`, дополняют состояние):

| Причина | Значение |
|---|---|
| `identity_regenerated` | хранилище пар удалено: `machine-id` не совпал с записанным (§14) |
| `state_corrupt_regenerated` | хранилище пар не читалось целиком и удалено (§14) |
| `pair_setup_locked` | блокировка перебора (§9) |
| `status_stale` | статус живого состояния старше 90 с |
| `peer_package_outdated` | при `missing_deps`: в установленном `sa02m_alice` нет символа из `peers.REQUIRED_PEER_SYMBOLS` (§1); карточка: «Обновите пакет Алисы» |
| `conf_unreadable` | при `missing_deps`: конфиг есть, но демон не может его прочитать (сломаны владелец, группа или режим, §13) — не «выключен»; выход 0, при старте или на ходу; отсутствующий конфиг по-прежнему значит «выключен»; карточка: «Нет доступа к настройкам» |

Первые две снимаются, как только мост снова сопряжён.

**`status.json`** (0644; никогда код сопряжения, никогда имена устройств — только
счётчики). Ключи (`status.STATUS_KEYS`):

| Ключ | Тип |
|---|---|
| `state` | строка состояния (без `not_installed`) |
| `ts` | секунды эпохи |
| `version` | версия пакета |
| `reason` | причина или `""` |
| `message` | текст диагностики (≤ 200 символов) |
| `enabled` | bool |
| `interface` | `eth0`/`eth1` |
| `address` | IPv4 слушателя или `""` |
| `port` | целое |
| `bridge_name` | имя моста |
| `paired` | bool или `null` |
| `pairings` | число пар |
| `accessories` | число аксессуаров |
| `skipped` | число пропусков |
| `pair_setup_locked` | bool |

Пока мост включён, файл переписывается каждые 30 с. Хелпер при `disable` может
записать сокращённую форму `{"state":"disabled","ts":…,"reason":"",
"message":…,"enabled":false}` — диспетчер принимает любое подмножество ключей.

**`projection.json`** (0640, группа `www-data`): `accessories`
(`[{device_id, name, aid, services}]`), `skipped`
(`[{device_id, name, item, reason}]`, ≤ 200), `skipped_total`, `ts`. Имена
устройств живут только здесь.

**`setup.json`** (0640, группа `www-data`, только `running` ∧ не сопряжён):
`code`, `setup_uri`, `setup_id`, `qr`, `ts`.

**Правило слияния** (`api.merged_status` — единственный дом; CGI след
установки сам не проверяет): нет следа → `not_installed`; конфиг выключен →
`disabled`; включён и нет `status.json` → `starting`; включён, а в файле
`disabled` → `starting` (только что включили), и его возраст отсчитывается
от более позднего из `ts` статуса и времени записи конфига (момента
включения) — старый статус `disabled` не даёт `status_stale` сразу после
«Включить», а демон, молчащий дольше 90 с после включения, даёт; живое
состояние (`starting`, `running`, `no_interface`, `port_in_use`) с `ts`
дальше 90 с от текущего времени → `error` + `status_stale`; `missing_deps` и `error` пишутся один раз и
верны в любом возрасте; иначе — состояние демона.

## 11. CGI API — `cgi-bin/sa02m_homekit_api.cgi`

Порядок: сессия (`unauthorized` до любой работы) → метод (`GET`/`POST`) →
CSRF на **каждом** POST (включая `setup` и `status`) → тело ≤ 16 КиБ →
диспетчер `python3 -m sa02m_homekit.api <METHOD>` под системным `python3`,
`PYTHONPATH=/opt/sa02m-homekit`, `timeout 8` → привилегированный толчок
(`timeout 11 sudo -n …trigger.sh <verb>`) только на POST и только для
четырёх закреплённых глаголов. Транспорт — всегда HTTP 200 (идиом проекта),
`Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Бюджет: 8 с +
11 с < 20 с `fastcgi_read_timeout` nginx.

Протокол диспетчера (единственный вход CGI): тело запроса — на stdin; stdout —
**ровно две строки**: JSON ответа, затем глагол (`enable|disable|restart|
reset-pairing`) или пустая строка; код выхода 0 всегда, когда строки выведены.

| Запрос | Ответ `ok:true` | Глагол хелпера |
|---|---|---|
| `GET` (тело игнорируется) или `POST {"action":"status"}` / `POST {}` | объект статуса (ниже) | — |
| `POST {"action":"setup"}` | `{"ok":true,"available":true,"code":"XXX-XX-XXX","setup_uri":"X-HM://…","setup_id":"ABCD","qr":["0101…",…]}` | — |
| `POST {"action":"enable"}` | `{"ok":true,"action":"enable","status":{…}}` | `enable` |
| `POST {"action":"disable"}` | `{"ok":true,"action":"disable","status":{…}}` | `disable` |
| `POST {"action":"set_interface","interface":"eth0"\|"eth1"}` | `{"ok":true,"action":"set_interface","status":{…}}` | `restart`, только если мост включён |
| `POST {"action":"set_port","port":<целое или строка цифр>}` | `{"ok":true,"action":"set_port","status":{…}}` | `restart`, только если мост включён |
| `POST {"action":"reset_pairing"}` | `{"ok":true,"action":"reset_pairing","status":{…}}` | `reset-pairing` (конфиг не пишется) |

`enable`/`disable`/`set_*` пишут `/etc/sa02m-homekit/sa02m-homekit.conf`
атомарно (владелец и режим файла сохраняются: конфиг пишут и CGI, и root из
каталога служб). Если толчок хелпера случился, к ответу добавляется
`"trigger":"ok"|"failed"|"timeout"` и, если хелпер назвал код ошибки из
`[a-z_]`, `"trigger_error":"<код>"` (текст хелпера не эхом).

**Объект статуса** (`GET`/`status`, и поле `status` мутаций): `ok, state,
reason, message, enabled, interface, address, port, bridge_name, paired
(bool|null), pairings, accessories, skipped_total, skipped (≤ 200),
accessory_list, pair_setup_locked, setup_available, interfaces
([{name, present, address}] для eth0 и eth1), port_default, port_min, port_max,
forbidden_ports, version, ts`. `address`, `pairings`, `accessories`,
`pair_setup_locked` значимы только в `running`; списки — только в живых
состояниях; `setup_available` = `running` ∧ `paired: false` ∧ `setup.json`
существует.

**Коды ошибок** (`{"ok":false,"error":…}`):

| Код | Кто | Когда |
|---|---|---|
| `unauthorized` | CGI | нет живой сессии |
| `csrf` (+ `error_code: "E_CSRF"`, `reason`) | CGI | POST без верного `X-SA02M-CSRF` (`docs/decisions/selective-csrf-policy.md`) |
| `method_not_allowed` | CGI, диспетчер | метод не `GET`/`POST` |
| `payload_too_large` | CGI, диспетчер | тело > 16 КиБ |
| `not_installed` | CGI | пакета нет на плате: `GET` → `{"ok":true,"state":"not_installed",…}`, `POST` → ошибка |
| `not_installed` | диспетчер | мутация на плате без установочного следа — конфиг не пишется, хелпер не зовётся |
| `homekit_api_failed` | CGI | диспетчер упал, завис или вывел не JSON |
| `invalid_json` | диспетчер | тело POST не объект JSON |
| `not_found` | диспетчер | неизвестное `action` |
| `not_available` | диспетчер | `setup` вне `running` ∧ не сопряжён, или `setup.json` отсутствует/не проходит форму |
| `invalid_interface` | диспетчер | не `eth0`/`eth1` |
| `invalid_port` | диспетчер | вне `1024–65535`, занят службой платы, не целое |
| `conf_write_failed` (+ `message`) | диспетчер | запись конфига не удалась |

## 12. Привилегированный хелпер

`/usr/local/sbin/sa02m-homekit-web-trigger.sh`, sudoers
`etc/sudoers.d/sa02m-homekit` — ровно четыре закреплённых вызова, `www-data`
→ root, без пароля. Хелпер сам проверяет argv (фиксированный `case`, ровно
один аргумент), не читает ничего от вызывающего, кроме argv, каждый
`systemctl` — под `timeout 10`, глаголы выполняются по одному (`flock` на
собственном файле хелпера, ожидание 5 с → `busy`).

| Глагол | Действие |
|---|---|
| `enable` | `unmask` + `enable` + `restart` юнита |
| `disable` | `stop` + `disable`; удалить `setup.json`; записать запасной статус `disabled`, только если файла нет или он старше вызова (свежий статус демона не затирается) |
| `restart` | `restart`, только если в конфиге `enabled = true`; иначе `"applied":"skipped"` |
| `reset-pairing` | `stop` → удалить хранилище пар (§14) — только когда юнит полностью `inactive`/`failed` → `start`, если мост включён |

Коды ошибок хелпера (попадают в `trigger_error`): `unknown_action`,
`unexpected_arguments`, `not_installed` (нет unit-файла), `busy`,
`state_dir_invalid` (каталог пар — симлинк или отсутствует), `still_running`
(юнит не остановился — удалять под живым демоном нельзя, он записал бы старые
ключи снова), `remove_failed`.

Root пишет в каталоги, принадлежащие демону, только так, чтобы подложенный
или подменённый между двумя шагами симлинк не сработал: запасной статус
создаётся `O_CREAT|O_EXCL|O_NOFOLLOW` относительно дескриптора каталога,
пишется и получает режим 0644 через свой дескриптор и переименовывается в
`status.json` в том же каталоге — ни одно имя там root повторно не открывает
(переименование заменяет симлинк, а не его цель). Файлы только удаляются
(`rm -f` удаляет саму ссылку), рекурсивного удаления нет. Установщик
(`scripts/06c-homekit.sh`) в `/run/sa02m-homekit` не пишет вовсе: пока статуса
нет, диспетчер выводит `disabled` из конфига (§10, правило слияния).

Каталоги: `/etc/tmpfiles.d/sa02m-homekit.conf` (переутверждаются каждым бутом)
и те же режимы в `scripts/06c-homekit.sh`. Этот файл кладёт в `/etc/tmpfiles.d/`
только установщик, из копии в пакете (`opt/sa02m-homekit/tmpfiles.d/`): всё,
что лежит в `etc/tmpfiles.d/` репозитория, OTA доставляет на каждую плату, а
строки HomeKit называют пользователя `sa02m-homekit`, который есть только там,
где модуль установлен. Каждая атомарная запись пакета
(`fsutil.atomic_write`) — временный файл `.hk-*.tmp` в том же каталоге,
`fsync` файла, `rename`, `fsync` каталога; собственный `persist()` HAP-python
(переименование без `fsync`) заменён этим.

Юнит `etc/systemd/system/sa02m-homekit.service`: `User=sa02m-homekit`
(системный, без оболочки и дома) **без группы `www-data`** — ни в юните, ни в
`/etc/group`: слушатель в LAN до сопряжения не должен читать пароль панели
(`/etc/sa02m_web.env`), YAML шлюза, файлы CSRF. Нужное выдано точечно (таблица
выше) обычными группами Unix, **без ACL** — в продуктовом RT-ядре нет POSIX
ACL на ext4 (`docs/decisions/homekit-home-connect.md`): setgid-каталог `/run/sa02m-homekit`
отдаёт CGI файлы 0640; каталог конфига принадлежит `www-data` с setgid-группой
моста, так что конфиг, сохранённый CGI атомарно (временный файл + `rename`),
всегда получает группу моста, и мост его только читает; документ устройств
читается через группу `sa02m-alice-devices` (мост и `www-data`, больше никого:
CGI Алисы заменяет документ переименованием, а не-root может дать новому файлу
только свою группу). Мост читает в `/etc/sa02m-alice` ровно один файл.
Проверка — **действием**, не строками: `usr/local/sbin/sa02m-daemon-access.sh
apply homekit` восстанавливает владельца, группу и режим (каталоги — по строкам
`d` tmpfiles-конфа пакета, файлы — через `O_NOFOLLOW`, только обычный файл с
одной ссылкой и только если он уже принадлежит `www-data` или root с группой
`www-data` либо группой доступа: подложенный symlink, жёсткая ссылка, FIFO,
root:root или чужой файл, переименованный на это имя, — отказ со строкой
«ОШИБКА» и кодом 1) и затем пробует каждое чтение (обычного файла) от имени моста (`setpriv` с его uid,
gid и группами из `/etc/group` — то, что systemd даёт юниту): свой конфиг и
документ устройств читаются, запись в свои каталоги и сохранение CGI работают,
пароль панели и остальные конфиги Алисы — нет, в `www-data` мост не состоит.
Это последний шаг `scripts/06c-homekit.sh` (провал — русская строка с
файлом, выход 1, без OK) и `ExecStartPre=-+` юнита перед каждым стартом
(провал — в журнале юнита, демон стартует и показывает `conf_unreadable`), так
что восстановление, сломавшее режимы, видно и лечится при ближайшем запуске.
Установщик исключает из `www-data` учётную запись, созданную раньше. Гейт
`daemon-least-privilege` (строки), `daemon-access-effect` (действие на
настоящих файлах). Остаток: сброс к заводским, образ и восстановление без
документа устройств создают его `root:www-data` — мост (после сброса он
выключен) прочитает его после ближайшего старта, который вернёт группу.
`ProtectSystem=strict`,
`ReadWritePaths=/var/lib/sa02m-homekit /run/sa02m-homekit`, `NoNewPrivileges`,
`RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX AF_NETLINK`,
`MemoryMax=64M`, `CPUQuota=25%`, `TasksMax=32`, `Nice=10`,
`Restart=on-failure`, `TimeoutStopSec=8s`. `www-data` в группу
`sa02m-homekit` не входит — хранилища пар не читает (P4).

## 14. Жизненный цикл

- **Установка** — только `install.sh --with-homekit` (или
  `SA02M_WITH_HOMEKIT=1`), либо `install.sh` на плате, где мост уже установлен
  (есть пользователь `sa02m-homekit`); `SA02M_SKIP_HOMEKIT=1` — не трогать.
  В сборку образа (`SA02M_ROOTFS_BUILD`) модуль не ставится. Юнит ставится
  выключенным и остановленным (`sa02m_svc_apply … app off`,
  `installer-refresh-policy.md`); повторный запуск обновляет код, не трогая
  конфиг, хранилище пар и решение оператора. Без venv (нет сети и нет
  wheelhouse `/opt/vendor-installers/homekit/`) пакет, юнит и карточка всё
  равно ставятся, а демон отвечает `missing_deps`.
- **OTA и офлайн-пакет** обновляют пакет, юнит, хелпер, sudoers, tmpfiles, CGI
  и JS, но **не устанавливают** модуль (venv, пользователь, каталоги, засевка
  конфига): такая плата показывает `not_installed`. Каталог служб показывает
  строку «Apple HomeKit» только при установленном venv и существующем
  пользователе (юнит, приехавший по OTA, без `User=` стартовать не может).
- **Включение/выключение** — карточка (`enable`/`disable`) или «Пуск»/«Стоп»
  каталога служб: тот синхронизирует `enabled` через тот же
  `sa02m_homekit.config` и зовёт `systemctl` сам. Демон перечитывает конфиг
  каждые 2 с: `enabled = false` → остановка и выход 0.
- **Самовосстановление идентичности (слой 1 защиты клонов).** На старте демон
  сравнивает `sha256(/etc/machine-id)` с `identity.json`; несовпадение или
  отсутствие привязки удаляет `state.json` и хвосты `.hk-*.tmp` (при
  существовавшем хранилище — `reason: identity_regenerated`, запись в журнал) и
  записывает новую привязку. Без `machine-id` привязка не проверяется
  (хранилище сохраняется: стирать пары на каждом старте значило бы сделать мост
  непригодным). Хранилище, не читающееся целиком (битый JSON, нет ключей,
  неверный код или ключ), удаляется с `reason: state_corrupt_regenerated` —
  никогда цикл падений и никогда частичные ключи. В обоих случаях новая
  идентичность для iOS — новый аксессуар: его добавляют в «Дом» заново.
- **Сброс сопряжения** (карточка → `reset_pairing` → хелпер `reset-pairing`):
  удаляются **ровно** `state.json` и `.hk-*.tmp`; `aids.json`, `identity.json` и
  конфиг остаются (aid остаются осмысленными при повторном добавлении). После
  рестарта — новые ключи, новый код, мост снова ждёт сопряжения.
- **Factory reset — СТЕРЕТЬ** (решение Оператора Q-F: при перепродаже
  iPhone прежнего владельца не должны сохранить доступ к реле). Противоположно
  политике идентичности Алисы (та при factory reset сохраняется —
  `image-identity-reset.md` §1): содержимое `/var/lib/sa02m-homekit/` (включая
  `.hk-*`) очищается, конфиг возвращается к шаблону (`enabled = false`).
- **Снятие образа — СТЕРЕТЬ** (слой 2): clear-list, keep-list и площадки —
  `docs/contracts/image-identity-reset.md` §7.
- **Веб-бэкап** — `/var/lib/sa02m-homekit/` не включается никогда (бэкап —
  allow-list путей, `etc/sa02m-web-backup.sh`); конфиг включается, и
  восстановление (`etc/sa02m-restore-backup.sh`) принимает только его.
  Восстановление кладёт конфиг на место и службу не трогает: работающий демон
  сам подхватывает конфиг за 2 с, а включить или выключить службу по
  восстановленному `enabled` восстановление не пытается.
- **OTA** — `/var/lib/sa02m-homekit/` и `/etc/sa02m-homekit/` во всех четырёх
  списках «не разворачивать» (`PRESERVE_PATHS` и `PRESERVE_PREFIXES` раннера,
  `validate_package.py`, `never_deploy` офлайн-карты); активный мост
  перезапускается после обновления, остановленный не запускается
  (`restart_if_active` раннера и офлайн-пакета — один список). Грант
  `etc/sudoers.d/sa02m-homekit`, приехавший по OTA, раннер приводит к 0440.

**Статус исполнения.** Очистка при factory reset реализована
(`erase_owner_state()` в `etc/sa02m-factory-reset-runner.sh`) в две фазы.
Сначала **каждый** юнит, чьё состояние стирается (мост HomeKit, затем клиент
Home Connect, `home-connect.md` §12): конфиг — к шаблону, затем остановка
(под `timeout`) и проверка, что systemd сообщил юнит полностью остановленным.
Только когда остановлены **все** — необратимое: хранилище пар и
`/run/sa02m-homekit/setup.json`, затем вход Home Connect. Отказ любой остановки
— `E_APPLY`: конфиги откатываются, **не стёрто ничего** (клиент Home Connect,
не остановившийся после моста, пар моста уже не стоит); мост, не
остановившийся первым, клиента Home Connect не трогает. Откат после такого
отказа возвращает плату в прежнее состояние: когда конфиги восстановлены,
юниты, которые сброс остановил и которые **до сброса работали**, запускаются
снова (под `timeout`, по мере сил — неудачный запуск пишется в журнал и откат
не прерывает); юнит, не работавший до сброса, остаётся остановленным. Без доверенного шаблона
(пакет отсутствует или его каталоги не root-only) конфиг не заменяется, а в нём
принудительно `enabled = false` — в любом написании ключа, которое читает
`configparser`; шаг идёт последним, после проверки остальной части сброса. Исключение ключей из бэкапа
действует по построению; из защит клонов действуют оба слоя
(`image-identity-reset.md` §7).

## 15. Вне объёма

Режимы термостата Выкл/Охлаждение/Авто и `HeaterCooler` (после этапа B
`sh-model`); несколько кнопок в одном аксессуаре (`ServiceLabel`);
`CarbonDioxidePeakLevel`; резервный классификатор нажатий по фронтам `di_N`;

замки; публикация моста через облачный туннель.
