# Контракт: адресная лента MR-02m LED (RGBW_WS2812, type 120)

Единственный дом границ платы для модуля ленты: опознание, карта регистров,
окно настройки (backend), MQTT-тип `led`. Карта взята из десктопного
прошивальщика (`feat/led-spy-and-picker`); расхождение решается в пользу
**кода** той ветки (в заметке десктопа 81 эффект, в коде — 82).

**Проверено на железе 2026-09-04.** Стенд 192.168.1.135, COM3 **19200**
addr **13** (та же линия, что Carel; заводские 115200 здесь не используются).
Скан опознал сигнатуру `LED`; поллер `led-COM3-13` публикует `power` /
`color` / `temperature`; запись `power/on` 1→0 прошла (PlayCtrl 416),
лента возвращена в выкл. Mixed baud на одном COM по-прежнему не
поддерживается.

Проверка: `py-unit-led`, `led-shared-home`, `py-unit` (поллер в
`opt/sa02m-modbus-mqtt/tests/test_led_poller.py`), `py-unit-flasher`
(`tests/test_led_scan.py`, `tests/test_led_config.py`).

---

## 1. Опознание

Код типа `RGBW_WS2812 = 120`, имя «LED», caps `(0, 4, 0, 0)`. Сигнатура
(`RGBW_WS2812` / `RGBWWS2812` / `RGBW` / `LED`) побеждает Input-регистр 0.
Префикс `LED` как трёхсимвольный **запрещён** — он крадёт сигнатуру Wiren
Board `ledGe`. Лента не цель пакетной прошивки и не FC17-probe.

## 2. Один дом карты

`opt/sa02m-led/sa02m_led/` ставится в `/opt/sa02m-led` помощником
`sa02m_install_led_pkg` из **трёх** путей: `04-flasher.sh`, `05-mqtt.sh`,
`update-www-only.sh`. Потребители: демон прошивальщика и мост MQTT. Копии
карты в дереве не допускаются (`led-shared-home`).

Непереговорные свойства карты (каждое — свой класс тестов):

1. unlock 410 = `0x10C8` → записи в **зависимом** порядке → lock 410 = 0,
   для всего блока 400..419 **включая PlayCtrl 416**;
2. бегущая строка пишется только с базы 516 (64 регистра); база 495
   запрещена — она задевала safe-state ШИМ 503..506;
3. CMD 3 (SAVE_FLASH) не выдаётся;
4. mode-data — ровно один FC03 на 15 регистров с 453; шире 467 — отказ
   всего блока;
5. регистр 418 — read-modify-write; неизвестный prior + неизвестное поле
   → пропуск, не сборка с нуля.

## 3. Окно настройки (backend)

Вид `led`. Снимок: блок 400×20 читается на **каждом** опросе; дорогие
блоки (453 / 494 / 516 / 640) — по вкладке. Spy (640×70) — только для
эффекта 81.

`POST /device_config/led_write` — команда окна ленты под тем же
арендованным сеансом порта (`port_lease`), что и остальные
`device_config`-маршруты; пока на порту идёт задание прошивки — отказ.

Тело запроса: `{"port": "COM3", "device": {…строка скана…}, "action":
"<команда>", "params": {…}, "active_tab": "<вкладка>" | null}`. Allow-list
`action` и параметры: `pwm` (`mode` | `channel` + `value` permille), `di`
(`channel`, `mode` 0/1, `debounce_ms` 10..2000), `strip` (`line`, `led_type`,
`led_count0`/`led_count1`, `pixel_format`, `byte_order`, `auto_refresh` —
reg 418 read-modify-write поверх прочитанного с устройства), `scene` /
`play`, `text` (`text`, `lines`, `colors`), `clock` (`hours` + `minutes` |
`from_pc` | `unset`), `weather` (+ `temp_color`), `spy`, `stop`, `refresh`,
`load_flash` (`slot` 0..31). Неизвестное действие, не-лента в `device` или
плохой параметр отклоняются **до открытия линии** — план записи строится
дважды: чистый разбор до транспорта, затем с двумя прочитанными с устройства
входами (418 и текущий FX id), которые могут только добавить регистр, но не
сделать верный запрос неверным.

Ответ — свежий снимок окна: `{"ok": true, "action": "<команда>",
…snapshot_for_device(active_tab)…}`. Ошибка — **реальный HTTP-статус демона**
с `{"ok": false, "error": …}`: 400 — отклонённый запрос, 404 — нет порта или
устройства, 409 — линия занята / сбой записи (слой прошивальщика, не CGI:
`web-code-rigor.md`, «match the probe to the layer»).

Скобка lock/unlock — свойство регистра из карты, не списка вызывающего; при
сбое записи блок запирается вручную (410 = 0) перед повторным выбросом, чтобы
не оставить 400..419 открытыми на общей линии. Единственная законная блочная
запись — 516. Одиночные write-эндпоинты ленту отказывают, как Carel.

Окно фронтенда (вкладки «RGBW каналы» · «Входы DI» · «Адресная лента» ·
«Сцена» · «Эффекты EXFX») **ещё не подключено** к этому backend.

## 4. MQTT-тип `led`

Поллер `bridge_led.LedPoller`. Инвентарь контролов — `sa02m_led.controls`
(один дом имён). `power` — это PlayCtrl 416, не реле питания; запись
только через скобку 410. `color` — тройка ШИМ R/G/B permille в форме
`#RRGGBB`, той же, что уже читает `sa02m_alice.client.converters`. Текст —
блочная запись cp1251 на 516. Опрос ~2 с, текст ~30 с.

**Смешанный baud на одном COM не поддерживается.** Лента с завода 115200,
Carel на стенде — 19200. Мост ключует порты как `port:baud` и открывает
tty с `exclusive=True`; два ключа на одном физическом порту — второй
open на занятом устройстве, не общая линия. Ленту ставят на свой COM либо
меняют её скорость под линию. Конфликт логируется
`modbus_mqtt_bridge.mixed_baud_port_conflicts`.

Fast Modbus ranges не заявляются: не измерены на модуле.

**4×16×16 метеостанция (стенд 1.135, 2026-09-04).** Регистры часов/даты
не переставлять: 453 = часы 0..23, 454 = минуты 0..59, 457 =
`(день<<8)|месяц` (11:05 → `{453:11, 454:5}`, 04.09 → `0x0409`). Прошивка
1.0.3.0 так и рисует (`fx_wx_put_date` / `svc_time_of_day`). «00:11» /
«09.04» на четырёх тайлах — это **MIRROR_X** (reg 418 bit 2, `0x04`),
холст справа налево. Зеркало по X **выключено**. Поворот 90° по часовой —
**SWAP_XY** (bit 3, `0x08`), не 180° и не против часовой. На стенде
layout `0x0408` (TileCount=4 + 90° CW, MIRROR_X=0). Рецепт:
`rgbw_matrix_layout_4tiles_90cw()`. Две строки метеостанции — **reg 494 = 2**
(`MB2WS_TEXT_LINES_DOUBLE`; 0/1 = одна строка). На стенде 1.135 Алиса
«LED лента» — это свет, не метеостанция: YAML `effect: 0` (STATIC),
`weather_lines` / `text_lines` = 1 (поллер не восстанавливает FX 64 и не
пинит 494=2). `power/on` 1 → RenderSource=FX + FxId 0 + Play; `power/on` 0
→ `rgbw_stop_blank_writes` (STOP + pool + CLEAR_POOL + REFRESH). Layout
`0x0408` остаётся. YAML `led-COM3-13`: `matrix_layout` / `rotate_90_cw` /
`mirror_x` / `weather_lines` / `text_lines` / `effect` / `brightness` —
поллер один раз восстанавливает четыре регистра (418, 494, FX id, FX param =
яркость), если живые значения разошлись; `effect` / `brightness` из YAML при
этом перекрывают выставленные из окна прошивальщика — YAML, который их
задаёт, объявлен их источником. Один факт — одна форма: `matrix_layout`
побеждает `tile_count` / `rotate_90_cw` / `mirror_x`, `weather_lines`
побеждает `text_lines`; вторая форма молча игнорируется. Сбой записи
повторяется на следующих опросах не более трёх раз, затем восстановление
считается выполненным (в журнале — «giving up»): на общей с Carel линии
батч под скобкой 410 не должен выдаваться каждые 2 с до конца жизни
процесса.
