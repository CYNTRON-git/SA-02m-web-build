# Контракт MR: профиль, достоверность состояния и управление

Окно настройки MR и MQTT сохраняют адреса каналов и значения команд,
определённые прошивкой. Поддержка профиля не подтверждает электрическое
срабатывание выхода: ACK, прочитанное состояние и измерение клемм — разные
свидетельства.

## Профиль 6AI2AO

Тип `12`, сигнатура `6AI2AO` и установленный псевдоним `AI6AO2` обозначают
шесть AI и два AO без самостоятельных DI/DO. Префикс MR/MP и суффикс `_bl`
допускаются при распознавании и выборе общей MR-прошивки. Сигнатура и
Input `0` определяют профиль; один только серийный номер из общего диапазона
MP02M не доказывает тип 12.

AI1..6 используют Holding/Input `400 + 7*(ch−1)`. AO1/2 используют `33/34`,
безопасные значения — `503/504`. Список записи запрещает измерительные
смещения AI, AI7, AO3 и чужие слоты фильтров. Условия доступности фильтров
живут в [контракте AI](module-config-ai.md). UI не подставляет схему клемм
другой модели, если собственной схемы нет.

## Достоверность снимка

DO читается полным валидным FC01-ответом либо полным Input-зеркалом.
Оба недоступны или неполны — ошибка, а не массив OFF. Полный нулевой ответ
означает OFF. После потери FC05 ACK команда считается подтверждённой только
при свежем полном чтении с совпадающим адресованным битом. Автоматического
повтора FC05 нет.

Обязательные данные выбранного снимка: DO, DI Input `18..`, AO Input `33..`,
AI-конфигурация и запрошенные AI-измерения. Неполный обязательный блок
останавливает снимок через обычный ответ ошибки демона (HTTP `409` для
ошибки чтения). Данные сканирования служат описанием, а не доказательством
доступности устройства.

Окно сохраняет предыдущий успешный снимок и ввод пользователя, показывает
постоянную ошибку обновления и снимает её после следующего успешного снимка.
Независимая ошибка записи при восстановлении опроса не стирается. До первого
успешного чтения отсутствующие состояния показываются `—`. Общий бюджет
запроса настройки `120000 ms` включает получение заголовков и всего JSON,
включая ошибочный HTTP-ответ; завершение по таймауту освобождает очередь.

Необязательные uint32-счётчики при неполном ответе возвращаются `[]`, а
отсутствующие элементы показываются `—`, в том числе после фонового опроса.
Нули допустимы только из полученных данных. Необязательное битовое зеркало
также возвращает `[]` при неудаче. Достоверность необязательных настроек и аварий
AI описана в [контракте AI](module-config-ai.md); режимов и статусов реле —
в [контракте реле](module-config-relay.md). Старые bool/числовые поля сохраняют
типы для совместимости, но без соответствующего признака достоверности не
подтверждают отсутствие аварии или прочитанную настройку.

## Единицы 4TO6DI

Тип `15` передаёт и принимает AO raw `0..1000`. Окно настройки и MQTT
отображают `raw / 10` в процентах; обычные AO сохраняют отображение
`raw / 100` в вольтах. Для исходного MQTT payload единица типа 15 — `‰`.
Команда яркости не включает DO автоматически, открытие окна и переключение
вкладок не отправляют команд выходам. Wire-контракт записи находится в
[mqtt-set-endpoint.md](mqtt-set-endpoint.md).

## Проверки и границы

`test_mr_readback_truth.py` проверяет реальные кадры Modbus, ACK-loss и HTTP
dispatch с подменой только транспорта/аренды. `test_mr_module_matrix.py`
закрепляет профили, адреса, версионный запрет и выбор single/batch MR app
реальным runner. `test_mr_ao_units.py` закрепляет raw MQTT poll/writeback,
метаданные и отказ воспроизведения retained `/on`.

`test-flasher-readback-truth.mjs` проверяет окно в Chromium, сохранение ввода,
неизвестное состояние, исчезнувшие счётчики и зависшее HTTP-тело.
`test-mr-ao-units.mjs` проверяет типы 15/3/12 и настоящие HTTP-команды обоих
интерфейсов. Эти тесты не заменяют измерение клемм или проверку каждой
физической модификации. TENZO2 не входит в серийные профили этого контракта.
Файлы конфигурации описаны в [своём контракте](module-config-file.md).

## Подтверждение команд MQTT

MR DO/AO выполняют одну запись и читают адресованный выход. Публикуется только
фактически прочитанный coil или raw AO; подтверждение повторяется и для
неизменившегося значения. Результат определяется парой ACK/чтение:

| ACK | Чтение | Публикация |
| --- | --- | --- |
| Получен | Совпадает с командой | Фактическое значение, без `w` |
| Получен | Другое значение | Фактическое значение, без `w`: возможен режим или задержка |
| Потерян | Совпадает | Фактическое значение, без `w`; выполнение именно этой команды не доказано |
| Потерян | Другое значение | Фактическое значение и адресный `w` |
| Любой | Ошибка или невалидный ответ | Только адресный `w`, без нового значения |

Автоматического повторения команды и записи режима 130 нет. Эти результаты не
подтверждают контакт или напряжение на клеммах. После команды старые события
выхода FMB удерживаются до свежего чтения и валидированного пустого ответа
собственного slave; подробности в [контракте FMB](fmb-event-wire.md).

Кнопка MQTT сохраняет последнее наблюдаемое состояние и явно показывает ожидание.
HTTP `ok` означает публикацию команды. Таймаут говорит только, что заданное
состояние не наблюдалось, и не доказывает отказ физического выхода.

DO принимает после trim только `0`/`1` и `true`/`false` без учёта регистра.
Пустой, иной или невалидный UTF-8 payload не попадает в очередь. AO и AI-type
отклоняют nonfinite значения (`inf`, `-inf`, `nan`, overflow); прежняя обработка
конечных значений и диапазонов сохраняется. Для MR через `rtu_tcp` после попытки
отправки FC05/FC06 нижний повтор при устаревшем соединении отключён. Отдельное
переподключение для чтения результата допустимо; поведение других устройств и
обычных чтений не меняется. Это закрепляют `test_mr_writeback_readback.py`,
`test_mr_fmb_output_ordering.py`, `test_mr_rtu_tcp_write_once.py` и браузерный
`test-mqtt-mr-readback.mjs`.
