# Допуск зависимостей Node-RED к выпуску

Для этого выпуска пользователь явно выбрал официальный npm Security API. Critical и High блокируют выпуск; Moderate, Low и Info остаются в отчёте с владельцем дальнейшей работы. Неизвестная тяжесть, неполные данные, неверный диапазон версий или ошибка сети дают `INDETERMINATE` и ненулевой код. Исключения не утверждены и отклоняются. Неудачные проверки provenance OSV сохранены отдельно; OSV отложен и не используется как скрытый резервный провайдер.

Политика и покрытие находятся в `vendor-src/nodered/admission-policy.json`, реализация — `scripts/dev/nodered-admission.py`. Область проверки: lock Node-RED и рекурсивный состав точного архива, включая вложенные пакеты npm и поставленные примеры `package.json`. Python, HomeKit, dev-зависимости, ОС, ядро и нативный Node.js остаются вне этого допуска. Неисполняемый пример не исключается из запроса автоматически.

Перед запросом сверяются SHA-256 исходных manifest/lock, релизного manifest, архива, inventory, политики и проверяющего скрипта. Inventory сравнивается с содержимым архива, а количество записей — с coverage. Полный запрос содержит объединение всех name/version из lock и архива; повторные физические копии сохраняют все пути в отчёте.

Запрос идёт только по проверяемому HTTPS на `https://registry.npmjs.org/-/npm/v1/security/advisories/bulk`. Требуются HTTP 200, полный JSON, ограничение размера и времени. Пустой успешный ответ означает отсутствие возвращённых advisory для отправленного запроса; API не возвращает отдельное подтверждение обработки каждого пакета. Поэтому сохраняются точные байты запроса, его SHA и все счётчики. Ошибка не заменяется пустым ответом. Совпадение версий с `vulnerable_versions` вычисляет upstream semver из того же проверенного архива, исполняемый закреплённым Node 22.23.5; собственного движка сравнения версий нет. Тяжесть берётся из официального поля advisory, а не из отсутствующего CVSS.

## Запуск и срок действия

В Linux amd64 из корня репозитория:

```sh
python3 scripts/dev/test-nodered-admission.py
python3 scripts/dev/nodered-admission.py scan \
  --artifact-dir /path/to/exact/payload \
  --tool-dir /path/to/node-v22.23.5-linux-x64/bin --out /path/to/new/report
python3 scripts/dev/nodered-admission.py check \
  --artifact-dir /path/to/exact/payload \
  --tool-dir /path/to/node-v22.23.5-linux-x64/bin --out /path/to/report
```

`scan` выполняет свежий онлайн-запрос после фиксации зависимостей. `check` повторно сверяет входы, raw-ответ, исходящий запрос и решение, заново применяя upstream semver. Успешный отчёт действует не более 24 часов от начала сканирования только для неизменных входов, политики и инструментов. Время из будущего, изменившийся SHA или просроченный отчёт отклоняются. Повторное использование сохраняет исходное время. Новый неуспешный `scan` не получает допуск из прежнего отчёта.

В отчёте сохраняются `provider:npm`, входные SHA, `query.json`, `raw.json`, диапазоны и результаты upstream semver, все найденные версии/пути/идентификаторы, владелец дальнейшей работы и `admission.json` со статусом `PASS`, `FAIL` или `INDETERMINATE`. Локальные тесты не заменяют онлайн-запрос и не доказывают полноту внешней базы.

Первичные описания: [npm bulk advisory endpoint](https://docs.npmjs.com/cli/v11/commands/npm-audit#bulk-advisory-endpoint), [upstream semver](https://github.com/npm/node-semver).
