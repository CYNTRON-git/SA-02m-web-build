# Контракт: Modbus TCP в мосте Modbus→MQTT (`transport: tcp`)

Единственный дом правил, по которым мост SA-02m опрашивает устройство **по сети
Ethernet (Modbus TCP)**, а не по линии RS-485: грамматика YAML, коды отказов,
запрещённые адреса, какие типы устройств допускаются, жизненный цикл
соединения, пределы и что проверено на оборудовании. Машинная грамматика
(ключи YAML, коды отказов, имена) — на английском (`PROTOCOL.md` invariant 5);
пояснения — на русском. С релиза 1.0.6.56.

Реализация: `opt/sa02m-modbus-mqtt/bridge_bus.py` (выбор транспорта и
валидатор — один дом правил; только stdlib, его импортирует и CGI),
`opt/sa02m-modbus-mqtt/bridge_tcp.py` (клиент `ModbusTcpClient`, пул
`get_tcp_client`), `bridge_device.py` (`DevicePoller.bus`),
`modbus_mqtt_bridge.py` (`compose_pollers`).

## 1. Гарантия

Устройство `type: template` или `type: carel` с `transport: tcp` опрашивается по
Modbus TCP и получает **тот же наблюдаемый MQTT-контракт**, что и на RS-485:

- шаблон — `docs/contracts/template-device.md` §5;
- Carel — `docs/contracts/carel-ahu.md` §5 (контролы, meta, планы записи,
  журнал записей);
- оба — `/devices/<id>/meta/error = "r"` после `offline_after_fails` неудачных
  чтений и снятие флага при первом успешном; последовательность публикаций при
  обрыве и восстановлении совпадает с RS-485 (закреплено тестами одного
  сценария на обоих транспортах).

Устройство по TCP **никогда не открывает, не арендует и не показывает
COM-порт**: у него нет `port_path`, оно не попадает в `_roster.json`
(`docs/contracts/rs485-roster.md`) и в проверку «один порт — одна скорость».

Запись без `transport` (или `transport: rtu`) — поведение RS-485 байт в байт как
до 1.0.6.56. Невалидная TCP-запись **отклоняется** (устройство пропускается с
одной строкой ERROR в журнале, остальной парк работает) — её никогда не
превращают молча в RS-485 и к ней никогда не подключаются.

## 2. Грамматика YAML

```yaml
- id: mp02-ahu-tcp-192_168_1_20-1
  type: template
  template: mp02-ahu
  transport: tcp          # absent | rtu = the serial path, unchanged
  host: 192.168.1.20      # strict IPv4 dotted-decimal literal, no leading zeros
  tcp_port: 502           # 1..65535, default 502
  address: 1              # unit id 1..255 (0 = broadcast, refused), default 1
  tcp_timeout_s: 1.0      # 0.2..5.0, default 1.0
  poll_s: 2
- id: carel-tcp-192_168_1_50-1   # MUST start with `carel-`
  type: carel
  family: crst            # REQUIRED on tcp: crst | uaria
  app_version: 2.03.00.46 # recommended on tcp for crst
  transport: tcp
  host: 192.168.1.50
  tcp_port: 502
  address: 1
  poll_s: 2
```

| Ключ | Значение | Примечание |
|---|---|---|
| `transport` | `tcp`; отсутствует или `rtu` — RS-485 | любое другое значение — отказ |
| `host` | IPv4 `a.b.c.d`, каждое число 0…255 без ведущих нулей | только цифры: без имён, без DNS, без IPv6. Подключение идёт по каноническому виду адреса |
| `tcp_port` | 1…65535 | по умолчанию 502 |
| `address` | 1…255 | номер устройства (unit id); 0 — широковещательный, ответа на него нет |
| `tcp_timeout_s` | 0.2…5.0 | ограничивает и подключение, и ожидание каждого ответа |
| `port`, `baudrate` | **запрещены** на TCP-записи | противоречие; другие читатели YAML (инвентарь Алисы) отнесли бы устройство к COM-порту |
| `family` (Carel) | `crst` \| `uaria` | на TCP обязательно (§4) |

Идентификатор: окно «Добавить устройство» генерирует `<шаблон>-tcp-<a_b_c_d>-<адрес>`
и `carel-tcp-<a_b_c_d>-<адрес>` (точки → подчёркивания). Для Carel префикс
`carel-` — **соглашение, на которое опираются потребители** (вкладка
«Устройства» ищет `carel-*.json`, Алиса — `/devices/carel-`), но не правило
валидатора: запись с другим id работает в MQTT, но не попадёт в эти экраны.

Несколько устройств за одним `host:tcp_port` (шлюз TCP→RTU) делят **одно**
соединение; запросы к ним идут по очереди. Таймаут соединения — из первой
записи с этим адресом и портом; если следующая запись на том же адресе просит
другой `tcp_timeout_s`, мост пишет одно WARN на адрес («… ignored — endpoint
already opened with … (first entry wins)») и оставляет первый. В окне панели
поля таймаута нет — расхождение возможно только при ручной правке YAML.

## 3. Коды отказов

Одни и те же коды возвращают и мост (журнал `device <id> refused: <code>`), и
`mqtt_config.cgi` при сохранении (`{"ok":false,"error":"invalid_device","id":…,"reason":<code>}`,
сохранение отклоняется целиком, файл не пишется).

| Код | Когда |
|---|---|
| `transport_unknown` | `transport` есть, но это не `rtu` и не `tcp` |
| `type_not_tcp_capable` | тип устройства не `template` и не `carel` |
| `carel_family_required` | Carel по TCP без `family` из `crst`/`uaria` |
| `host_missing` | у TCP-записи нет `host` |
| `host_not_ipv4_literal` | `host` — не строгий IPv4 (имя, ведущий ноль, `0177.0.0.1`, IPv6, лишние пробелы) |
| `host_forbidden` | адрес из запрещённых (§5) |
| `tcp_port_invalid` | `tcp_port` вне 1…65535 |
| `unit_invalid` | `address` вне 1…255 |
| `timeout_invalid` | `tcp_timeout_s` вне 0.2…5.0 |
| `serial_keys_on_tcp` | у TCP-записи есть `port` или `baudrate` |
| `tcp_endpoint_limit` | больше 16 разных `host:tcp_port` (17-й и дальше отклоняются) |

Если на плате нет модуля-валидатора, `mqtt_config.cgi` отвечает
`{"ok":false,"error":"transport_validator_unavailable"}` на любое сохранение с
TCP-записью; сохранение только RS-485 проходит как раньше. GET отдаёт
`capabilities` (`tcp_types`, `carel_families`, `tcp_default_port`) только когда
валидатор импортируется — иначе окно не предлагает Ethernet. Причина
(не удалось импортировать `bridge_bus`) в обоих случаях пишется в stderr
эндпойнта — на плате это журнал ошибок nginx.

**Кто решает.** Последнее слово — за мостом: `/etc/sa02m-modbus-mqtt.yaml`
имеет права `0660 root:www-data`, его может переписать любой процесс www-data в
обход CGI. Проверка при сохранении — ранний понятный отказ, не защита.

## 4. Какие устройства по сети

| Тип | По TCP | Почему |
|---|---|---|
| `template` | да | карта регистров задаётся шаблоном, транспорт ей безразличен |
| `carel` | да, `family` обязателен | на RS-485 мост узнаёт семейство командой опознания (FC17); по Ethernet Carel это не проверено, а неверное семейство — чтение и запись чужой карты (int16×10 вместо float32) |
| `mr02m`, `dtv`, `ce02m3`, `led` | нет | только RS-485 (Fast Modbus — широковещание по линии) |

Для Carel c.pCOmini по TCP рекомендуется `app_version`: без версии (нет ответа
на FC17 и нет ключа) выбирается таблица состояний v2 — неверный текст состояния
для прошивок старше 2.02.xx.52. Мост пишет об этом одну строку WARN при старте.

## 5. Запрещённые адреса

`127.0.0.0/8` (loopback: брокер 1883, API 8765 и другие службы самой платы),
`0.0.0.0` (это тоже сама плата), `224.0.0.0/4` (multicast), `240.0.0.0/4`
(зарезервированные, включая `255.255.255.255`). Разрешены частные, публичные и
link-local (`169.254/16`).

Сама плата по любому её адресу (в том числе полученному по DHCP) отсекается уже
при подключении: если адрес своей стороны соединения равен адресу другой, мост
закрывает соединение и пишет один раз ERROR «refused: target is this board».
Иначе мост «ходил бы сам в себя» через собственный шлюз RS-485 на портах
502–506 и занимал бы COM-линию в обход аренды (`docs/contracts/gateway-network-access.md`).

## 6. Жизненный цикл соединения

| Что | Правило |
|---|---|
| Подключение | один сокет на `host:tcp_port`, `TCP_NODELAY`, таймаут `tcp_timeout_s`, без DNS |
| Кадр | MBAP: номер транзакции (счётчик, по кругу), протокол 0, длина, unit. Ответ читается ровно по длине из заголовка через любые паузы до таймаута; проверяются номер транзакции, протокол, unit и код функции |
| Ответ-исключение | ошибка «Modbus exception N on FCxx», соединение остаётся |
| Чужой ответ, таймаут, обрыв посреди ответа | соединение закрывается, следующая операция подключается заново |
| Устаревшее соединение | ОДНА прозрачная переотправка — только на уже использованном соединении и только если отправка не удалась или соединение закрылось до первого байта ответа (перезагрузка устройства, закрытие по простою 300 с у MP-02). **После таймаута не переотправляется никогда** — запись могла уже примениться |
| Отказ подключения | окно 1 → 2 → 4 → 8 → 10 с (не больше 10 с), внутри окна операции завершаются сразу без сети; окно сбрасывается первым успешным обменом. Подключение, принятое и тут же сброшенное (у MP-02 заняты все 7 сессий), считается отказом подключения |
| Номер устройства молчит | устройство принимает соединение, но не отвечает на этот unit (шлюз TCP→RTU с отключённым ведомым, устройство ждёт другой номер): после 3 таймаутов подряд ЭТОТ номер получает своё окно 1 → 2 → 4 → 8 → 10 с, внутри окна запросы к нему завершаются сразу без сети. Окно своё у каждого номера — остальные устройства за тем же шлюзом опрашиваются как обычно; сбрасывается первым ответом этого номера |
| Приоритет записи | запись из MQTT обгоняет опрос, как на RS-485 |
| Статистика | строка раз в 60 с: `tcp reconnects=+N timeouts=+N` вместо счётчиков UART |
| Журнал | «connected» — INFO при первом подключении и после отказа подключения; переподключение после таймаута — DEBUG (считается в `reconnects`). Молчащий номер — одно WARN на серию и одно INFO «unit N answering again» при возврате. Офлайн-устройство журнал не заполняет |

Задержка восстановления после возврата связи — не больше отката устройства
(`backoff_max_s`, 30 с) плюс окно клиента (10 с — окно подключения или окно
молчащего номера, оба не больше 10 с), около 40 с.

Строка «device offline» в журнале для TCP-устройства называет адрес и номер
устройства (`… (192.168.1.50:502 unit 1)`). Если устройство на Ethernet молчит
на `address: 1`, попробуйте `address: 255` — часть устройств отвечает только на
него.

## 7. Известные ограничения

- **Прошивка модулей RS-485 останавливает весь мост** (аренда порта флешером,
  `etc/sa02m_flasher.conf`), поэтому на её время сетевые устройства тоже
  пропадают из MQTT, Алисы и сценариев на минуты (решение Оператора 2026-09-27).
- У Modbus TCP нет аутентификации: узел сети, выдающий себя за адрес
  устройства, может подавать ложные значения. Рекомендуется статический IP
  устройства и отдельная технологическая сеть (VLAN).
- Если устройство сменило адрес (DHCP), оно остаётся «нет связи», пока не
  исправлен `host`.
- На СА-02м-2 (2×Ethernet) мост может связать два сегмента сети.
- Не поддерживаются: IPv6, имена хостов, RTU-over-TCP и прозрачный режим как
  клиент, Fast Modbus по TCP, окно настроек Carel во флешере по TCP.

## 8. Потребители

- Вкладка «Устройства»: id `carel-tcp-<a_b_c_d>-<адрес>` разбирается в
  `kind=carel`, адрес и хост без номера порта; подпись карточки
  «Carel c.pCOmini № 1 · 192.168.1.50» (`opt/sa02m-devices/sa02m_devices/stand_devices.py`).
  Архив `carel_samples` хранит TCP-id как любой другой.
- Алиса и «Умный дом» опираются на префикс `/devices/carel-` и id, не на
  COM-порт; в инвентаре у TCP-устройства `port` пустой.
- Вкладка MQTT: столбец «Порт» показывает `host:tcp_port`.

## 9. Что проверено и что нет

| Семейство | Проверено | Не проверено на оборудовании |
|---|---|---|
| Шаблон (MP-02) | клиент и опрос против поддельного Modbus-TCP-сервера в тестах; **на оборудовании** — реальный MP-02 (192.168.1.20:502, unit 1) со стенда 1.135, 2026-09-28, сборка 1.0.6.56: шаги 1–7, 9 и 11 таблицы ниже — PASS (шаг 12 — уборка стенда, не проверка) | квитирование/сброс аварий (шаг 8): команды доставлены, подтверждение по журналу MP-02 запрошено у их команды; обрыв сбросом соединения (шаг 10, REJECT) — на ядре платы не выполним |
| Carel | наша сторона целиком против настоящих значений регистров обоих семейств (сняты со стенда 2026-09-03) и записанных ответов FC17 за поддельным сервером: опрос и расшифровка, пуск и остановка, уставки (uAria — одной записью FC16), журнал записей, ограничение диапазона, запасной путь чтения аварий, «нет связи» и восстановление | отвечает ли родной Ethernet-интерфейс Carel на FC17; какой номер устройства он ждёт (1 / 255 / любой); принимает ли запись уставки uAria одним пакетом; сколько сессий держит и как быстро отвечает |

## 10. «Проверить связь» из окна панели
С 1.0.6.67 окно «Добавить устройство» (вкладка MQTT, способ подключения
«Ethernet (Modbus TCP)») спрашивает плату **до сохранения**, отвечает ли по
введённым `host:tcp_port` устройство с номером `address`. Эндпойнт
`POST cgi-bin/mqtt_tcp_probe.cgi`, модуль `opt/sa02m-modbus-mqtt/bridge_probe.py`
(только stdlib, импортирует только `bridge_bus`). Проверка — подсказка, не
условие: «Добавить» работает при любом ответе (устройство можно настроить до
подачи питания).
**Запрос** — та же запись, которую окно добавило бы в YAML (§2): `type`,
`transport: tcp`, `host`, `tcp_port`, `address`, у Carel `family`; лишние ключи
записи (`id`, `name`, `poll_s`, `template`) не мешают. Порядок до любой сети:
сеанс (`unauthorized`) → только POST (`method_not_allowed`) → токен
`X-SA02M-CSRF` (`csrf`, `error_code: E_CSRF`) → тело не больше 4096 байт
(`body_too_large`) → JSON (`invalid_json`) → **правила сохранения** §3/§5 через
`bridge_bus.device_bus` (`invalid_device` + `reason` — код §3) → одна проверка
на плату одновременно (`probe_busy`). Предел 16 адресов (`tcp_endpoint_limit`) —
правило всего списка, к одной записи не применяется.
**Что делает с сетью** — ровно одно: от имени `www-data`, без sudo, подключается
к `host:tcp_port` (таймаут 1 с, без DNS — адрес уже канонический), посылает
**один** запрос FC03 «1 регистр с адреса 0», ждёт ответ до 1 с и **всегда
закрывает соединение**. Никогда не пишет, не повторяет запрос, не шлёт FC17, не
держит сессию (у MP-02 7 сессий). Весь вызов ограничен оболочкой: 8 с
(`probe_timeout`), при недоступном модуле — `probe_unavailable` (закрыто, причина
в журнале ошибок nginx). Сама плата отсекается после подключения тем же
правилом, что у моста (§5).
**Ответ** `ok: true`, когда проверка выполнена, — вердикт и есть результат:
`{"ok":true,"verdict":"device_ok","host":"192.168.1.20","tcp_port":502,"address":1,"exception":null,"elapsed_ms":41}`.
| `verdict` | Что значит | Как определяется |
| `device_ok` | TCP принят, устройство с этим номером ответило | номер транзакции, протокол, unit и код функции ответа совпали |
| `device_exception` | TCP принят, устройство ответило исключением (`exception` — код) | бит 0x80, номер транзакции и unit совпали: устройство живо, регистр 0 просто не читается |
| `unit_silent` | TCP принят, ответа нет за 1 с | шлюз TCP→RTU с неверным или выключенным ведомым; устройство не отвечает на этот номер |
| `not_modbus` | TCP принят, но ответ — не MBAP на наш запрос | протокол ≠ 0, длина вне 2…254, чужие номер транзакции/unit/функция, обрыв посреди ответа (например веб-сервер) |
| `tcp_refused` | соединение отклонено | хост в сети, на порту нет службы; также «принято и сразу сброшено» (заняты все сессии) |
| `tcp_timeout` | нет ответа на подключение за 1 с | хост выключен, не в этой подсети или фильтруется |
| `tcp_unreachable` | нет маршрута | `EHOSTUNREACH` / `ENETUNREACH` — подсеть платы не та |
| `self` | адрес — сама плата | адрес своей стороны соединения равен адресу другой (§5) |
«Связь есть» ⇔ `verdict` ∈ {`device_ok`, `device_exception`}. Непредвиденная
ошибка внутри проверки — `{"ok":false,"error":"probe_failed","detail":<класс>}` и
строка в журнале ошибок, не вердикт. Окно показывает неизвестный вердикт как
«не выполнена», никогда как «отвечает».
**Чего проверка не доказывает:** что выбран верный шаблон или карта регистров,
что Carel того семейства, что устройство ответит на другие регистры или при
нагрузке опроса. Для RS-485 кнопки нет — там порт арендуется, опрос шины делает
`mqtt_scan.cgi`.
**Граница (почему это не «сканер портов»):** цель — только запись, которую
принял бы мост при сохранении; одна проверка на плату одновременно, каждая не
дольше ~2 с сети; только чтение; ответ не подробнее, чем журнал моста после
сохранения (подключено / отказ / таймаут / исключение); без привилегий. Тот же
сеанс уже имеет `cmd_exec.cgi` — проверка уже, медленнее и не даёт новой
возможности (`docs/threat-model.md` §4).
