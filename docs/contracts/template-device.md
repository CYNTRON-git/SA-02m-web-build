# Контракт: устройство `type: template` (Modbus→MQTT мост)

Домашний адрес контракта для данных-управляемого типа устройства `template` в
`/etc/sa02m-modbus-mqtt.yaml`. Мост читает JSON-шаблон в WB-формате, разворачивает
его каналы в список опроса и публикует их по тем же конвенциям Wiren Board MQTT,
что и штатные семейства `mr02m`/`dtv`/`ce02m3` — без ручной карты регистров.
Машинная грамматика (имена и формы JSON, схема шаблона) — на английском
(`PROTOCOL.md` invariant 5); прозаические пояснения — на русском.

**Только механизм (решение Оператора 2026-08-17).** Мост читает любой JSON,
лежащий в каталоге шаблонов; ни один файл-шаблон Wiren Board в репозиторий НЕ
вкладывается — их LICENSE ограничивает использование оборудованием Wiren Board,
а SA-02m — это Allwinner A40i. В `templates/` лежат и собственные шаблоны
семейства CYNTRON, и шаблоны, которые кладёт интегратор; перечень поставляемых —
`opt/sa02m-modbus-mqtt/templates/README.md`.

Реализация: `opt/sa02m-modbus-mqtt/bridge_template.py` (`TemplatePoller`);
регистрация типа: `POLLER_CLASSES["template"]`
(`opt/sa02m-modbus-mqtt/modbus_mqtt_bridge.py`).

## 1. YAML-запись устройства

```yaml
- id: example-COM5-30       # MQTT device id (/devices/<id>/...)
  type: template
  template: example         # bare name → templates/config-<name>.json
  port: /dev/COM5
  baudrate: 9600            # WB default line is 9600; per device
  address: 30               # Modbus slave address
  name: "Example (COM5 addr=30)"
  poll_s: 2                 # base poll cadence for the template channels
  # fmb_event_channels: ["Pressure"]  # optional, serial only; exact channel name
  # optional availability keys inherited from DevicePoller:
  # offline_after_fails, backoff_base_s, backoff_max_s
```

Устройство-шаблон можно опрашивать и по сети Ethernet (Modbus TCP): вместо
`port`/`baudrate` запись несёт `transport: tcp`, `host`, `tcp_port` —
грамматика, коды отказов и пределы в `docs/contracts/bridge-modbus-tcp.md`.

`template` — **bare name**; резолвер ищет `config-<name>.json`, затем
`<name>.json` в каталоге шаблонов. Каталог: `templates/` рядом с
`bridge_template.py` (на устройстве `/opt/sa02m-modbus-mqtt/templates/`),
переопределяется переменной окружения `SA02M_WB_TEMPLATES_DIR` (тест-шов).

## 2. Резолвер пути и безопасность обхода каталога

`_resolve_template_path(name)` — **fail-closed**. Значение `template:` приходит
из YAML, записываемого веб-CGI, и считается недоверенным. Правила:

- допускается только имя `^[A-Za-z0-9._-]+$` (без `/`, без `..`, не абсолютное);
- итоговый путь обязан лежать строго внутри каталога шаблонов (проверка
  `realpath` — родитель разрешённого файла == каталог шаблонов);
- имя, не разрешаемое в существующий файл, → устройство **пропускается** с
  записью ERROR в лог; остальные устройства продолжают опрос (fail-open для
  флота, fail-closed для плохого устройства — оно не публикует ничего).

## 3. Поддерживаемое подмножество схемы (v1)

Мост и веб-каталог читают каналы из `device.channels`. Вложенные группы
с собственным списком `channels` разворачиваются рекурсивно.

Идентификатор устройства может задавать иерархию, например `room/strip`. Каждый
уровень содержит литеральное имя. Пустые уровни, `.` и `..` запрещены. После
первого уровня зарезервированы `controls` и `meta`, поскольку эти ветви принадлежат
вышестоящему устройству. Имя канала занимает ровно один уровень и не содержит `/`.
Допускаются пробелы, кавычки и печатный Unicode. Имена с `+`, `#`, NUL,
управляющими символами, суррогатами или некодовыми точками Unicode исключаются.
Полная тема, включая `/meta/precision`, должна помещаться в 65535 байт UTF-8.
Числовые идентификаторы устройств по-прежнему поддерживаются. При недопустимом
идентификаторе устройства мост сообщает `invalid_device_id` до регистрации
опросчика. Недопустимое имя активного канала отражается в журнале с причиной.
Остальные каналы этого шаблона остаются в каталоге, опрашиваются и принимают
команды. Для управления мост подписывается на точную тему конкретного выхода.
Ранее сохранённая брокером команда `/on` при переподключении пропускается.
Снимок текущих значений всегда хранится одним файлом в каталоге кэша. Для
вложенных, зарезервированных и слишком длинных имён мост использует имя файла
с SHA-256 от полного идентификатора в UTF-8. Поле `device` внутри снимка и
топики MQTT содержат исходный идентификатор. В URL пробел кодируется как `%20`.

| Поле | Значения v1 | По умолчанию |
| --- | --- | --- |
| `reg_type` | `coil`, `discrete`, `input`, `holding` | — (обязательно) |
| `address` | целое либо десятичная/шестнадцатеричная строка (например, `"0x10d9"`). Весь канал должен помещаться в адреса 0…65535 | — (обязательно) |
| `format` | `u16`, `s16`, `u32`, `s32`, `float` (для `input`/`holding`) | `u16` |
| `word_order` | `big_endian`, `little_endian` (для 32-бит) | `big_endian` |
| `scale` | конечное число, в том числе в числовой строке. Для записи в holding требуется ненулевой множитель | `1` |
| `offset` | конечное число, в том числе в числовой строке | `0` |
| `units` | строка (WB units → авто-precision) | `""` |
| `type` | WB control type (`value`/`switch`/`temperature`/…) | `value` (бит: `switch`) |
| `readonly` | bool | `true` |
| `enabled` | bool (`false` — канал исключён молча) | `true` |
| `min` / `max` | число в единицах канала (диапазон записи) | — (мостом не читается: принимается и игнорируется; его читает окно настроек MTD прошивальщика) |

Датчик присутствия MTDx62-MB (шаблон `mtdx62-mb`): окно настройки, смена
адреса/скорости и перенос записи моста — `mtd-presence.md`.

- `coil`/`discrete` — 1 бит, `format` игнорируется, значение `0`/`1`.
- 32-бит `u32`/`s32`/`float` читают 2 слова; `big_endian` = слово по младшему
  адресу является старшим словом.
- Значение = `raw * scale + offset`; целочисленный формат без scale/offset
  публикуется как целое, иначе округляется по WB-precision единиц.
- При недопустимом `scale`, `offset`, типе управляющего флага или текстового поля
  мост пропускает этот канал и указывает поле в журнале. Если измеренное
  IEEE-значение или результат пересчёта равен NaN либо бесконечности, канал
  получает `/meta/error=r`. Следующее конечное показание снимает ошибку.
- `device.setup` — список инициализирующих записей в holding-регистры
  (`{address, value}`, только целые из самого файла-шаблона — доверенный вход,
  никогда не из запроса/пользователя).
- Записываемый канал: `holding`/`coil` с `readonly:false` → подписывается
  writeback (`/devices/<id>/controls/<name>/on`), плечо базового `DevicePoller`.
  **Writeback только 16-битный (v1):** записываемый `holding`-канал с 32-битным
  форматом (`u32`/`s32`/`float`) **пропускается ГРОМКО** (WARN, writeback не
  регистрируется) — фактически остаётся read-only. Одно-регистровая запись
  затронула бы лишь младшее слово (`address+1` осталось бы старым), а echo вернул
  бы задуманное значение — тихая мис-запись. Много-регистровая запись требует
  проверки на оборудовании и в v1 не реализуется.
- **Запись вне диапазона формата отклоняется.** Payload `/on` пересчитывается
  в сырое слово `round((value − offset) / scale)`; если оно не помещается в
  формат канала (`s16`: −32768…32767, `u16`: 0…65535), записи на шину нет —
  сырое значение никогда не «заворачивается» по модулю 2¹⁶. Отказ идёт тем же
  путём, что и нечисловой payload: WARN в лог с id устройства, именем канала,
  значением и диапазоном; `/meta/error` канала = `w`; значение контрола не публикуется
  (echo нет — MQTT держит прежнее значение до следующего опроса).

**Групповое чтение (поля объекта `device`, семантика Wiren Board).** Без этих
полей устройство опрашивается как раньше — один запрос на канал в порядке
шаблона.

| Поле `device` | Значение | По умолчанию |
| --- | --- | --- |
| `max_read_registers` | предел одного запроса, в регистрах (`input`/`holding`) или битах (`coil`/`discrete`); `1` — без группировки; `0` или больше 125 (регистры) / 2000 (биты) — максимум протокола | `1` |
| `max_reg_hole` | сколько незаявленных регистров можно прочитать и выбросить, чтобы склеить соседние каналы в один запрос | `0` |
| `max_bit_hole` | то же для битов | `0` |

- В один запрос склеиваются только каналы одного `reg_type`; дыра входит в
  предел `max_read_registers`; канал никогда не делится между запросами;
  каналы с пересекающимися адресами читаются одним запросом.
- Значение, не являющееся целым ≥ 0 (строка, отрицательное, `true`), →
  WARN в лог и умолчание поля.
- **Пачка, которую прибор не принимает, разбивается.** Если пачка не
  прочиталась, мост читает её каналы по одному — значения не теряются. Обычно
  это происходит в том же проходе; если на этом отказе проход обрывается
  (§5, «Молчащее устройство»), дочитывание продолжается со следующего прохода
  с канала после остановки, а саму пачку мост до конца дочитывания повторно не
  запрашивает. Если проба молчавшего устройства (§5) приходится на такую
  пачку, её отказ неотличим от молчания: возвращение устройства стоит ещё одно
  окно back-off, в которое пачка дочитывается по одному.
- Попытка пачки считается отказом, когда пачка не прочиталась, а при
  дочитывании по одному прочитался хотя бы один её канал. После двух таких
  попыток подряд пачка до перезапуска моста заменяется одиночными чтениями
  (одна строка WARN); после перезапуска пачка пробуется заново. Счёт
  обнуляется успешным чтением пачки и попыткой, после которой по одному не
  прочитался ни один канал: тогда молчал весь прибор, а не отвергал пачку.
  Признак — поведение прибора, а не код исключения Modbus: на RS-485 код
  сейчас не доходит до опроса. **Не проверено на оборудовании.**
- Пачка, все каналы которой не отвечают и по одному, не разбивается: каждый
  проход она даёт на один отказ подряд больше, чем те же каналы без
  группировки. Пачка из двух таких каналов — три отказа подряд, и при пороге
  `offline_after_fails` по умолчанию (3) прибор уходит в офлайн, хотя без
  группировки (два отказа) оставался бы онлайн. Такие каналы лучше исключить
  из шаблона (`enabled: false`).
- **Предел по скорости RS-485.** Ответ на запрос N регистров — `5 + 2N` байт, а
  мост ждёт весь ответ не дольше 0,3 с (`bridge_serial.py`, таймаут порта). На
  9600 бод байт идёт ≈1,04 мс: 125 регистров ≈0,27 с, почти без запаса на
  реакцию прибора. На 9600 держите `max_read_registers` не больше ~100; иначе
  пачка упадёт по таймауту и будет разбита (цена — два лишних таймаута).

На встроенных портах платы (`ttyS`) при скорости ≥ 57600 блок регистров длиннее 24 дополнительно делится самим портом (`fifo_safe_read_regs`, 1.0.7.2: ответ должен поместиться в 64-байтный буфер UART); это деление не меняет правила §3 о разбиении и точке возобновления — поллер видит один результат блока; блоки катушек/дискретных входов порт не ограничивает.

## 4. Отложено — пропуск ГРОМКО (WARN + пропуск канала), НИКОГДА не мис-опрос

Мост не выдумывает значение, которое не может честно декодировать. Каждый такой
канал выбрасывается из списка опроса с одной записью WARN:

- битовые адреса-поля (`"address": "reg:shift:width"` — любая строка с `:`);
- форматы `bcd`, `string`, `u64`/`s64`, `u8`/`s8`;
- `byte_order` (перестановка байт внутри регистра; в v1 только `word_order`);
- `consists_of` (составные каналы);
- `condition` (условные выражения включения);
- под-устройства (`device_type`/вложенный `device`);
- Jinja-шаблоны (`*.json.jinja`).

**Guard rail:** если пропущены ВСЕ каналы (полностью неподдерживаемый шаблон =
мис-импорт), мост пишет ERROR и не публикует ни одного control — сбой виден, а
не «наполовину работает».

## 5. Выходное отображение WB-MQTT

Совпадает со штатными семействами:

```
/devices/<id>/meta/name              = cfg.name | device.name | id
/devices/<id>/meta/driver            = "template"
/devices/<id>/controls/<name>                     ← значение канала
/devices/<id>/controls/<name>/meta/type           = WB control type
/devices/<id>/controls/<name>/meta/readonly       = "1" | "0"
/devices/<id>/controls/<name>/meta/units          = units (+ авто precision)
/devices/<id>/controls/<name>/meta/error          = "r" | "w" | ""
```

Ошибка чтения канала (таймаут, исключение Modbus) ставит его `/meta/error` =
`r`; значение не публикуется, в MQTT остаётся последнее прочитанное. Первое
успешное чтение снимает флаг (`""`) — конвенция `docs/MQTT_TOPICS.md`, как у
Carel и ДТВ, через тот же `pub_error`. Флаг, оставленный прошлым процессом
моста, снимает общий сброс при старте (там же, `meta/error`); своего механизма у
шаблона нет. Гейты — `test_template_poller::TestReadErrorFlag` и
`test_pub_error_stale::TestTemplateReadErrorMeetsClear`.

**Молчащее устройство не занимает линию** (решение Оператора 2026-09-30:
память по каналам). Мост помнит по каждому каналу, ответил ли он при своём
последнем чтении у отвечающего устройства. Проход обрывается, когда
`offline_after_fails` чтений подряд не ответили на каналах, которые до этого
отвечали, — устройство перестало отвечать. Канал, отказывавший, когда
устройство отвечало, — сломанный (например, регистр, которого нет в прошивке
прибора): его отказ в счёт обрыва не идёт никогда. Поэтому живое устройство
со сломанными каналами читается целиком каждый проход, а его офлайн, back-off,
`/meta/error` каналов и запись — как без обрыва. Устройство, замолчавшее в
работе — между проходами или посреди прохода, — обнаруживается ровно после
`offline_after_fails` свежих отказов подряд: тот же порог, по которому мост и
без обрыва переводит устройство в офлайн. Так же, как без обрыва,
`offline_after_fails` помех подряд на здоровых каналах дают офлайн и одно окно
back-off — это порог моста, не новая цена; со следующего окна проба (ниже)
возвращает устройство. Первый проход после старта моста истории не имеет и
читает всё: живое устройство со сломанным началом на старте офлайн не бывает,
мёртвое с самого старта стоит один полный проход. Каналы, до которых
оборванный проход не дошёл, получают `/meta/error` = `r`.

Пока устройство молчит, каждое окно back-off стоит один запрос — **проба**:
сначала канал, который ответил последним; если он не ответил, следующее окно
пробует следующий из каналов, отвечавших при последнем чтении (сломанный канал
пробой не бывает); устройство, не ответившее ни разу, пробуется по одному
каналу в порядке шаблона; если сбойным было чтение пачки, проба продолжает её
каналы по одному (§3). Когда проба отвечает, тот же проход дочитывает
остальные каналы в порядке шаблона: вернувшееся устройство читается целиком в
первое же окно после возвращения при любых сломанных каналах и любой длине
простоя, и со следующего прохода опрашивается как без обрыва. Если канал пробы
сломался за время простоя, следующее окно пробует другой — ещё одно окно, не
навсегда.

Цена опроса молчащего устройства:

- мёртвое с самого старта моста — первый проход целиком, дальше один запрос на
  каждое окно back-off;
- замолчало в работе — `offline_after_fails` запросов после последнего ответа
  (сломанные каналы между ними не в счёт и читаются как обычно), дальше один
  запрос на окно;
- вернулось после простоя — один запрос-проба и остальные каналы в том же
  проходе; устройство онлайн в первое окно после возвращения, как без обрыва.

Гейты — `test_template_block_read::TestSilentDevice`,
`::TestLiveDeviceStaysOnline`, `::TestRecoveryProbe` и `::TestStallOnBlock`.

### Быстрые события по RS-485

Идентификатор устройства может включать вложенные уровни, например `room/strip`.
Для доступного на запись канала `relay` прямая команда MQTT в этом случае
публикуется в `/devices/room/strip/controls/relay/on`. Панель показывает
значения и выбор событий для такого устройства. Поле записи появляется только
для разрешённых `mqtt_set.cgi` имён каналов и плоского ID из 1–64 символов
`[A-Za-z0-9._-]`. Остальные команды записи доступны через MQTT в пределах
прав и форматов самого канала.

На последовательной линии оператор может выбрать отдельные каналы установленного
JSON-шаблона для Fast Modbus. Поле устройства `fmb_event_channels` содержит список
точных имён каналов. Отсутствующий или пустой список оставляет обычный режим.
`fast_modbus: false` выключает подписки. Записи Modbus TCP по-прежнему используют
классическое чтение. Поле WB `sporadic` само по себе подписку не включает.

Веб и мост используют общий разбор поддерживаемого подмножества шаблона.
Для события требуются уникальное имя и непересекающийся диапазон адресов в
таблице Modbus. Мост отдельно запрашивает и подтверждает каждый выбранный
начальный адрес. Второй регистр 32-битного значения не образует отдельной подписки.
Неизвестное либо неоднозначное имя пропускается с предупреждением.

Тип, начальный адрес и ширина WB DATA должны совпасть с выбранным каналом.
Для `coil`/`discrete` передаётся один байт со значением 0 или 1. При другом
значении мост пропускает эту запись и обрабатывает остальные записи кадра.
Для `u16`/`s16` передаются два байта, для `u32`/`s32`/`float` — четыре.
Данные события содержат готовое число
младшим байтом вперёд. При обычном чтении `word_order` определяет сборку
двух Modbus-регистров. Затем оба маршрута одинаково применяют формат,
масштаб, смещение, округление и защиту от устаревшего эха записи. Тема MQTT
и метаданные канала общие для обоих маршрутов.

У канала только для чтения событие сразу публикует значение из DATA. Для канала с
управлением (`coil` или однословный `holding` с `readonly: false`) DATA сообщает
о необходимости перечитать конкретный адрес. Прошивка может прислать старую
запись очереди даже после того, как обычное чтение подтвердило новое значение.
Мост ставит адрес в очередь, а в ближайшем свободном срезе обычного опроса
читает состояние прибора и публикует его. Длинный `poll_s` этому чтению не
мешает. Повторные подсказки по одному адресу объединяются. За срез выполняется
до одного дополнительного чтения для этого устройства. Плановый полный опрос
имеет приоритет и тоже подтверждает адрес. При записи во время чтения мост
сохраняет новое эхо и повторяет проверку после интервала защиты. Ошибка чтения
помечает канал `r`, следующее событие или плановый опрос повторяет чтение.

Классический опрос всех каналов сохраняет настроенный `poll_s`, в том числе
при отказе прибора подтвердить подписку или при отсутствии событий. Наличие
канала в веб-пикере описывает карту регистра. Поддержку события прошивкой
конкретного прибора подтверждает ответ прибора на подписку.

Первый опрос начинается при запуске. Для включения подписки нужны два
успешных ответа на классические запросы. Если за первый проход поступил один
ответ, мост в ближайшем срезе один раз проверяет ответивший канал. После
события перезагрузки мост перечитывает состояние прибора в ближайшем срезе
обычного опроса и заново проверяет готовность к подписке.

В конце серии Fast Modbus мост сохраняет один веб-снимок каждого устройства,
у которого изменились показания или ошибки. Поэтому панель и монитор видят
новое состояние до следующего полного опроса. Для записываемого канала в
снимок попадает результат адресного чтения или его ошибка.
[Формат кадров и подтверждения](fmb-event-wire.md)

## 6. Ростер RS-485

`write_bridge_roster` (`modbus_mqtt_bridge.py`) не меняется: `_OUR_DEVICE_TYPES`
остаётся `("mr02m","dtv","ce02m3")`, поэтому устройство `template` корректно
считается сторонним (`ours:false`), а `_roster_model_name` возвращает `""` — это
допустимо (сторонний модуль, модель не из наших таблиц).

## 7. Честность: не проверено на оборудовании

Карты регистров шаблонов **невозможно проверить на стенде без физического
устройства**. Тесты (`opt/sa02m-modbus-mqtt/tests/test_template_poller.py`)
проверяют РАНТАЙМ (разбор → декод формата/word_order/scale → набор публикаций
MQTT против `FakeSerial`), а НЕ соответствие реальному прибору. Веб-пикер
помечает каждый шаблон `verified:false` («не проверено на оборудовании»), пока
Оператор не подтвердит показания на реальном устройстве.

## 8. Последовательная линия: 8N1 по умолчанию, stopbits 1 или 2

Раздел касается только RS-485; у устройства по Modbus TCP параметров линии нет.

Чётность по-прежнему нет (`parity=NONE`). Стоп-биты задаёт поле устройства
`stopbits`: **1** (значение по умолчанию, все модули CYNTRON) или **2**.
`get_port` держит отдельный handle на сочетание порт + скорость + стоп-биты.
Два разных кадрирования одного физического порта не работают: мост пишет
ошибку и второй handle не откроется. Датчик, который отвечает на 8N1, вносится
без `stopbits` и делит линию с уже висящими на ней устройствами. `stopbits: 2`
— только если на 8N1 он молчит, а на 8N2 отвечает, и порт при этом его один.
