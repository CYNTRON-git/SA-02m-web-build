# Контракт транспорта шлюза RS-485

`opt/sa02m-serial-gateway/serial_gateway.py` публикует `running: true` только
после успешного получения UART lease, открытия UART и запуска TCP listener.
Ошибка открытия порта или bind оставляет `running: false` и причину в
`last_error`. Правила `bind` / `allow_from` находятся в
[контракте сетевого доступа](gateway-network-access.md).

## Владение и остановка

Остановка закрывает listener и клиентские соединения, отменяет и дожидается
обработчиков TCP и фонового читателя прозрачного режима. Уже запущенная
операция UART в executor обязательно завершается до закрытия serial descriptor
и освобождения lease координатора. Отмена asyncio-ожидания сама по себе не
останавливает поток executor.

Ошибка закрытия UART удерживает lease и публикует причину; повторная остановка
может завершить закрытие. Ошибка восстановления службы координатором
возвращается вызывающему коду и записывается в `last_error`.
Отмена запуска, остановки или основного цикла также выполняет очистку.

Для `modbus_tcp` и `rtu_over_tcp` на порту выполняется один UART-обмен за раз.
Очередь блокировки обслуживает ожидающих клиентов по порядку. Медленное
чтение TCP-ответа одним клиентом не удерживает UART-блокировку.
Отключение клиента не освобождает её до завершения его текущего UART-обмена.
Прозрачный режим сохраняет передачу произвольных байтов и рассылку UART RX
всем подключённым клиентам.

## Границы запросов RTU-over-TCP

TCP является потоком: фрагменты одного запроса собираются до полной длины,
а несколько запросов из одного чтения выполняются отдельно.
CRC16 Modbus проверяется **до записи в UART**. Неверный CRC, неподдерживаемая
функция, неоднозначная длина или несовпадение количества записываемых
элементов с числом байтов закрывают соединение и увеличивают `errors`;
`last_error` содержит причину. После ошибочного кадра последующие байты этого
соединения не выполняются. Уже выполненный предшествующий корректный запрос
не откатывается.

Поддержанные стандартные запросы; длины включают адрес и два байта CRC:

| Function code | Длина запроса | Условие определения длины |
|---|---:|---|
| `0x01`–`0x06` | 8 | Фиксированная |
| `0x07`, `0x0B`, `0x0C`, `0x11` | 4 | Фиксированная |
| `0x0F`, `0x10` | `9 + byte_count` | Поле `byte_count` после start/quantity; quantity `1..1968` coils либо `1..123` registers; байты соответствуют quantity |
| `0x14`, `0x15` | `5 + byte_count` | Byte count `7..245` либо `7..251` соответственно |
| `0x16` | 10 | Mask Write Register |
| `0x17` | `13 + byte_count` | Write quantity `1..121`, byte count = quantity × 2 |
| `0x18` | 6 | Read FIFO Queue |
| `0x2B`, MEI `0x0E` | 7 | Read Device Identification |

FastModbus:

| Prefix | Длина запроса | Значение |
|---|---:|---|
| `FD 46 01`, `FD 46 02`, `FD 46 04` | 5 | Начало, продолжение, завершение сканирования |
| `FD 46 08` + serial number (4 bytes) + inner PDU | `9 + len(inner PDU)` | Inner PDU определяется той же таблицей стандартных функций |

Максимальный запрос — 262 байта с FastModbus-обёрткой; обычный RTU —
не более 256 байт. В частности, поддержан FastModbus FC16 блок из 123
регистров длиной 261 байт.

`0x08` diagnostics, неизвестные vendor-функции, другие MEI и FastModbus
response/event-команды не угадываются по паузам или границам TCP-пакетов.
Для произвольного обмена такими байтами предназначен `transparent`.
`rtu_over_tcp` не является универсальным туннелем vendor/event-протоколов.

Первый байт ожидается до 30 секунд, остальные байты одного запроса — до
5 секунд суммарно. Неполный запрос по таймауту закрывает соединение без
записи в UART. Буфер чтения TCP использует backpressure с лимитом 1024
байта; сборщик держит только один ограниченный кадр.
UART response timeout составляет 1 секунду, для запросов длиннее 200 байт —
2,5 секунды. Остановка может ждать окончания уже начатой операции; lease
не передаётся другому владельцу ради соблюдения искусственного срока отмены.

## Проверка

`opt/sa02m-serial-gateway/tests/test_transport_lifecycle.py` проверяет все
границы фрагментации поддержанных форм, объединённые запросы, ошибочный CRC,
отказы, несколько клиентов, отмену и ошибки запуска/остановки. Композиционные
тесты используют настоящий TCP, PTY и процесс координатора с реальными
Unix socket, передачей descriptor и `flock`; systemd моделируется.
Это программная симуляция UART, а не доказательство обмена с физическим
модулем RS-485.
