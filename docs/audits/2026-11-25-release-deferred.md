# Аудит выпуска 1.0.8.2: границы и отложенная работа

Этот выпуск предназначен для полного `install.sh --refresh` и последующей
подготовки золотого образа. Он не означает, что весь аудит Linux и безопасности
закрыт. По решению пользователя незавершённая широкая интеграция сохранена
отдельно; в выпуск выбираются исправление systemd parser/CI и проверенный
установщик с закреплённым payload Node-RED поверх ранее проверенной базы.
Результат сборки, независимого ревью, испытаний платы и фактического снятия
образа фиксируется отдельно; наличие этой страницы не подтверждает их успех.

## Решения и обязательные ограничения

- **D1 принято, реализация отложена:** проверка root-пароля должна иметь один
  root-owned счётчик на устройство, 10 неверных попыток за 300 секунд, с отказом
  при ошибке состояния. Параметр `REMOTE_ADDR` от вызывающего процесса не является
  доверенной границей. Обычные web-login и SSH в этот счётчик не входят.
- **D2 принято:** Critical/High в точном выпускаемом артефакте запрещают выпуск
  и golden image. Остальные уровни остаются в отчёте. Успешный свежий scan
  привязан к SHA артефакта, lock и фактическому дереву пакетов; ошибка запроса или
  разбора не считается отсутствием уязвимостей. Срок свежести — 24 часа;
  изменение любого входа немедленно делает квитанцию устаревшей.
- **Первый переход журнала через OTA остаётся открытым.** При активном старом
  стенде и пропущенном по Condition API logger может исчерпать прежний лимит
  5 секунд/256 узлов/64 KiB. Отказ не скрывается и `ready=false` не превращается
  вручную в успех. Поддержанная процедура — полный refresh и проверка authority,
  квитанции и реального чтения; история и поколение сохраняются. Архитектурный
  worker PID1 из WIP в этот выпуск не переносится.
- **Node-RED требует bootstrap полного refresh.** Старый онлайн-обновлятор не
  понимает новые назначения manifest/unit и не выполняет новый preflight из
  overlay. Без helper установка явно недоступна; сетевого root-shell fallback
  нет. После bootstrap новый runner доставляет все три доверенных файла.
  Пакет `.sa02m` с ними собирается с `--min-updater 1.0.8.2` и проверяется на
  отказ старого валидатора до раскладки. URL runtime в manifest остаётся `null`
  до фактической публикации закреплённого артефакта; локальный staged payload
  обязателен, пока URL отсутствует.

## Все 11 оставшихся замечаний исходного аудита

| Замечание | Статус выбранного выпуска и следующий шаг |
|---|---|
| L1: `reboot -f` прежде штатного выключения | **Отложено.** Сохраняется исходный helper; подготовленный WIP orderly reboot/worker/fallback не включён. Завершить отдельное ревью, native PID1 и проверку сторожа. Обычная SSH-перезагрузка не проверяет кнопку панели. |
| L2: перезапуск веба затрагивает сеть и cgroup fcgiwrap | **Отложено.** Исходные restart helper/CGI сохраняются. Завершить независимый worker, только nginx/fcgiwrap, достоверный ответ о принятии и UI-тесты. |
| L3: публикация cache без доказанного владения lock | **Отложено.** Сохраняется прежний lifecycle. WIP требует доказанной quiescence старых операций; старые result-файлы не несут PID/birth/boot/job и не доказывают отсутствие orphan. Не удалять lock/gen и не считать отсутствие helper доказательством безопасности миграции. |
| L4: неограниченный job запуска MPLC и повторный init.d fallback | **Отложено.** Загрузка проекта не закрывает общий дефект запуска. Довести единый timeout/drop-in, PID1 job/cgroup proof и безопасный rollback по подготовленному плану. |
| APP-01: обходимый throttle root-пароля | **Отложено**, несмотря на принятое D1. Перенести ограничение в привилегированную границу, добавить реальные конкурентные/refusal tests; не считать текущий CGI-счётчик достаточным. |
| SYS-01: root ext4 `commit=600` | **Отложено.** Исходная политика остаётся. WIP commit60/ordered не включён. Нужны отдельные live/offline проверки, обычная перезагрузка и сопоставимые часовые diskstats; точное окно потери данных из commit не выводится. |
| DEP-01: уязвимые зависимости Node-RED | Включён новый закреплённый payload; закрытие только после scan точных окончательных bytes по D2 и фактической установки/проверки ARM. Последний промежуточный npm scan обнаруживал два Moderate: glob/minimatch; он не заменяет итоговую release-квитанцию. |
| DEP-02: изменяемый upstream installer от root | Включён единый verifier и фиксированный panel delegate вместо прежней online/offline install chain. Требуются итоговые tests/review и доставка полного trust bundle. Runtime/flows/credentials и rollback проверяются canonical helper; второй start после него не добавляется. |
| DEP-03: плавающие пакеты общего system Python | **Отложено.** Изолированные runtimes не подключены. Черновой Python manager не имеет завершённого manifest/lock/readiness contract. Не доставлять его и не переключать CGI/units до доказанного first-upgrade barrier и ARM wheels. |
| PROC-02: отсутствие общего advisory scan | Включается ограниченный scan выбранного Node-RED артефакта по D2. Общий охват system Python/OS и остальных компонентов остаётся **открытым**; targeted Node-RED PASS не означает отсутствие всех CVE проекта. |
| FL-COM4: прерывание прошивки посреди образа | **Открыто.** Два текущих same-version прогона на .135 COM4@10, SN0E0A4E21, APP.40→.40 (PLAIN и FAST) прошли571/571 без warn/error,148 настроек и EEPROM health сохранились. Это не воспроизводит весь исторический сбой и не доказывает причину/исправление. |

APP-02 (возвращаемые SD/USB и очищенные события) и APP-03 (расхождение HardPy)
не входят в эти 11: соответствующие изменения уже входят в выбранную базу,
но приёмка по-прежнему требует совместимых установленных исходников и реальных
проверок. Нельзя повторно использовать старую paired-квитанцию после изменения
хеша пакета. Физические 5 холодных и 3 запуска без LAN пользователь исключил;
они не считаются выполненными. Проверка первого серийного клона остаётся отдельной.

Для базового MPLC пути `--submit` → фоновый deploy проверка с подменёнными
командами pytest не доказывает выживание процесса в реальной цепочке
fcgiwrap/sudo/cgroup. Такой native lifetime-тест для выбранной базы **не выполнен**.
Его нужно выделить отдельным следующим стендовым планом; тесты незавершённого
Linux B worker не являются доказательством для сохранённой реализации.

Исторический FL-COM4 содержит пять **выбранных** неудач SA с неизвестным общим
числом попыток; шесть успехов — четыре локальных SA и два PC/TCP, плюс отдельный
дополнительный SA success. Сравнивались10 против3 retries и PLAIN523/75 против
FD4608 в других случаях. APP.22 — версия исправленного приёмника, не доказанная
версия дефекта; TX-gap не измерялся. Процент отказов и вывод «PC против daemon»
из этих данных не следуют. Следующий шаг — согласованный стендовый план с точной
трассой и классификацией legacy readiness, без произвольного изменения retries.

## Сохранённая работа и порядок продолжения

Архив всех84 WIP-файлов: SHA256
`2a59de142f08f920fa0abc6beb0c5ae27d62c88db9de9c461b968abbd1901ee0`.
Он сохранён Orchestrator отдельно от final checkout. Подробная
[передача интеграции](../../../release-audit-20261124/journal-systemd-fix/structural/final-wip-handoff-20261125/HANDOFF.md)
содержит37 точных source-хешей, результаты focused-проверок и незакрытые gates.
Это локальные аудиторские артефакты, не часть устанавливаемого образа.

Продолжение: сначала согласовать безопасный bootstrap старого online updater;
затем завершать journal PID1 и Linux A/B как самостоятельные изменения,
проверяя реальные jobs/locks/cgroups. После этого — Python isolation и D1.
Каждый выпуск проходит полный build и свежий независимый review на одном
замороженном составе; незавершённый WIP не переносится целиком ради экономии
времени. Архив и прежние успешные scoped-тесты не заменяют эти проверки.
