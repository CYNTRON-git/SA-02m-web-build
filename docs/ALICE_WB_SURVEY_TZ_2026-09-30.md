## Как устроено сейчас

Уже есть и это ТЗ не переделывает:

- Навык Яндекса через шлюз, OAuth только на шлюзе, на плате mTLS и карта устройств.
- Типы устройств — официальный каталог Яндекса, включая `devices.types.openable.curtain` и типы света. Наличие типа в списке **не** означает, что для него собрана привязка.
- Форма «Умный дом» умеет: переключатель `on_off`, датчики (температура, влажность, давление, CO₂, ЛОС, напряжение, ток, мощность, движение), уставку вентустановки (`range` / `temperature`), режим вентилятора Carel. Флаг «Показывать в Алисе», «Инвертировать» только на `on_off`.
- Конвертеры `range`, `color_setting` (`rgb` и `temperature_k` целым числом), `on_off`, float, event, mode. `color` ленты публикуется как `#RRGGBB` — форма, которую `mqtt_to_color_setting` уже принимает.
- Автосоздание карточек только для ДТВ и СЭ-02м-3 (`auto_provision.py`).
- Новое устройство в приложении появляется после «Обновить список устройств» у пользователя. Плата список сама не пушит — так устроен протокол Яндекса.
- Retained при новой подписке кладётся в кеш и наружу не репортится, пока не кончится окно grace; затем один кадр `origin=snapshot`.

Чего форма не делает, хотя код рядом уже есть:

- Нет вида привязки «цвет» (`devices.capabilities.color_setting`, instance `rgb`) на топик `color`.
- Нет вида «яркость» на топик `brightness` (0…255, `devices.capabilities.range`).
- Нет пресета «штора»: `on_off` на один топик команды плюс необязательный `range` с instance `open`, min 0, max 100.
- `temperature` ленты — это NTC в °C, только чтение. `white` — ШИМ белого канала в промилле 0…1000. Ни то, ни другое не является цветовой температурой в кельвинах.

## Делаем

### 1. Пресет «Светильник» в форме «Умный дом»

Одна карточка устройства типа `devices.types.light` (оператор может сменить на диммер / ленту / бра — тип уже в списке):

- `power` → `devices.capabilities.on_off`;
- `brightness` → `devices.capabilities.range`, instance `brightness`, range min 0, max 255, precision 1 (как `RANGE_LIMITS` в `opt/sa02m-led/sa02m_led/controls.py`);
- `color` → `devices.capabilities.color_setting`, instance `rgb`.

Валидатор (`config/models.py`) сейчас пропускает `color_setting`, если топик валиден, и не проверяет instance. Добавить ту же строгость, что у `range` и `mode`: instance только `rgb` или `temperature_k`; для `temperature_k` value — целое в диапазоне, который Яндекс принимает для кельвинов (2700…6500, если актуальная страница платформы не задаёт иной). В discovery уходит как есть, без поля `scale` внутри `parameters`.

Команда и чтение идут через уже существующие `yandex_to_color_setting` / `mqtt_to_color_setting` и `yandex_to_range` / `mqtt_to_range`. Новый конвертер не писать.

`white` в этот пресет не входит: это отдельный ШИМ-канал, не компонент RGB.

### 2. Цветовая температура — только кельвины

Если оператор вручную или пресетом задаёт `color_setting` / `temperature_k`, в MQTT и в Яндекс уходит целое число кельвинов. Пересчёт в 0–100 запрещён: это ровно дефект, из‑за которого в чате WB заводят виртуальное устройство.

На ленте МР-02м LED регистра кельвинов нет (`temperature` — NTC, `white` — промилле). Пока его нет, форма **не** предлагает «цветовую температуру» для устройства `type: led` и не подставляет туда `white` или `temperature`. Отдельная задача прошивки ленты (новый контрол, который хранит кельвины и раскладывает их в теплый/холодный ШИМ) в это ТЗ не входит. Когда такой контрол появится, привязка — тот же instance `temperature_k`, без изменений конвертера.

### 3. Пресет «Штора»

Тип по умолчанию `devices.types.openable.curtain`.

- Обязательная строка: `on_off` на **один** MQTT-топик. Голос «открой» / «закрой» ищет именно `on_off`. Один только `range` эту фразу не закрывает (это уже зафиксировано по чату WB от 2026-08-18).
- Необязательная строка: `range`, instance `open`, min 0, max 100, precision 1 — фраза «открой на 50 %».

Два физических выхода реверса (открыть и закрыть — разные DO) в одну способность `on_off` не склеивать. Как и раньше: сценарий на плате публикует один виртуальный топик команды и при необходимости топик положения; в Алису попадает он. Форма это не скрывает: подсказка под пресетом в одну строку.

Клапан (`devices.types.openable.valve`) использует тот же пресет, другой тип.

### 4. Состояние сразу после появления устройства

Сохранить правило «retained не репортится как live, пока не кончилось grace». Добавить второе: когда шлюз присылает discovery (пользователь нажал «Обновить список устройств»), ответ query по каждому устройству берётся из кеша, и следом уходит один `device_state` с `origin=snapshot` по тем устройствам, у которых в кеше уже есть значение. Датчик не остаётся в «Ожидает данных» до следующего периодического кадра 30 с и до повторной публикации моста.

Тихий датчик, который держит retained и не меняется, не переводится в недоступные по одному только возрасту значения, если мост не поднял `meta/error`. Порог `STATUS_STALE_S` (90 с) для этого случая не ужесточать.

Правка карты по-прежнему не перезапускает `sa02m-alice-client`. В карточке «Яндекс Алиса» после сохранения устройства одна строка: список в приложении обновится, когда пользователь нажмёт «Обновить список устройств».

### 5. Инструкция на карточке, без новой службы

На карточке «Яндекс Алиса» (блок уже есть): клиент выключен, пока его не включили; «Отвязать» стирает привязку к аккаунту и сертификат по текущему контракту и **не** удаляет `/etc/sa02m-alice/sa02m-alice-devices.conf`. Проверить unlink-путь тестом: после `controller_unlink` комнаты и устройства на месте, `client_enabled` становится false.

Текст «как снять пакет с диска» в UI не нужен: выключение клиента достаточно, unit и так standby.

- Локальное распознавание речи и свои микрофоны.
- Рестарт клиента после каждой правки карты.
- Подмена промилле или NTC под видом кельвинов.

## Проверка

Юнит-тесты в `opt/sa02m-alice/tests/`:

- пресет светильника: discovery содержит `on_off`, `range/brightness` 0…255 и `color_setting/rgb`; `white` и NTC `temperature` в этот документ не попадают;
- `temperature_k`: команда `4500` публикует MQTT `"4500"`, не `"45"` и не долю 0…100;
- валидатор отвергает `color_setting` с чужим instance;
- пресет шторы: есть `on_off` и `range/open` 0…100; устройство только с `range` валидатор пресета не выдаёт (ручной документ только с `range` по-прежнему грузится — старые файлы не ломаем);
- unlink не очищает `sa02m-alice-devices.conf`;
- на discovery при непустом кеше уходит ровно один snapshot по затронутым устройствам, retained-burst по-прежнему не маркируется как live.

Сборка: цель веб-приложения SA-02m (пакет, который ставит `scripts/06-alice.sh`). Бутлоадер не собирать.

Руками на стенде: лента — «включи», «яркость 40», «сделай синим»; штора на одном топике — «открой» / «закрой» / «на 50 %»; ДТВ сразу после «Обновить список» показывает последнюю температуру, а не «Ожидает данных».
